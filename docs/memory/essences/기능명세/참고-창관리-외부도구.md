# 참고 — 창관리 외부 도구

flux의 창 관리 기능(`docs/features/창관리.md`, 8장 명세)을 설계할 때 참고하는 외부 도구 메모. 본 파일은 원재료(에센스)이고 결정은 features 명세에 옮긴다.

후보군: macOS Rectangle · Windows PowerToys.

---

## Rectangle (macOS) — Todo Mode

위키: https://github.com/rxhanson/Rectangle/wiki/Todo-Mode (Patrick Collison · Nat Friedman 추가, 2021).

### 핵심 동작

- 사용자가 지정한 앱 하나를 **화면 우측에 사이드바 형태로 항상 고정**한다.
- 그 앱은 todo 앱이 디폴트 가정이지만, 임의 앱을 핀할 수 있다("Use [Application] as Todo App").
- 다른 모든 창의 movement shortcut은 **todo 사이드바 폭만큼 줄어든 화면**을 기준으로 동작한다 → 다른 창이 todo를 가리지 않는다.

### 활성화 절차

1. 터미널: `defaults write com.knollsoft.Rectangle todo -int 1` (숨김 기능 해제) → 앱 재시작
2. Todo 앱 활성화 후 Rectangle 메뉴 → "Use [Application] as Todo App"
3. Rectangle 메뉴에서 Todo Mode ON

### 설정 옵션

- 너비: `defaults write com.knollsoft.Rectangle todoSidebarWidth -float 400` (px)
- "Reflow Todo" 메뉴 또는 단축키: 창 배치 어긋나면 보정

### Pro 차이

문서에 명시 안 됨. Rectangle Pro 페이지(rectangleapp.com/pro)에는 "focused work area + more configuration" 정도 표현만.

### 한계·주의

- 1개 앱만 핀 가능 (multi-pin 없음). 좌측·상하 사이드 변경 옵션은 위키에 명시 없음.
- 디스플레이별 toggle은 primary display 한정.
- 가끔 창 배치 어긋남 — Reflow로 보정.

## PowerToys (Windows)

flux 8장의 v1 범위(포스트잇·분할 4프리셋·레이아웃 자동 저장)와 매핑되는 세 도구.

### FancyZones — zone 기반 스냅

문서: https://learn.microsoft.com/en-us/windows/powertoys/fancyzones

- **modifier는 Shift**가 디폴트(준영의 멘탈 모델 "Alt"는 PowerToys 실 동작과 다름 — 설정에서 modifier 변경 가능). 창을 드래그하다 Shift 누르면 zone 가이드가 화면에 overlay로 뜨고, 마우스 떼는 zone에 정확히 안착.
- **Ctrl 동시**: 여러 zone에 걸쳐 멀티 zone 점유.
- **레이아웃 에디터**: 미리 정의된 레이아웃 + 사용자 커스텀. 핸들로 zone 경계·gap 조정.
- **저장 위치**: `%LocalAppData%\Microsoft\PowerToys\FancyZones\custom-layouts.json`.

flux 매핑: 분할뷰 1/2·1/3·1/4 프리셋 + 사용자 정의 zone(준영의 의도 1번 항목)이 정확히 FancyZones 영역.

### Always On Top — 임의 창 핀

문서: https://learn.microsoft.com/en-us/windows/powertoys/always-on-top

- **단축키 Win+Ctrl+T** (변경 가능): 활성 창을 모든 창 위에 핀. 같은 단축키로 토글 해제.
- **시각 피드백**: 핀 시 음향 알림 + 창 외곽 테두리.

flux 매핑: 포스트잇 모드의 "항상 위" 토글이 본질 동일. flux는 OS 후킹 없이 자기 노트 창에만 적용한다는 차이.

### Workspaces — 앱 묶음 레이아웃 저장·복원

문서: https://learn.microsoft.com/en-us/windows/powertoys/workspaces

- **Capture**: 현재 데스크톱 상태(어떤 앱이 어디 어느 크기로 열려 있는지)를 캡처해 한 workspace로 저장. CLI 인자·바탕화면 단축키 함께 저장 가능.
- **Launch**: 저장된 workspace를 한 클릭으로 복원 — 앱들이 원래 위치·크기로 다시 뜬다. 진행 상황 다이얼로그 표시.
- **단축키**: `Win+Ctrl+\``로 에디터 열기.
- **편집·되돌리기**: 기존 workspace 재캡처·수정·revert.

flux 매핑: 8장 "레이아웃 자동 저장/복원"의 본질 동일. PowerToys Workspaces는 "앱 묶음" 단위, flux는 **노트·세션 컨텍스트와 묶인 레이아웃**이 차별점이 될 수 있다("AI 논문 세션을 열면 분할 + 사이드바 폭 + 핀된 노트가 같이 복원").

## flux 창 관리에 줄 수 있는 영향

이 섹션은 결정이 아니라 검토 후보다.

1. **포스트잇이 단지 "투명 작은 창"을 넘어선 의미**: Rectangle Todo의 핵심은 "다른 창의 movement이 todo를 자동 회피"한다는 점이다. flux 포스트잇이 OS 단축키를 후킹하지 않더라도, **같은 컴포지션 의식(자동 회피)**이 자연스러운 UX다. 8장은 "사용자가 크기·위치 지정"까지만 정의하므로 자동 회피는 v1 범위 밖일 가능성이 크다.

2. **분할뷰 프리셋의 외부 매핑**: 8장 분할뷰는 1/2·1/3·1/4 프리셋. PowerToys FancyZones·Rectangle 자체 단축키(Ctrl+Option+화살표)가 같은 카테고리 — 외부 도구가 이미 같은 자리를 차지하고 있다는 점이 중요하다. flux 분할뷰가 OS 창 관리를 대체하는지 보완하는지 결정 필요(현재 8장은 flux 내부 분할만 다룸).

3. **레이아웃 자동 저장**: PowerToys Workspaces, macOS Stage Manager가 같은 영역. flux의 강점은 "노트·아이템 컨텍스트와 묶인 레이아웃"이 될 수 있다 — 예: "AI 논문 세션을 열면 그 세션의 분할 + 사이드바 폭이 같이 복원". 이건 외부 도구가 못 하는 자리.

## 사용자 의도 — 드래그 스냅 + Alt 가이드 (2026-05-02 메모)

준영의 멘탈 모델: Rectangle Todo + PowerToys FancyZones를 합성한 단일 동작.

> 마우스로 창을 우측으로 끌면 Rectangle처럼 그 창이 우측에 Todo나 메모 적기 딱 좋은 크기로 붙는다. 어떤 크기로 붙을지는 미리 설정해 둔다. 드래그하면서 Alt를 누르면 PowerToys처럼 가이드를 띄우고, 그곳으로 드래그하면 Rectangle Todo처럼 작동한다.

### 동작 분해

1. **드래그 → 사이드 스냅**
   - 임의 창을 화면 가장자리로 드래그 → 사용자 정의 폭의 사이드바 zone에 스냅.
   - 스냅된 창은 Rectangle Todo의 사이드바 슬롯처럼 작동: 다른 창이 그 폭만큼 줄어든 영역을 기본 작업 공간으로 인식.
   - 흡수: Rectangle의 "사이드바 핀" 결과물.

2. **Alt 드래그 → zone 가이드 overlay**
   - 드래그 중 Alt 누르고 있으면 미리 정의한 zone들이 화면 위 반투명 가이드로 표시.
   - 마우스를 zone 위에 놓고 떼면 그 zone에 창이 정확히 안착.
   - 흡수: PowerToys FancyZones의 "Alt overlay → zone snap" 인터랙션.

3. **사용자 정의 zone 크기**
   - 좌·우·상·하 각 사이드바 zone의 폭/높이를 사용자가 설정에서 미리 입력.
   - Rectangle은 `defaults write ... todoSidebarWidth`로 한 값만 / FancyZones는 zone 편집기 따로. 합쳐서 zone 편집기 + 즉시 미리보기가 자연스럽다.

### flux 8장과의 관계

현재 8장 창 관리 명세는 "포스트잇(투명·항상 위) + 분할 4프리셋 + 레이아웃 자동 저장"까지. 본 의도는 그 위에 다음을 추가한다:

- **드래그 인터랙션**이 단축키를 대체하거나 보완 (현재 명세는 단축키만 시사)
- **zone 가이드 overlay**가 새 표면이다 (FancyZones 본질)
- **사이드바 핀 슬롯**이 포스트잇과 분할뷰 사이에 새 카테고리가 된다 (포스트잇은 임의 위치·크기, 분할뷰는 4프리셋, 핀 슬롯은 zone 정의)

### 결정 미정 항목

- v1에 넣을지, v2 이후로 미룰지
- 모바일·web에서는 드래그 스냅이 의미 없음 (데스크톱 전용 기능)
- macOS·Windows·Linux 각각 OS API 차이 — Tauri 플러그인으로 흡수 가능한지 검증 필요
- 사이드바에 핀된 게 일반 창인지 flux 노트인지 — Rectangle은 "임의 앱 핀"이지만 flux는 자기 노트만 핀 가능하게 좁힐 수도 있다

## 본질 정제 (2026-05-04 메모)

> **Rectangle Todo + 사용자 지정 창 크기 = 전부.**

5/2 메모(드래그 스냅·Alt 가이드·zone 정의)에서 한 단계 좁힌 본질이다. 둘이 모순이 아니다 — 5/2가 인터랙션 표면(어떻게 핀하는가)을 그렸다면, 5/4는 **무엇이 핀되어야 하는가**에 답한다.

### 명제

- Rectangle Todo는 준영이 원하는 걸 거의 다 구현해뒀다. **딱 하나 빠진 게 사용자 지정 창 크기**다.
- PowerToys FancyZones는 그 빠진 한 조각(zone 크기 사용자 지정)을 갖고 있다. **그 측면만** 차용한다.
- Rectangle Todo의 모든 특성 + 사용자 지정 창 크기 → flux 창관리 v1의 충분조건.

### "Rectangle Todo가 거의 전부"의 함의

이게 8장에 박힐 결정 후보다.

- 다중 zone·여러 사이드 토글·복잡한 레이아웃 에디터는 **불필요**할 가능성이 크다 (Rectangle이 그걸 안 하고도 충분했으니까).
- 핵심은 (a) 화면 가장자리 사이드 슬롯, (b) 다른 창의 자동 회피, (c) 폭 사용자 지정 — 이 셋만 갖추면 끝.
- FancyZones의 광범위한 zone 시스템·overlay·multi-zone 점유는 **본 의도의 범위 밖**. 위 PowerToys 섹션에서 "분할뷰와 본질이 같다"고 적은 매핑은 v1 범위로는 너무 넓다 — 본 의도 기준으로는 zone 편집기의 "사용자 지정 폭" 한 측면만 흡수한다.

### `철학-기본값과-사용자-지정.md`와의 연결

본 의도는 그 철학의 **두 번째 사례**다. 첫 사례가 테마 5개 + 사용자 지정 팔레트라면, 두 번째 사례는 **사이드 슬롯 디폴트 폭(예: 화면 30%) + 사용자 지정 폭**. 같은 형식이 그대로 적용된다.

### 사용자 발화 원본

> 창 관리 기능은 에센스 어딘가에도 있겠지만, 이번에 ractangle의 todo 기능이 내가 원하는걸 거의 구현했더라고, 사용자 지정 창 크기 빼고.
> 그걸 window powertoy가 사용자 지정할 수 있게 해놨다-해서 레퍼런스로 넣고 싶었던 거야.
> ractangle의 todo 기능에 사용자 지정 창 크기가 전부야. 그게 필요해.
