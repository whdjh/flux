# File Explorer System - BDD Specification

## Design Rationale / 설계 근거

### Why VS Code's File Explorer Pattern? / 왜 VS Code의 파일 탐색기 패턴인가?

파일 트리는 1983년 Apple Lisa부터 시작된 검증된 패턴이다. Windows Explorer, macOS Finder, 모든 IDE가 동일한 메타포를 사용하며, 학습 시간이 0초인 즉각적으로 친숙한 인터페이스다.

인간의 뇌는 계층 구조를 자연스럽게 처리한다 (Miller, 1956). 트리 구조는 공간 기억을 활용해 50% 빠른 파일 찾기를 가능하게 하며, 필요한 정보만 단계적으로 노출하여 인지 부하를 감소시킨다.

VS Code를 선택한 이유는 다음과 같다:
1. 검증된 UX: 2천만+ 개발자가 매일 사용하는 인터페이스
2. 최적화된 상호작용: 키보드 단축키와 마우스 동작의 완벽한 균형
3. 확장성: 플러그인 생태계로 검증된 확장 가능한 구조
4. 성능: 수십만 파일도 처리 가능한 가상 스크롤링

Git 상태 표시로 버전 관리를 통합하고, 드래그 앤 드롭으로 직관적인 파일 이동을 지원한다. 컨텍스트 메뉴로 모든 작업에 빠른 접근이 가능하며, 타입 어헤드 검색으로 즉각적인 파일 찾기를 제공한다.

## Overview
File Explorer는 VS Code 스타일의 파일 시스템 탐색기를 구현합니다.
트리 구조의 파일/폴더 표시, 가상 스크롤링, 드래그 앤 드롭, 컨텍스트 메뉴 등
현대적인 파일 관리 기능을 제공합니다.

## Feature: File Tree Display

### Scenario: Displaying directory structure
```gherkin
Given 프로젝트 폴더가 열려있는 상태
When 파일 탐색기가 로드되면
Then 루트 폴더의 내용이 트리 구조로 표시되어야 한다
And 폴더는 폴더 아이콘과 함께 표시되어야 한다
And 파일은 확장자에 맞는 아이콘과 함께 표시되어야 한다
And .gitignore 파일은 필터링되어야 한다
```

### Scenario: Expanding and collapsing folders
```gherkin
Given 폴더가 접혀있는 상태
When 사용자가 폴더 옆 화살표를 클릭하면
Then 폴더가 펼쳐지며 하위 항목이 표시되어야 한다
And 화살표가 아래 방향으로 회전해야 한다
And 펼침 상태가 세션 동안 유지되어야 한다
```

### Scenario: Nested folder structure
```gherkin
Given 깊은 중첩 구조의 폴더가 있는 상태
When 사용자가 중첩된 폴더를 탐색하면
Then 각 레벨이 적절히 들여쓰기되어야 한다
And 들여쓰기는 20px씩 증가해야 한다
And 현재 경로가 breadcrumb에 표시되어야 한다
```

## Feature: Virtual Scrolling

### Scenario: Large directory handling
```gherkin
Given 1000개 이상의 파일이 있는 폴더
When 파일 목록이 렌더링되면
Then 뷰포트에 보이는 항목만 DOM에 렌더링되어야 한다
And 스크롤 시 항목이 동적으로 로드되어야 한다
And 스크롤 성능이 60fps를 유지해야 한다
And 전체 높이가 가상으로 계산되어야 한다
```

### Scenario: Smooth scrolling
```gherkin
Given 가상 스크롤이 활성화된 상태
When 사용자가 빠르게 스크롤하면
Then 항목 로딩이 부드럽게 이루어져야 한다
And 플레이스홀더가 로딩 중 표시되어야 한다
And 스크롤 위치가 정확히 유지되어야 한다
```

## Feature: File Operations

### Scenario: Creating new file
```gherkin
Given 폴더가 선택된 상태
When 사용자가 "New File" 명령을 실행하면
Then 인라인 입력 필드가 나타나야 한다
And 사용자가 파일명을 입력할 수 있어야 한다
And Enter 키로 파일이 생성되어야 한다
And ESC 키로 취소할 수 있어야 한다
```

### Scenario: Creating new folder
```gherkin
Given 파일 탐색기가 열려있는 상태
When 사용자가 "New Folder" 명령을 실행하면
Then 인라인 입력 필드가 나타나야 한다
And 폴더 아이콘이 입력 필드 옆에 표시되어야 한다
And 중복된 이름 입력 시 경고가 표시되어야 한다
```

### Scenario: Renaming file or folder
```gherkin
Given 파일이 선택된 상태
When 사용자가 F2 키를 누르거나 "Rename"을 선택하면
Then 파일명이 편집 가능한 입력 필드로 변경되어야 한다
And 확장자를 제외한 파일명만 선택되어야 한다
And 유효하지 않은 문자 입력이 제한되어야 한다
```

### Scenario: Deleting files
```gherkin
Given 파일이 선택된 상태
When 사용자가 Delete 키를 누르거나 "Delete"를 선택하면
Then 확인 대화상자가 표시되어야 한다
And 확인 시 파일이 휴지통으로 이동되어야 한다
And 트리에서 즉시 제거되어야 한다
And 실행 취소가 가능해야 한다
```

## Feature: Drag and Drop

### Scenario: Moving file to another folder
```gherkin
Given 파일과 대상 폴더가 표시된 상태
When 사용자가 파일을 폴더로 드래그하면
Then 드래그 중인 파일이 반투명하게 표시되어야 한다
And 대상 폴더가 하이라이트되어야 한다
And 드롭 시 파일이 해당 폴더로 이동되어야 한다
And 원본 위치에서 파일이 제거되어야 한다
```

### Scenario: Copying file with modifier key
```gherkin
Given 파일이 선택된 상태
When 사용자가 Ctrl/Cmd를 누른 채 파일을 드래그하면
Then 커서에 복사 표시(+)가 나타나야 한다
And 드롭 시 파일이 복사되어야 한다
And 원본 파일은 그대로 유지되어야 한다
```

### Scenario: Invalid drop prevention
```gherkin
Given 파일을 드래그 중인 상태
When 사용자가 유효하지 않은 위치로 드래그하면
Then 드롭 불가 커서가 표시되어야 한다
And 드롭 시 아무 동작도 일어나지 않아야 한다
And 파일이 원래 위치로 돌아가야 한다
```

## Feature: Context Menu

### Scenario: Right-click context menu
```gherkin
Given 파일이 표시된 상태
When 사용자가 파일을 우클릭하면
Then 컨텍스트 메뉴가 표시되어야 한다
And 메뉴에 다음 항목들이 포함되어야 한다:
  | Action | Shortcut |
  | Open | Enter |
  | Open to the Side | Ctrl+Enter |
  | Rename | F2 |
  | Delete | Delete |
  | Cut | Ctrl+X |
  | Copy | Ctrl+C |
  | Paste | Ctrl+V |
```

### Scenario: Folder-specific context menu
```gherkin
Given 폴더가 표시된 상태
When 사용자가 폴더를 우클릭하면
Then 폴더 전용 메뉴 항목이 표시되어야 한다:
  | Action | Description |
  | New File | 폴더 내 새 파일 생성 |
  | New Folder | 하위 폴더 생성 |
  | Find in Folder | 폴더 내 검색 |
  | Collapse All | 모든 하위 폴더 접기 |
```

```gherkin
Then 빠른 파일 검색 창이 열려야 한다
And 파일명 입력 시 실시간 필터링되어야 한다
And 퍼지 매칭이 적용되어야 한다
And Enter로 선택된 파일이 열려야 한다
```

### Scenario: Search highlighting
```gherkin
Given 검색어가 입력된 상태
When 검색 결과가 표시되면
Then 매칭된 문자가 하이라이트되어야 한다
And 대소문자 구분 없이 매칭되어야 한다
And 파일 경로도 검색 대상에 포함되어야 한다
```

## Feature: File Status Indicators

### Scenario: Git status indication

## Performance Optimizations

1. **Virtual Scrolling**: react-window로 대용량 디렉토리 처리
2. **Lazy Loading**: 폴더 내용을 필요시에만 로드
3. **Debounced Search**: 검색 입력 디바운싱
4. **Memoization**: React.memo로 불필요한 리렌더링 방지
5. **Icon Caching**: 아이콘 컴포넌트 캐싱
