# 핵심 — AI 자동 수집

flux의 정체성을 결정하는 핵심 기능. "AI 노트테이킹 앱"의 "AI"가 가장 강하게 작동하는 자리다. 결정은 features/수집.md·features/ai.md에 옮긴다. 본 파일은 그 결정을 위한 원재료이자 무게다.

---

## 명제 (정제)

> **컴퓨터 안에 흩어진 자료를 AI가 카테고리별로 발견해 flux로 모아준다.**

flux가 "또 하나의 노트 앱"이 아니라 "AI 노트테이킹 앱"인 이유는 이 명제 하나에 걸려 있다. 사용자가 의식적으로 옮기지 않아도 AI가 자료를 끌어와 카테고리에 정리해 둔다.

### 명제의 세 부분

1. **컴퓨터 안에 흩어진 자료** — 로컬 파일 시스템·앱 캐시·다운로드·스크린샷·클립보드 히스토리·브라우저 히스토리·음성 메모 등. 사용자가 한 번이라도 컴퓨터에 만든·받은·찍은 것 모두.
2. **AI가 카테고리별로 발견** — flux가 정의한 ItemType 7종(텍스트·이미지·링크·동영상·스크린샷·클립보드·음성 메모)에 맞춰 자동 분류.
3. **flux로 모아준다** — 발견 결과를 inbox 또는 활성 맥락 폴더로 자동 배치. AI 메타데이터(요약·키워드 3개)도 함께 부착.

이 셋이 한 흐름으로 연결될 때 사용자 경험은 "찾아 헤맸던 자료가 어느새 flux 안에 모여 있다"가 된다.

---

## 기존 에센스와의 연결

이 명제는 기존 정의 위에 놓인다. 새로 추가하는 게 아니라 **이미 존재하던 표면을 핵심으로 끌어올리는 것**이다.

### 1. 깊이 모델의 "감시" 단계 (`앱-재정의.md` 5장)

> 깊이 모델: 감시(앱이 알아서 수집) → 캡처(1~2초 수집) → 포스트잇(옆에 띄워두고 작업) → 몰입(풀 앱)

본 명제 = "감시" 단계의 구체적 동작 정의. 5장은 깊이 단계를 정의했지만 "감시"가 실제로 무엇을 하는지 명시하지 않았다 → 본 메모가 그 빈 자리를 채운다.

### 2. ItemType 7종 (`packages/shared/src/item.ts` + `앱-재정의.md` 7장)

```ts
export const ITEM_TYPES = [
  "text", "image", "link", "video",
  "screenshot", "clipboard", // (음성 메모는 아직 미구현 — 추가 예정)
] as const;
```

AI 자동 수집은 이 7종 카테고리에 그대로 매핑된다. 새 카테고리 도입 없이 작동.

### 3. 의도 보존 3층 (`앱-재정의.md` 5장)

> 자동(URL·타임스탬프) / 추론(AI 요약·키워드) / 선택(한 줄 메모)

자동·추론 두 층이 본 명제에서 동시에 발생한다. 사용자 마찰 0.

### 4. 8장 수집 명세 (`docs/features/수집.md`)

현재 수집 명세는 "사용자가 능동적으로 트리거"하는 경로만 정의(브라우저 확장 Alt+우클릭·Share Sheet·드래그). **AI 자동 수집은 사용자 트리거 없이 백그라운드로 돌아간다** — 별도 갈래로 features에 추가될 가치가 있다.

## 자율 에이전트와의 구분 (중요)

8장 ai 섹션은 다음을 명시 부정한다:

> 하지 않는 것. 자율 에이전트(사용자 대신 수집하거나 정리를 실행하는 것).

표면 단어가 비슷해 충돌처럼 보이지만 다른 영역이다.

| 구분 | 8장 부정한 "자율 에이전트" | 본 명제 "AI 자동 수집" |
|---|---|---|
| 작동 영역 | 외부 (웹 크롤링·이메일·외부 API) | 로컬 (컴퓨터 안 이미 존재하는 자료) |
| 행동 종류 | 결정 + 외부 행동 실행 | 발견 + 인덱싱 + 분류 |
| 사용자 대신? | 결정·실행 모두 AI가 | 발견·분류만, 실행은 없음 |
| 비유 | 비서가 외출해 일 처리 | 비서가 책상 위 종이를 정리 |

본 명제는 **로컬 인덱서·디스커버러에 가깝다**. AI가 사용자 대신 어디로 나가서 새 자료를 만들거나 가져오는 게 아니라, 사용자가 이미 컴퓨터에 만든 것들을 찾아 정리한다. "보여주되 묻지 않고, 실행하지 않는다"는 8장 AI 원칙이 그대로 작동.

이 구분을 8장에 박을 때 단어 선택 주의 — "자동 수집"이라는 표현이 양쪽에 모두 쓰일 수 있다. 정확한 표현은 **로컬 자료 자동 발견(local auto-discovery)** 또는 **AI 인덱싱**.

## v1 범위 후보 (결정 미정)

본 명제 전체를 한 번에 v1에 넣을지, 갈래를 나눌지는 desktop 단계에서 결정. 후보 갈래:

1. **클립보드 자동 감지** — 가장 가벼운 자리. macOS·Windows 모두 OS API 안정. 8장 수집에 이미 "클립보드"가 ItemType에 있어 명세 보강만 하면 된다.
2. **다운로드 폴더 감시** — 사용자 명시 폴더 경로를 watch해 새 파일을 발견. 권한·스토리지 부담 적음.
3. **스크린샷 폴더 감시** — macOS의 `~/Desktop` 또는 사용자 지정 위치. 시각 자료 핵심.
4. **브라우저 히스토리 인덱싱** — 권한 부담 큼. 후속.
5. **로컬 파일 전체 인덱싱** — Spotlight·Windows Search와 본질 동일. 가장 무거움. 후속의 후속.

기본값과 사용자 지정(→`essences/UI-UX/철학-기본값과-사용자-지정.md`)이 여기에도 적용된다 — 어떤 폴더를 감시할지 디폴트 + 사용자 추가.
