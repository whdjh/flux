# 보안

← [문서 네비게이션](../00-시작/00-시작하기.md)

보안은 5개 레이어로 구성된다. Defense in Depth 전략으로 각 레이어가 독립적으로 동작한다.

## 5-Layer 보안 구조

사용자 입력은 5개 레이어를 거쳐서 처리된다. 한 레이어가 뚫려도 다른 레이어가 막는다.

```
사용자 입력
    ↓
[Layer 1] CSP (Content Security Policy)
    ↓
[Layer 2] Security Headers
    ↓
[Layer 3] Zod 입력 검증
    ↓
[Layer 4] Rate Limiting
    ↓
[Layer 5] Path Validation
    ↓
안전한 처리
```

## Layer 1: CSP (Content Security Policy)

CSP는 브라우저 레벨에서 동작한다. 허용된 소스만 로드할 수 있게 제한한다.

### 설정 위치

src/main/index.ts에서 HTTP 헤더로 설정한다. 모든 요청에 CSP 정책이 적용된다.

```ts
session.defaultSession.webRequest.onHeadersReceived((details, callback) => {
  callback({
    responseHeaders: {
      ...details.responseHeaders,
      'Content-Security-Policy': [
        "default-src 'self'",
        "script-src 'self'",
        "style-src 'self' 'unsafe-inline'",
        "img-src 'self' data: https:",
      ].join('; ')
    }
  });
});
```

### 차단하는 것

외부 스크립트 로드를 막는다. eval() 같은 인라인 실행도 차단한다. 신뢰되지 않은 소스는 전부 거부된다.

## Layer 2: Security Headers

HTTP 헤더로 추가 보호막을 친다. 브라우저의 보안 기능을 활성화한다.

### HTTP 보안 헤더

5개의 보안 헤더를 설정한다. X-Frame-Options로 iframe 삽입을 막고, X-Content-Type-Options로 MIME 타입 변조를 차단한다.

```ts
'X-Content-Type-Options': 'nosniff',
'X-Frame-Options': 'DENY',
'X-XSS-Protection': '1; mode=block',
'Referrer-Policy': 'no-referrer',
'Permissions-Policy': 'geolocation=(), microphone=(), camera=()'
```

### 효과

Clickjacking 공격을 막는다. MIME 타입 스니핑도 차단해서 파일 실행 공격을 방지한다. 브라우저의 XSS 필터를 활성화한다.

## Layer 3: Zod 입력 검증

모든 IPC 입력은 Zod로 검증한다. 런타임에 타입을 체크해서 잘못된 데이터를 거른다.

### 런타임 타입 체크

Zod 스키마를 정의한다. parse() 호출 시 타입이 맞지 않으면 에러를 던진다.

```ts
import { z } from 'zod';

const FilePathSchema = z.object({
  path: z.string().min(1).max(1024),
  encoding: z.enum(['utf-8', 'base64']).optional()
});

ipcMain.handle('read-file', async (event, input: unknown) => {
  const validated = FilePathSchema.parse(input);
  // validated.path는 타입 안전
});
```

### 검증 항목

타입을 검증한다. 문자열 길이를 제한한다. 정규식으로 형식을 확인한다. 허용된 값 범위 안에 있는지 체크한다.

## Layer 4: Rate Limiting

IPC 요청 빈도를 제한한다. 100ms 안에 같은 채널을 두 번 호출하면 거부한다.

### IPC 요청 제한

Map으로 마지막 호출 시간을 기록한다. 100ms가 지나지 않았으면 false를 반환해서 요청을 막는다.

```ts
const rateLimiter = new Map<string, number>();

function checkRateLimit(channel: string): boolean {
  const now = Date.now();
  const lastCall = rateLimiter.get(channel) || 0;

  if (now - lastCall < 100) { // 100ms throttle
    return false; // 거부
  }

  rateLimiter.set(channel, now);
  return true; // 허용
}
```

### 보호 대상

DoS 공격을 막는다. 과도한 API 호출로 인한 리소스 고갈을 방지한다.

## Layer 5: Path Validation

파일 경로는 4단계로 검증한다. Path Traversal 공격을 막는 마지막 방어선이다.

### 파일 경로 검증

경로를 정규화한다. 절대 경로로 변환해서 basePath 안에 있는지 확인한다. 금지된 문자가 있으면 에러를 던진다.

```ts
import path from 'path';

function validatePath(inputPath: string, basePath: string): string {
  // 1. 정규화
  const normalized = path.normalize(inputPath);

  // 2. 절대 경로 변환
  const resolved = path.resolve(basePath, normalized);

  // 3. Path Traversal 체크
  if (!resolved.startsWith(basePath)) {
    throw new Error('Invalid path: traversal detected');
  }

  // 4. 금지된 문자 체크
  if (/[<>:"|?*]/.test(inputPath)) {
    throw new Error('Invalid path: forbidden characters');
  }

  return resolved;
}
```

### 차단하는 것

../../etc/passwd 같은 Path Traversal을 막는다. 절대 경로로 직접 접근하는 것도 차단한다. 허용되지 않은 디렉토리는 접근 불가다.

## 보안 테스트

보안 테스트는 여러 카테고리로 나뉜다. 모두 100% 통과한다.

### 보안 테스트 구조

npm run test:security로 실행한다. 6개 카테고리로 나뉜다.

```bash
npm run test:security
```

### 테스트 카테고리

다음 카테고리를 테스트한다. CSP 우회 시도, XSS 공격 패턴, Path Traversal, SQL Injection, Rate Limit 초과, 입력 검증 우회를 확인한다.

1. CSP 우회 시도
2. XSS 공격 패턴
3. Path Traversal
4. SQL Injection
5. Rate Limit 초과
6. 입력 검증 우회

## 보안 체크리스트

배포 전과 정기 점검 항목이 있다.

### 배포 전

CSP 정책을 검증한다. 모든 IPC 핸들러에 Zod 검증을 적용한다. Path Validation을 설정한다. Rate Limiting을 확인한다. 보안 테스트를 통과해야 한다.

- [ ] CSP 정책 검증
- [ ] 모든 IPC 핸들러에 Zod 검증
- [ ] Path Validation 적용
- [ ] Rate Limiting 설정
- [ ] 보안 테스트 통과

### 정기 점검

의존성 취약점을 스캔한다(npm audit). Electron 버전을 업데이트한다. CSP 정책을 강화한다. 로그를 분석해서 비정상 패턴을 찾는다.

- [ ] 의존성 취약점 스캔 (npm audit)
- [ ] Electron 버전 업데이트
- [ ] CSP 정책 강화
