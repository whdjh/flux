## 실행 명령어

npm test로 모든 테스트를 실행한다. Watch 모드는 코드 변경 시 자동으로 재실행한다. 특정 카테고리만 골라서 테스트할 수 있다.

```bash
# 모든 테스트
npm test

# Watch 모드
npm run test:watch

# 특정 카테고리
npm test -- security
npm test -- integration

# Coverage
npm run test:coverage

# UI 모드 (브라우저)
npm run test:ui
```

## BDD 테스트 전략

BDD는 Given-When-Then 패턴을 사용한다. 시나리오를 자연어로 작성하고 코드로 구현한다.

### Given-When-Then 패턴

Given은 초기 상태를 설정한다. When은 사용자 행동을 실행한다. Then은 결과를 검증한다.

```typescript
// tests/bdd/file-explorer.test.ts
describe('Feature: 파일 탐색기', () => {
  it('Given 파일 탐색기가 열려있고, When 폴더를 클릭하면, Then 하위 파일 목록이 표시된다', async () => {
    // Given
    const { getByText } = render(<FileExplorer />);

    // When
    await userEvent.click(getByText('src'));

    // Then
    expect(getByText('components')).toBeInTheDocument();
  });
});
```

## 보안 테스트 (182개)

182개의 보안 테스트가 5개 레이어를 검증한다. 모두 100% 통과해야 배포할 수 있다.

### 5-Layer 검증 전략

Layer 1(CSP), Layer 3(Zod), Layer 5(Path Validation)를 집중적으로 테스트한다.

```typescript
// tests/security/5-layer-validation.test.ts
describe('5-Layer Security System', () => {
  describe('Layer 1: CSP', () => {
    it('외부 스크립트 로드 차단', () => {
      // CSP 정책 검증
    });
  });

  describe('Layer 3: Zod 검증', () => {
    it('잘못된 타입 입력 거부', () => {
      expect(() => FilePathSchema.parse(123)).toThrow();
    });
  });

  describe('Layer 5: Path Validation', () => {
    it('Path Traversal 시도 차단', () => {
      expect(() => validatePath('../../etc/passwd')).toThrow();
    });
  });
});
```

### 보안 테스트 카테고리

6개 카테고리로 182개 테스트를 실행한다. CSP 우회 23개, XSS 공격 31개, Path Traversal 42개, SQL Injection 18개, Rate Limit 28개, 입력 검증 40개다.

**1. CSP 우회 시도 (23개)**: inline script 실행, eval() 호출, 외부 CDN 로드를 시도한다.

**2. XSS 공격 패턴 (31개)**: `<script>` 태그 삽입, `<img onerror>` 공격, HTML 속성 주입을 테스트한다.

**3. Path Traversal (42개)**: `../../etc/passwd`나 `..\\..\\windows\\system32` 같은 경로 조작을 시도한다. URL 인코딩 우회도 확인한다.

**4. SQL Injection (18개)**: `' OR '1'='1`이나 `; DROP TABLE users--` 같은 인젝션을 테스트한다. Union-based 공격도 포함한다.

**5. Rate Limit 초과 (28개)**: 100ms 내 반복 요청, 동시 다발 요청, DoS 시뮬레이션을 실행한다.

**6. 입력 검증 우회 (40개)**: 타입 혼동 공격, 길이 제한 초과, 정규식 우회를 시도한다.

## Mock 전략

테스트 환경에서는 IPC, FileSystem, Supabase를 Mock으로 대체한다. 실제 의존성 없이 빠르고 격리된 테스트가 가능하다.

### IPC Mock

window.electron을 vi.fn()으로 Mock한다. readFile, writeFile, listDirectory 호출을 가짜로 처리한다.

```typescript
// tests/setup/ipc-mock.ts
global.window.electron = {
  readFile: vi.fn((path: string) => Promise.resolve('mock content')),
  writeFile: vi.fn(() => Promise.resolve()),
  listDirectory: vi.fn(() => Promise.resolve(['file1.txt', 'file2.txt']))
};
```

### FileSystem Mock

```typescript
// tests/setup/fs-mock.ts
vi.mock('fs/promises', () => ({
  readFile: vi.fn(),
  writeFile: vi.fn(),
  readdir: vi.fn()
}));
```

### Supabase Mock

```typescript
// tests/setup/supabase-mock.ts
vi.mock('@/backend/infrastructure/db/client', () => ({
  db: {
    select: vi.fn().mockReturnThis(),
    from: vi.fn().mockReturnThis(),
    where: vi.fn().mockResolvedValue([])
  }
}));
```
