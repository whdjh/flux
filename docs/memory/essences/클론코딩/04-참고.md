# 참고

## 경쟁 분석

21개 서비스를 분석했다. Notion, Obsidian, Eagle, Raindrop, mymind, Karakeep, Recall AI, Readwise, Evernote, Apple Notes, Microsoft OneNote, Microsoft Sticky note, Google Keep, Boardmix, Keep it, Bear, Goodnotest, Ulysses, Memo it, EdrawMind, Simplenote이다.

기존 도구들의 공통적인 약점은 정보 수집 단계에서의 마찰이다. 사용자들은 웹페이지를 일일이 복사-붙여넣기 하거나 스크린샷을 찍어야 한다. 이 과정에서 많은 정보가 수집되지 않고 사라진다. 본 서비스는 이 '수집의 마찰'을 제거하는 것에서 출발한다.

차별화 포인트는 세 가지다.

첫째, 원클릭 수집으로 작업 흐름을 끊지 않는다. Alt+우클릭 하나로 텍스트, 이미지, 링크, 동영상을 수집한다. 크롬 확장 프로그램이 로컬 서버를 통해 앱과 통신한다. 웹서핑을 방해하지 않는다.

둘째, AI 자동 정리로 수집 후 정리 부담을 줄인다. 수집과 동시에 AI가 1~3줄 요약과 키워드 3개를 생성한다. 병렬 처리로 UX가 느려지지 않는다. Elasticsearch-rs로 유의어 검색까지 지원한다.

셋째, 전체 워크플로우 통합으로 수집부터 아이디어 발상까지 한 곳에서 해결한다. 분할 뷰로 레퍼런스와 메모를 나란히 둔다. 드래그앤드롭으로 핵심 정보를 추출한다. AI 어시스턴트로 아이디어를 확장한다.

## 디자인 철학

조니 아이브의 철학을 따른다. 사랑과 배려로 제품을 만든다. 누군가 앱을 열 때 "누군가 나를 신경 썼구나"라고 느끼게 하는 것이 목표다.

단순함은 혼란에 질서를 가져오는 것이다. 본질과 목적, 삶에서의 역할을 간결하게 표현한다. 미니멀리즘은 종종 메마르고 영혼 없는 제품으로 끝난다. 기쁨과 유머가 중요하다. 기쁨이 사소한 것으로 혼동되지만 내 마음 상태가 결국 작업에 구현된다.

기능하지 않으면 추하다. 효용과 미학 사이의 거짓 대립은 좌절스럽다. 작동하지 않는 것을 디자인하면 보기에 상관없이 추하다. 사람들은 배려를 감지한다. 서비스에서는 사람을 대면하기 때문에 쉽지만 객체나 소프트웨어를 통해서도 배려를 감지한다.

## 개발 원칙

사용자 경험이 최우선이다. 직관적인 UI로 학습 곡선을 최소화한다. 사용자의 작업 흐름(웹서핑)을 방해하지 않는 설계가 핵심이다. 사용자의 뇌와 손의 에너지를 아껴주며 시간을 절약해주는 설계를 추구한다.

최소한의 에너지로 최대한의 정리 효과를 얻는 것이 목표다. AI가 예측 가능하게 분류하고 프라이버시를 보장한다. 협업 기능으로 팀 작업까지 확장한다.

Cloudflare의 OAuth 2.1 라이브러리 사례를 참고한다. AI가 코드의 95% 이상을 생성했지만 인간의 감독은 과정 내내 필수적이었다. 프롬프트를 코드와 함께 커밋하는 습관이 중요하다. 때로는 엔지니어가 잘못된 가정을 선언하고 모델이 맹목적으로 따를 때 코드보다 프롬프트를 리뷰하는 게 더 가치 있다.

## 기술 인사이트

### Shadcn/UI

Shadcn/UI는 컴포넌트 라이브러리가 아니다. 여러분만의 컴포넌트 라이브러리를 만들도록 돕는 도구다. MUI처럼 node_modules에 추상화된 코드가 아니라, components 폴더에 직접 들어있는 소스 코드를 수정한다. Radix UI 프리미티브를 감싸는 래퍼일 뿐이고 CSS를 추가해서 좋은 기본기를 만들어준다.

테마를 전역으로 업데이트하려면 tweak-cn을 쓴다. 색상뿐 아니라 radius, 타이포그래피, 자간, 그림자를 모두 커스터마이징할 수 있다. 컴포넌트는 components 폴더 안에 있는 파일을 직접 수정한다. 별도의 컴포넌트를 만들지 말고 바로 그 컴포넌트 파일 안에서 업데이트한다.

### AI 최적화 UI

LLM과의 대화는 1980년대 터미널 사용과 비슷하다. GUI는 아직 개발되지 않았지만 일부 특성은 예측할 수 있다.

인터페이스는 시각적 방식으로 구현될 것이다. 인간의 뇌가 시각 정보(사진, 차트, 애니메이션)를 처리하는 데 매우 특화되어 있기 때문이다. 읽기보다 시각적 정보는 뇌에 더 빠르고 효율적으로 전달된다.

GUI는 생성적이고 입력 조건에 따라 변할 것이다. 사용자의 프롬프트에 맞춰 실시간으로 GUI가 생성되며 필요한 모든 구성 요소가 즉각 제공된다. 목적에 맞춰 구성이 변화하며 기존의 고정된 화면 레이아웃을 벗어난다.

현재 이 변화는 이미 시작되고 있다. 코드 블록, 하이라이트, LaTeX 수식, 마크다운(굵게, 기울임, 리스트, 표), 이모지는 이미 초기 형태를 갖췄다. Mermaid 차트나 Artifacts 탭처럼 더 복잡한 기능들이 포함될 가능성도 있다.

### Apple Liquid Glass

2025년 6월 8일 Apple이 발표한 투명하고 유려한 UI 컨셉이다. blur 22px, 배경 알파 0.06, 보더 알파 0.16으로 구현한다. 포스트잇 창과 오버레이 모드에서 적극 활용한다.

## 런칭 전략

베타 테스트 기간 동안 사용자들이 가입 후 하루 만에 떠나지 않고 며칠이라도 꾸준히 사용하는 모습이 보일 때 런칭한다. 사용자가 앱에 머무를 거라는 확신이 들 때가 바로 런칭할 때다.

분석 시스템(PostHog), 피드백 보드(Canny), 이메일 시퀀스(Loops)를 런칭 전에 구축한다. 앱 스토어 리스팅을 최적화하고 랜딩 페이지를 제작한다. Product Hunt와 Reddit 같은 커뮤니티에 적극적으로 알린다.
