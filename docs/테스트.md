# 테스트

## 전략

테스트 피라미드로 얇은 E2E와 두꺼운 단위 테스트를 유지한다. 수집 < 100ms, 에디터 입력 60fps 같은 성능 메트릭은 별도 벤치마크로 본다.

```
        ┌───────────┐
        │    E2E    │   ~10%   — 핵심 유저 플로우만
        └───────────┘
      ┌───────────────┐
      │   Integration │   ~30%  — API, 동기화, CRDT 병합
      └───────────────┘
    ┌───────────────────┐
    │       Unit        │   ~60%  — 순수 로직, 유틸, 리듀서
    └───────────────────┘
```

목표 커버리지 (제안, CI 도입 시 팀 확정): **packages/\* 80%**, **apps/\* 60%** (UI는 상호작용이 많아 낮게). 일반 기준 80%를 따르되 UI 특성을 반영한 제안치다.

| 레이어 | 무엇을 검증 | 툴 |
|------|-----|-----|
| Unit | packages/shared의 순수 함수, editor-core의 로컬 연산 | Vitest (TS), Bun test |
| Integration | packages/api-client ↔ flux-be 목 서버, store ↔ SQLite 실 인스턴스 | Vitest + msw, wa-sqlite 인메모리 |
| E2E (Web) | 로그인 → 수집 → 메모 작성 → 검색 | Playwright |
| E2E (Desktop) | 웹 E2E를 Tauri 바이너리에서 재사용 + 포스트잇·트레이 케이스 | Playwright + Tauri driver |
| E2E (Mobile) | Share Sheet, 카메라, 오프라인 | Detox 또는 Maestro |
| CRDT | loro 동시 편집, 오프라인 병합 정합성 | 속성 기반 테스트 (fast-check) |

## TDD 루프

새 기능은 테스트 먼저.

1. 실패하는 테스트 작성 (Red)
2. 최소 구현으로 통과 (Green)
3. 리팩터링 (Refactor)

`.claude/agents/tdd-guide` 에이전트가 순서를 강제한다. 커버리지 80% 미만이면 PR 머지 차단.

## 성능 벤치마크

기능 통과와 별도로 검증해야 할 성능 기준이 있다. 요구사항의 비기능 요구사항과 연결.

| 메트릭 | 기준 | 측정 |
|------|------|------|
| 수집 응답 (로컬 저장 완료까지) | p95 < 100ms | `packages/store` 벤치 |
| AI 요약 (수집 → 요약 도착) | < 2s | `packages/ai` 벤치, 프로덕션 메트릭 |
| 에디터 입력 → 화면 반영 | 60fps (16ms) | React DevTools Profiler, Playwright trace |
| WebSocket 재연결 | < 3s (지수 백오프 포함) | 인위적 네트워크 차단 시나리오 |
| 앱 콜드 스타트 (데스크톱) | < 1.5s | Tauri devtools |

## 실행 방법

```bash
# 전체 (현재 작동)
pnpm -r test                  # 모든 패키지·앱의 단위·통합 테스트

# 패키지/앱 단위 (현재 작동)
pnpm --filter @flux/shared test
pnpm --filter @flux/api-client test
pnpm --filter @flux/cli test

# 계획 (CI 도입·E2E 추가 시점)
pnpm test:e2e                 # 플랫폼별 E2E 묶음
pnpm test:cov                 # 커버리지 리포트
pnpm test --watch             # TDD 루프
pnpm test:e2e --ui            # Playwright UI 모드
```

(계획) CI(`ci.yml`)는 PR마다 `pnpm test:cov`를 실행한다. 커버리지가 기준 미달이면 머지 차단. 현재 CI 미도입.
