# 비전: 왜 만드는가

타겟 사용자는 유저리서치.md, 경쟁 분석은 경쟁분석.md, 비즈니스 모델은 사업.md를 참조한다.

## 핵심 가설

"사용자는 정보를 모으고 싶어하지만, 정리는 귀찮아하고, 나중에 꼭 필요할 때 찾고 싶어한다."

여러 도구를 사용하면 정보가 분산된다. 정리는 부담이고, 필요할 때 찾기 어렵다. 이 세 가지 문제를 동시에 해결하는 도구를 만든다.


## 문제 인식

### 정보 파편화의 실제 비용

현대 지식 노동자의 정보는 너무 많은 곳에 흩어져 있다. 윈도우 스크린샷, 카카오톡 나에게 보내기, 인스타 저장, 유튜브 재생목록, 브라우저 북마크, 클립보드, 각종 메모 앱. 어디에 뭘 저장했는지 기억나지 않는다.

글로리아 마크 교수의 연구에 따르면, 한 번 방해를 받으면 원래 하던 일에 다시 완전히 집중하는 데 평균 23분 15초가 걸린다. 단순한 0.5초의 앱 전환이 23분의 몰입 시간을 파괴하는 행위인 것이다.

우리 뇌는 멀티태스킹을 하는 게 아니라 작업 사이를 빠르게 전환하며 '전환 비용(switch cost)'을 치른다. 보수적으로 하루 50번 전환, 매번 30초 손실이면 하루 25분을 허공에 날린다. 하지만 진짜 비용은 시간이 아니라 '사고의 모멘텀' 파괴다. 끓는 물을 90도까지 올렸다가 불을 끄고 다시 켜는 것과 같다.

계속된 컨텍스트 전환은 결국 창의적 연결 고리의 단절과 결과물 품질 저하로 이어진다. 깊은 몰입 상태(Deep Work)에 아예 진입하지 못하면 생산성 저하는 40% 이상까지 뛸 수 있다.

### Pain Point 상세

수집이 불편하다. 텍스트는 복사/붙여넣기를 반복하고, 이미지는 다운로드 후 정리하고, 링크는 북마크 폴더를 관리하고, 스크린샷은 따로 폴더를 만든다. 매번 다른 앱으로 관리하는 반복 작업이다.

저장이 불편하다. 노션에 문서 정리, 픽픽에 스크린샷, 브라우저에 북마크, 갤러리에 이미지. 저장 위치를 기억하기 어렵고 중복 저장이 발생한다.

검색이 불편하다. 어디에 저장했는지 기억 안 나고, 여러 앱을 돌아다니며 검색해야 하고, 연관 정보를 함께 찾기 어렵고, 저장 당시 맥락을 잊어버린다.


## 핵심 철학

"정리는 프로그램이, 활용은 사용자가."

이 한 문장이 프로젝트의 본질이다. 사용자는 수집만 하면 된다. 정리는 프로그램이 알아서 한다. 결과물은 실용적으로 활용 가능하다.

구체적인 원칙:
- 심플 is best. 불필요한 복잡성을 제거한다.
- 접근성, 직관성을 극대화한다.
- 사용자의 작업 흐름을 방해하지 않는다.
- 터치 한 번이라도 줄인다.
- 권장 설정을 기본으로 해두고 커스터마이즈를 제공한다. 사용자가 앱을 설정하며 들 에너지도 생각한다.
- 사용자는 복잡한 시스템을 전혀 느끼지 못하면서도 그 혜택을 받을 수 있어야 한다.


## 기록학적 기반

하버드 기록학의 원칙을 현대 사용자 니즈에 맞게 적용한다.

Records Continuum Model:
1. 데이터 수집 (생산)
2. 메타데이터 부여 (포착)
3. 체계적 정리 (조직화)
4. 실제 활용 (다원화)

이 흐름이 자연스럽게, 자동으로 이어지도록 한다.

기록학의 핵심 원칙 적용:
- 진본성(Authenticity): 원본 보존, 출처 정보 자동 저장, 수집 시점 타임스탬프, 체크섬 저장
- 무결성(Integrity): 자동 백업, 중복 방지, 수정 불가능한 원본 저장소
- 맥락성(Context): 수집 당시 탭 정보, 주변 검색어, 연관 콘텐츠, 작업 환경 스냅샷 자동 캡처
- 검색성(Retrievability): 메타데이터 기반 다각적 검색 (키워드, 맥락, 유의어)

기록물의 생애주기를 관리하는 것이 기록학의 핵심이다. 가치평가 -> 보존처리 -> 분류와 정리 -> 활용. 이 전체 과정이 하나의 흐름으로 이어진다. 입력(수집) -> 처리(정리/기술) -> 저장(보존) -> 출력(활용)이 끊임없이 이어지는 운영체제와 같다.


## 설계 철학

> "최고의 인터페이스는 인터페이스가 없는 것이다. 그 다음은 이미 아는 인터페이스다."

### 인지 부하 최소화

모든 새로운 패턴은 작업 기억 할당, 패턴 학습 시간, 오류와 복구 사이클, 인지 전환 비용을 요구한다. 그래서 기존 멘탈 모델을 활용한다. VS Code를 쓸 줄 아는 사람은 우리 앱도 바로 쓸 수 있어야 한다. Cmd+S를 누르면 저장되고, Cmd+F를 누르면 검색창이 열려야 한다.

### 몰입 상태 유지

모달 다이얼로그 없이 모든 것은 인라인 또는 비차단 방식이다. 예측 가능한 200ms 애니메이션. 키보드 우선 설계. 불필요한 확인 없는 조용한 작업. 모든 것 자동 저장.

### 점진적 복잡성 (양파 모델)

Layer 1(표면): 드래그 앤 드롭, 클릭하여 열기, 간단한 정리. Layer 2(발견 가능): 키보드 단축키, 분할 뷰, 일괄 작업. Layer 3(고급): 사용자 정의 워크플로우, API 접근, 자동화. 각 레이어는 그 자체로 완전하고 유용하다.

### 성능 = 기능

```
0-100ms:    즉시 (피드백 불필요)
100-300ms:  빠름 (미묘한 피드백)
300-1000ms: 로딩 중 (명확한 피드백)
1000ms+:    느림 (진행 표시기)
```

수집 < 100ms, 검색 < 100ms, 애니메이션 200ms, 60fps. 성능보다 기능을 희생한다.

### 로컬 우선, 클라우드 보강

핵심 기능은 절대 네트워크에 의존하지 않는다. 로컬은 즉시(0ms 지연), 비공개, 신뢰성 있고, 빠르다. 클라우드는 동기화, 백업, 협업, AI 향상 기능으로 보강한다.


## 왜 VS Code + Chrome 패턴인가

VS Code의 강력한 레이아웃과 Chrome의 우아한 애니메이션을 결합했다.

VS Code를 선택한 이유: 74% 개발자 선호도, 3,500만+ 활성 사용자. 3-패널 레이아웃(왼쪽 탐색, 중앙 콘텐츠 70% 집중, 오른쪽 보조 도구)은 시선 추적 연구에서 40% 스캔 감소, 25% 빠른 파일 찾기를 보여줬다. 파일 트리는 보편적 멘탈 모델이라 학습 곡선이 없다.

Chrome을 선택한 이유: 65% 브라우저 시장 점유율, 30억+ 사용자. 200ms 애니메이션은 부드럽고 추적 가능한 최적 타이밍이다. 탭 드래그 재정렬, 부드러운 닫기, 중간 클릭 등 사용자가 기대하는 패턴 그대로.

혁신은 익숙한 패턴을 대체하지 않고 향상시킨다. 코어는 익숙하게, 가장자리에서 혁신한다. 파일 트리는 그대로 쓰고, AI 분류로 향상시킨다. 탭은 그대로 쓰고, 의미 검색을 추가한다.


## 트레이드오프

의식적으로 선택한 것들:

친숙함 vs 혁신: 친숙함을 선택했다. 학습 곡선 제거, 즉각적인 생산성을 얻고 독창적 UX를 포기했다.

성능 vs 기능: 성능을 우선했다. 100ms 이하 응답 시간을 얻고 일부 실시간 고급 기능을 포기했다.

최소 노력 vs 최대 커스터마이징: 스마트 기본값을 선택했다. 즉시 완벽하게 작동하고 설정 피로감이 없다.

모든 사용자 vs 파워 유저: 점진적 복잡성을 선택했다. 초보자를 위한 직관적 UI, 필요시 활성화되는 고급 기능.

절대 포기하지 않을 것: 사용자 경험 최우선, 최소 학습 곡선, 100ms 이하 응답 시간, 작업 흐름 연속성, 데이터 무결성.


## 리서치 워크플로우

이 도구가 지원하는 전체 흐름: 정보 수집 -> 검토 -> 통합 -> 정제 -> 아이디어 발상.

수집 단계에서 사용자는 단축키 한 번으로 텍스트, 이미지, 링크, 스크린샷, 클립보드를 캡처한다. 프로그램은 자동으로 원본을 보존하고 맥락을 캡처하고 메타데이터(시간, 출처, 키워드 3개, 한 줄 요약)를 생성한다.

정리 단계에서 AI가 백그라운드에서 주제어를 추출하고, 관계도를 구성하고, 맥락을 분석하고, 자동 분류한다. 사용자는 필요시 7가지 북마크(빈 체크, 체크, X 체크, 동그라미, 세모, X, 별)로 중요도만 표시하면 된다.

활용 단계에서 기본 시간순 정렬에 통합 검색(키워드, 맥락, 연관, 유의어)을 제공한다. 결과는 타임라인과 관계도로 표시한다.

이 프로그램은 단순히 정보를 수집하고 정리하는 유틸리티가 아니다. '인지적 마찰'을 최소화해서 사용자가 '생각의 흐름'을 잃지 않도록 보호하는 '인지 보호막(Cognitive Shield)'이다.


## 개발 원칙

> "한 세션에 완성하고, 완벽하게 테스트하고, 자신있게 병합한다."

5가지 핵심 원칙:
1. 데모 우선 개발: demos/에서 자유롭게 실험, 검증되면 features/로 graduation
2. 분해 가능한 설계: 처음부터 쪼갤 수 있게. UI, Logic, Data로 나눈다
3. 리프 노드 아키텍처: 2-4시간 단위로 완성, 테스트 커버리지 90% 이상
4. 익숙한 패턴 활용: 새로운 패턴 만들기 전에 이미 아는 것이 있는지 확인
5. 사용자 중심 개발: 추측이 아니라 증거와 데이터로 결정


## 개인적 동기

저는 정보를 수집하고 정리하는 과정에서 생각의 흐름이 계속 끊어진다는 문제를 경험했다. 링크, 스크린샷, 메모, 이미지 등이 여러 공간에 흩어져 있었고, 필요한 정보를 찾으려 여러 앱을 오갈 때마다 사고의 깊이가 얕아지는 것을 느꼈다.

그냥 키고 적으면 알아서 정리되는 메모장이 있었으면 좋겠다고 생각했다. 사용자가 본질적인 사고에 집중할 수 있도록 몰입을 돕는 것이 프론트엔드 개발자가 만들어야 할 가치라고 생각했다.
