## Code Style (from main-rules.mdc)

- 반말 사용 ("합니다" → "해")
- SOLID 원칙과 Clean Architecture 준수
- DRY 원칙 - 중복 코드 제거
- YAGNI - 당장 필요 없는 기능 만들지 않기
- 함수명은 목적을 표현 (구현 방법 X)
- 매직 넘버 대신 상수 사용
- BDD 방식으로 테스트 작성 (행동 중심 개발)
- 기술 부채 방지를 신경써줘

## 소통의 원칙

효과적인 소통을 위한 세 가지 핵심 원칙:

### 1. 전문성의 원칙
**대화의 주제를 정확히 알아야 함.**
- 모르는 것에 대해 얘기하지 말고 아는 것만 얘기하기.

### 2. 공감의 원칙
**듣는 사람의 입장에서 생각해야 함.**
- 상대방에게 중요한 부분이 무엇인지 파악해야 정말 의미 있는 대화를 할 수 있음.

### 3. 단순함의 원칙
**간결하고 명확하게.**
- 진정으로 듣는 사람의 입장에서 생각하고, 말하고자 하는 주제를 제대로 이해하고, 최대한 간결하고 명확하게 대화를 한다면 여러분은 어느새 소통의 달인이 될 것임.


설정 → 레이아웃 → 기능 추가 → 구조 정리 순서로 진행하고 있고, 빠르게
  기능을 붙여나가는 바이브 코딩 스타일이구나.

  ★ Insight ─────────────────────────────────────
  바이브 코딩의 핵심은 "빠른 실험과 반복"이야. 폴더 구조도 새 기능 추가가 쉽고, 기능-뷰-라우트
  연결이 명확해야 해. 너무 복잡한 구조보다는 직관적이고 실용적인 구조가 필요해.

데모에서 먼저 만들고 → features로 옮기는 워크플로우

데모에서 실험 → 검증되면 features로 이동. 이건 "Spike and Stabilize" 패턴이

https://www.youtube.com/watch?v=KEK_WcSTiuE
 영상에 나왔던 Do's, Don'ts 그대로 가져올 수 있는건 가져오는게 어때? 

```
1. 설정 및 구성 → 2. 레이아웃 구조 → 3. 기능 개발 → 4. 폴더 정리
                                              ↓
                                데모 → 테스트 → 통합 → 배포
```
