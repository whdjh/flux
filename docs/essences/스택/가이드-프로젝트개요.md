# 프로젝트 개요 / Project Overview

## 프로젝트 소개

**VS Code + Chrome UX Boilerplate**는 검증된 UX 패턴을 활용하여 빠르게 데스크톱 애플리케이션을 개발할 수 있는 Electron 기반 보일러플레이트입니다.

### 핵심 철학

"20억 사용자가 이미 익숙한 인터페이스를 재발명하지 않고, 당신의 핵심 기능 개발에 집중하세요."

## 왜 이 보일러플레이트인가?

### 전통적 접근법의 문제점
```
 수개월간 UI/UX 결정에 시간 소비
 모든 컴포넌트를 처음부터 구현
 불확실한 사용자 경험
 6개월 이상의 개발 기간
```

### 우리의 해결책
```
 첫날부터 작동하는 UI (검증된 패턴)
 첫 주부터 커스텀 기능 개발
 검증된 UX 패턴 (VS Code + Chrome)
 자신있게 빠른 배포
```

## 세 가지 핵심 기둥

### 1. Proven Patterns (검증된 패턴)
- **VS Code 3-Panel Layout**: 복잡한 정보 관리를 위한 검증된 레이아웃
  - Left: File Explorer / Navigation
  - Center: Main Content / Editor
  - Right: Additional Info / Tools

- **Chrome Animations**: 프리미엄 느낌의 부드러운 애니메이션
  - 200ms 표준 애니메이션
  - 하드웨어 가속
  - 자연스러운 전환

### 2. Structured Decisions (체계적 의사결정)
- **Architecture Decision Records (ADR)**
  - 모든 중요 결정 문서화
  - 의사결정 배경과 근거 기록
  - 팀 전체의 컨텍스트 공유

- **BDD Specifications**
  - 기능별 명세서
  - Design Rationale 포함
  - 과학적 UX 원칙 적용 (Fitt's Law, Miller's Law)

### 3. Progressive Development (점진적 개발)
```
demos/ → features/ → production
  ↓         ↓            ↓
실험     검증        배포
```

**Demo-First 워크플로우**:
1. `demos/`에서 빠르게 프로토타입
2. 사용자 피드백으로 검증
3. `features/`로 정제된 코드 이동

##  보안 아키텍처

### Defense-in-Depth 철학

보안은 단일 방어선이 아닌 **다층 방어(Defense-in-Depth)** 전략을 사용합니다. 각 레이어는 독립적으로 작동하며, 하나의 레이어가 우회되더라도 다른 레이어가 공격을 차단합니다.

**핵심 원칙**:
-  **독립성**: 각 레이어는 다른 레이어에 의존하지 않음
-  **단일 책임**: 각 레이어는 특정 공격 유형을 방어
-  **실패 안전**: 검증 실패 시 요청 즉시 거부
-  **성능**: 전체 검증 오버헤드 <1ms

#### Layer 1: Input Validation (Zod)

잘못된 형식의 데이터가 시스템에 진입하는 것을 차단한다.

**구현**: [schemas.ts](../src/shared/validation/schemas.ts)
```typescript
// 안전한 경로 문자열 정의
const safePathString = z
  .string()
  .min(1, 'Path cannot be empty')
  .max(4096, 'Path exceeds maximum length')
  .refine(
    (path) => !PathValidator.hasDangerousPatterns(path),
    'Path contains dangerous patterns'
  );

// 9개의 작업별 스키마
export const SinglePathSchema = z.object({ path: safePathString });
export const WriteFileSchema = z.object({
  path: safePathString,
  content: z.string().max(10485760), // 10MB limit
});
```

**검증 내용**:
- 타입 검증 (string, boolean, array)
- 길이 제한 (경로: 4096자, 파일: 10MB)
- 위험 패턴 검출 (`..`, `null bytes`, 제어 문자)
- 비즈니스 규칙 (예: 경로 배열은 최대 1000개)

**미들웨어**: [IPCValidation.ts](../src/shared/validation/IPCValidation.ts)
```typescript
const handler = createValidatedHandler(
  SinglePathSchema,
  async (event, input) => {
    // input은 이미 검증되고 타입이 지정됨
    return await fileSystem.readFile(input.path);
  }
);
ipcMain.handle('file:readFile', handler);
```

#### Layer 2: Rate Limiting

DoS(Denial of Service) 공격을 방지하고 리소스 남용을 차단한다.

**구현**: [IPCRateLimiter.ts](../src/backend/infrastructure/middleware/IPCRateLimiter.ts)

**알고리즘**: Sliding Window
```typescript
class IPCRateLimiter {
  private requestTimestamps = new Map<string, number[]>();

  checkLimit(channel: string): boolean {
    const now = Date.now();
    const { max, window } = this.limits.get(channel);

    // 윈도우 밖의 타임스탬프 제거
    timestamps = timestamps.filter(t => now - t < window);

    // 제한 확인
    return timestamps.length < max;
  }
}
```

**채널별 제한**:
| Channel | Max Requests | Time Window | Use Case |
|---------|--------------|-------------|----------|
| file:readFile | 20 | 1초 | 읽기 집약적 작업 |
| file:writeFile | 10 | 1초 | 쓰기 작업 제한 |
| file:createFile | 10 | 1초 | 파일 생성 제한 |
| file:deleteItem | 5 | 1초 | 삭제 작업 신중히 제한 |

**메모리 효율**:
- Map 기반 타임스탬프 추적
- 만료된 타임스탬프 자동 정리
- 채널별 독립적 제한

#### Layer 3: Path Validation

Path Traversal 공격을 차단하고 허용된 디렉토리만 접근하도록 한다.

**구현**: [pathValidation.ts](../src/shared/utils/pathValidation.ts)

**3단계 검증**:
```typescript
class PathValidator {
  validatePath(requestedPath: string): void {
    // 1. Normalize: 경로 정규화
    const normalized = path.normalize(path.resolve(requestedPath));

    // 2. Block traversal: .. 패턴 차단
    if (normalized.includes('..')) {
      throw new PathValidationError('Path traversal detected');
    }

    // 3. Verify base: 화이트리스트 확인
    const allowed = this.allowedBasePaths.some(base =>
      normalized.startsWith(base)
    );
    if (!allowed) {
      throw new PathValidationError('Path outside allowed directories');
    }
  }
}
```

**차단되는 공격 패턴**:
```typescript
// Path traversal
'../../etc/passwd'           //  Blocked by Layer 3
'..\\..\\windows\\system32'  //  Blocked by Layer 3

// Null byte injection
'/valid/path\0.txt'          //  Blocked by Layer 1

// Control characters
'/path/with\n/newline'       //  Blocked by Layer 1

// Absolute path outside workspace
'/etc/passwd'                 //  Blocked by Layer 3
'C:\\Windows\\System32'       //  Blocked by Layer 3
```

### IPC 보안 통신 흐름

**요청 흐름 (Request Flow)**:
```
┌──────────┐   invoke()    ┌───────────┐   validated   ┌──────────┐
│ Renderer │  ────────────> │ Preload   │  ──────────>  │   Main   │
│ Process  │   { path: X }  │  Bridge   │  { path: X }  │ Process  │
└──────────┘                └───────────┘               └──────────┘
                                                              │
                                                              ↓
                                                         [Zod Layer]
                                                         Type check
                                                         Format check
                                                              │
                                                              ↓
                                                        [Rate Limiter]
                                                        DoS protection
                                                              │
                                                              ↓
                                                      [Path Validator]
                                                      Traversal check
                                                      Whitelist check
                                                              │
                                                              ↓
                                                      [File System API]

```

**에러 처리 (Error Handling)**:
```
Any Layer Fails
      │
      ↓
  Throw Error
      │
      ↓
  Log Error (Main Process)
      │
      ↓
  Return Error (to Renderer)
      │
      ↓
  User Notification (UI)
```

## 기여 가이드

### 코딩 규칙
- **절대 경로 사용**: `@/` alias 사용
- **Demo First**: 모든 새 기능은 `demos/`에서 시작
- **컴포넌트 재사용**: `shared/components/ui/` 먼저 확인
- **테마 사용**: 하드코딩 색상 금지
- **테스트 작성**: 모든 기능에 테스트 포함

### Pull Request 프로세스
1. Feature branch 생성
2. Demo 구현 및 테스트
3. Features로 이동 및 통합
4. 테스트 통과 확인
5. PR 생성 (ADR/BDD 문서 포함)
