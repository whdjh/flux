# VS Code Tab System - BDD Specification

## Design Rationale (설계 근거)

### 왜 VS Code 탭 시스템인가?

정보 관리 앱에서 여러 문서를 동시에 다루는 것은 필수적이다. 사용자는 빠르게 문서 간 전환하고, 작업 컨텍스트를 유지하며, 시각적으로 작업 상태를 파악해야 한다.

VS Code를 선택한 이유는 다음과 같다:
1. 검증된 효율성: 수백만 개발자가 매일 8시간 이상 사용하는 검증된 패턴
2. 근육 기억 활용: 이미 익숙한 단축키와 인터랙션 (Ctrl+Tab, 드래그 앤 드롭)
3. 컨텍스트 유지: 탭 상태(수정됨, 고정됨, 미리보기)로 작업 흐름 보존
4. 시각적 피드백: 명확한 상태 표시(●수정됨, 📌고정됨)로 한눈에 파악

즉각적 사용성, 강력한 키보드 단축키, 검증된 UX를 얻었다. 독창적 탭 디자인, 모바일 최적화, 단순성을 포기했다.

---

## Overview
VS Code 탭 시스템은 Microsoft Visual Studio Code의 탭 관리 시스템을 완벽하게 구현한 것으로,
드래그 앤 드롭, 탭 재정렬, 컨텍스트 메뉴, 스크롤 등의 기능을 포함합니다.

## Feature: Tab Creation and Display

### Scenario: Creating a new tab
```gherkin
Given 에디터 그룹이 비어있는 상태
When 사용자가 파일을 열면
Then 새로운 탭이 생성되어야 한다
And 탭에 파일 이름이 표시되어야 한다
And 탭에 적절한 파일 아이콘이 표시되어야 한다
And 탭이 활성화된 상태여야 한다
```

### Scenario: Creating multiple tabs
```gherkin
Given 에디터 그룹에 하나의 탭이 있는 상태
When 사용자가 다른 파일을 열면
Then 두 번째 탭이 생성되어야 한다
And 새로운 탭이 활성화되어야 한다
And 이전 탭은 비활성화 상태여야 한다
```

### Scenario: Tab display with long filename
```gherkin
Given 탭의 파일명이 매우 긴 상태
When 탭이 렌더링되면
Then 파일명이 적절히 잘려서 표시되어야 한다
And 마우스 호버 시 전체 파일명이 툴팁으로 표시되어야 한다
```

## Feature: Tab State Management

### Scenario: Marking tab as dirty (modified)
```gherkin
Given 탭에 연결된 파일이 열려있는 상태
When 사용자가 파일 내용을 수정하면
Then 탭에 수정 표시(●)가 나타나야 한다
And 탭의 isDirty 상태가 true가 되어야 한다
```

### Scenario: Saving a dirty tab
```gherkin
Given 탭이 수정된 상태(isDirty: true)
When 사용자가 파일을 저장하면
Then 수정 표시가 사라져야 한다
And 탭의 isDirty 상태가 false가 되어야 한다
```

### Scenario: Pinning a tab
```gherkin
Given 일반 탭이 표시된 상태
When 사용자가 탭을 고정(pin)하면
Then 탭에 고정 아이콘이 표시되어야 한다
And 탭이 탭 바의 왼쪽으로 이동해야 한다
And 탭을 닫기 어려워져야 한다 (확인 필요)
```

## Feature: Tab Interaction

### Scenario: Clicking on a tab
```gherkin
Given 여러 탭이 열려있는 상태
When 사용자가 비활성 탭을 클릭하면
Then 클릭한 탭이 활성화되어야 한다
And 이전 활성 탭이 비활성화되어야 한다
And 에디터 내용이 클릭한 탭의 내용으로 전환되어야 한다
```

### Scenario: Closing a tab with close button
```gherkin
Given 탭이 열려있는 상태
When 사용자가 탭의 X 버튼을 클릭하면
Then 탭이 닫혀야 한다
And 다음 탭이 자동으로 활성화되어야 한다
And 마지막 탭인 경우 이전 탭이 활성화되어야 한다
```

### Scenario: Middle-click to close tab
```gherkin
Given 탭이 열려있는 상태
When 사용자가 탭을 마우스 휠 클릭하면
Then 탭이 닫혀야 한다
```

## Feature: Tab Drag and Drop

### Scenario: Reordering tabs within same group
```gherkin
Given 에디터 그룹에 3개의 탭이 있는 상태 [Tab1, Tab2, Tab3]
When 사용자가 Tab3을 Tab1 위치로 드래그하면
Then 탭 순서가 [Tab3, Tab1, Tab2]로 변경되어야 한다
And 드래그 중 시각적 피드백이 제공되어야 한다
And 드롭 위치 표시기가 나타나야 한다
```

### Scenario: Moving tab to another editor group
```gherkin
Given 두 개의 에디터 그룹이 있는 상태
And 첫 번째 그룹에 탭이 있는 상태
When 사용자가 탭을 두 번째 그룹으로 드래그하면
Then 탭이 첫 번째 그룹에서 제거되어야 한다
And 탭이 두 번째 그룹에 추가되어야 한다
And 두 번째 그룹에서 탭이 활성화되어야 한다
```

### Scenario: Creating new group by dragging
```gherkin
Given 하나의 에디터 그룹만 있는 상태
When 사용자가 탭을 에디터 영역 오른쪽 가장자리로 드래그하면
Then 드롭 존 오버레이가 표시되어야 한다
And 드롭 시 새로운 에디터 그룹이 생성되어야 한다
And 탭이 새 그룹으로 이동되어야 한다
```

## Feature: Tab Context Menu

### Scenario: Opening context menu
```gherkin
Given 탭이 표시된 상태
When 사용자가 탭을 우클릭하면
Then 컨텍스트 메뉴가 표시되어야 한다
And 메뉴에 다음 옵션들이 포함되어야 한다:
  | Option | Description |
  | Close | 현재 탭 닫기 |
  | Close Others | 다른 탭 모두 닫기 |
  | Close to the Right | 오른쪽 탭 모두 닫기 |
  | Close All | 모든 탭 닫기 |
  | Pin/Unpin | 탭 고정/해제 |
  | Split Right | 오른쪽으로 분할 |
  | Split Down | 아래로 분할 |
```

### Scenario: Closing other tabs
```gherkin
Given 에디터 그룹에 5개의 탭이 있는 상태
And 3번째 탭이 선택된 상태
When 사용자가 "Close Others"를 실행하면
Then 3번째 탭만 남아야 한다
And 나머지 탭들이 모두 닫혀야 한다
```

## Feature: Tab Scrolling

### Scenario: Horizontal scrolling with many tabs
```gherkin
Given 탭 바 너비보다 많은 탭이 열려있는 상태
When 탭이 탭 바를 초과하면
Then 수평 스크롤이 가능해야 한다
And 스크롤 버튼이 양쪽에 표시되어야 한다
And 마우스 휠로 스크롤 가능해야 한다
```

### Scenario: Auto-scroll to active tab
```gherkin
Given 스크롤이 필요한 많은 탭이 있는 상태
And 활성 탭이 보이지 않는 위치에 있는 상태
When 사용자가 보이지 않는 탭을 활성화하면
Then 탭 바가 자동으로 스크롤되어야 한다
And 활성 탭이 보이는 영역에 나타나야 한다
```

## Feature: Tab Animations

### Scenario: Tab open animation
```gherkin
Given 에디터 그룹이 있는 상태
When 새로운 탭이 생성되면
Then 탭이 부드럽게 나타나야 한다 (fade-in)
And 탭 너비가 애니메이션으로 확장되어야 한다
```

### Scenario: Tab close animation
```gherkin
Given 탭이 열려있는 상태
When 탭이 닫히면
Then 탭이 부드럽게 사라져야 한다 (fade-out)
And 탭 너비가 애니메이션으로 축소되어야 한다
And 다른 탭들이 부드럽게 이동해야 한다
```

## Feature: Tab Accessibility

### Scenario: Keyboard navigation
```gherkin
Given 여러 탭이 열려있는 상태
When 사용자가 Ctrl+Tab을 누르면
Then 다음 탭으로 이동해야 한다
And Ctrl+Shift+Tab으로 이전 탭으로 이동해야 한다
```

### Scenario: Screen reader support
```gherkin
Given 스크린 리더가 활성화된 상태
When 탭이 포커스를 받으면
Then 탭의 이름이 읽혀야 한다
And 탭의 상태(수정됨, 고정됨)가 알려져야 한다
And 탭의 위치(3개 중 2번째)가 알려져야 한다
```
