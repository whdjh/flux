## 경쟁 제품 분석

### 유사 앱 목록

수집 특화 도구: Readwise, Omnivore, Eagle, MyMind, Fabric

올인원 도구: Notion, Obsidian, Evernote, Apple Notes, Microsoft OneNote, Google Keep, Bear, Ulysses, Simplenote

AI 검색 특화: Recall, Karakeep

기타: Raindrop, Boardmix, Keep it, Goodnotes, Memo it, EdrawMind, Microsoft Sticky Note

### 초기 사용자 피드백 (8명)

기존 도구에 만족하는 사용자도 있지만(옵시디언 사용자), 포스트잇 모드 같은 차별화가 필요하다. 노션은 렉이 심하고 옵시디언은 협업 기능이 없어서 협업 기능이 강력한 차별화 포인트가 된다. 즉각적 접근성이 중요하고 유연한 창 관리가 필요하다. 기록해둔 링크를 2줄로 요약해주는 AI 요약 기능이 핵심 Wow 포인트다. 심플한 메모 + AI 자동 분류/요약 조합이 핵심이라는 의견도 있었다. 수집 세션 개념과 북마크/스티커 시스템도 제안됐다.

### 차별화 전략

1. 전체 워크플로우 통합: 수집부터 아이디어 발상까지 한 곳에서
2. 인지 전환 비용 제거: 여러 앱 오가지 않고 작업 지속
3. AI 자동화 + 심플함: 강력한 기능이지만 사용은 간단하게
4. 유연한 창 관리: 포스트잇 모드로 작업 방해 최소화
5. 협업 기능: 옵시디언에 없는 실시간 협업

핵심 가치 제안: "전 세계 지식 노동자들의 시간과 에너지를 절약하고, 생각의 흐름을 보호하여 더 깊고 창의적인 사고를 가능하게 한다."


## AI 최적화 UI의 미래

LLM과의 대화는 1980년대 터미널 사용과 비슷하다. 아직 GUI가 개발되지 않았지만 일부 특성은 예측할 수 있다.

인터페이스는 시각적 방식으로 구현될 것이다. 인간의 뇌가 시각 정보(사진, 차트, 애니메이션)를 처리하는 데 매우 특화되어 있기 때문이다. 뇌의 약 3분의 1이 시각 정보 처리에 사용된다.

GUI는 생성적이고 입력 조건에 따라 변할 것이다. 사용자의 프롬프트에 맞춰 실시간으로 GUI가 생성되며 필요한 모든 구성 요소가 즉각 제공된다. 기존의 고정된 화면 레이아웃을 벗어나 목적에 맞춰 구성이 변화한다.

절차적 구성의 정도는 열린 질문이다. 한쪽 끝에는 확산 모델이 전체 출력 캔버스를 그려내는 방식, 다른 쪽에는 React 컴포넌트(이미지, 차트, 애니메이션, 다이어그램)가 채워지는 방식이 있다. 두 가지가 혼합될 것이며 후자가 주요 뼈대가 될 것이다.

현재 이 변화는 이미 시작되고 있다. 코드 블록, LaTeX 수식, 마크다운, Mermaid 차트, Artifacts 탭 같은 기능이 초기 형태를 갖추고 있다.


## AI-인간 협업 패턴: Cloudflare 사례

Cloudflare가 OAuth 2.1 라이브러리를 거의 전체 Claude로 작성했다. 모든 프롬프트, 수정 과정, 인간 개입 순간을 git 커밋 메시지에 보존했다. 프로젝트를 이끈 엔지니어 Kenton은 원래 AI 회의론자였지만 두 달 후 운영 환경 수준의 인증 라이브러리를 거의 다 만들어냈다.

### 효과적인 협업 패턴

예제로 프롬프트하기가 가장 효과적이었다. 라이브러리 사용 코드를 보여주는 상당한 양의 코드 블록으로 시작하면 메서드 시그니처의 모호함이 사라진다.

"X라고 했는데 Y로 해야 해. 수정해줘" 패턴도 잘 작동했다. 현재 상태에 대한 명확한 맥락, 변경 이유, 구체적 방향을 제시하는 형태다.

문서화는 단 한 문장 프롬프트로 포괄적인 스키마 문서가 생성됐다. 과거에는 지루한 잡무였던 일이 개발의 자연스러운 부산물로 바뀌었다.

### AI가 고전한 부분

클래스 선언을 제대로 옮기지 못했고, 검색 및 바꾸기가 중복 코드 블록을 처리하지 못했다. 커밋 40개 지점부터 수동 커밋이 잦아졌다. 스타일링, 미사용 메서드 제거 같은 정리 작업이었다. AI가 코드의 95% 이상을 생성했지만 인간의 감독은 과정 내내 필수적이었다.

### 실용적 교훈

- 결과물에 집중하라. 공개 엔드포인트와 예상 동작을 정의하거나 사용 예시를 보여준다
- 프롬프트를 버전 관리 자산으로 취급하라. 커밋 메시지에 포함하면 미래의 유지보수와 디버깅에 유용하다
- 여러 번의 프롬프트는 기본이다. 거의 모든 기능은 반복과 개선이 필요했다
- 직접 손대는 것을 두려워하지 마라. 어떤 버그는 프롬프트보다 수동 수정이 더 빠르다

프롬프트를 코드와 함께 커밋하면 git 히스토리가 단순한 변경 기록에서 '의도의 기록'으로 바뀐다.


## 바이브 코딩 사례: Vibe Test

이브(Eve)라는 비개발자 출신 프로덕트 매니저가 Bolt를 사용해 Vibe Test라는 앱을 만들었다. 바이브 코더들이 자신의 앱을 체계적으로 테스트하도록 돕는 도구다.

성공적으로 제품을 출시한 바이브 코더들은 실제 개발에 20%, 테스트에 80%의 시간을 쓴다. 체계적으로 테스트하지 않으면 AI가 코드의 무언가를 망가뜨렸다는 걸 뒤늦게 깨닫게 된다. 이 때문에 80% 지점에서 막혀서 출시하지 못하는 경우가 있다.

프로젝트 구조화 방식이 흥미롭다. 복잡한 프로젝트를 기능별로 여러 개의 다른 프로젝트로 나누어 만들고, 각각이 작동하는 것을 확인한 후 마지막에 하나로 합쳤다. 프로젝트가 커지면 AI가 잘 작업하기 어려워지기 때문이다.


## 디자인 철학: 조니 아이브

조니 아이브는 사랑과 배려로 제품을 만든다고 말한다. 누군가 박스를 열고 케이블을 꺼낼 때 "누군가 나를 신경 썼구나"라고 느끼게 하는 것이 영적인 것이다. 스티브 잡스는 "종(species)에게 감사를 표현하는 방법"이라고 했다.

단순함은 혼란에 질서를 가져오는 것이다. 본질과 목적, 삶에서의 역할을 간결하게 표현하는 것이다. 미니멀리즘은 종종 메마르고 영혼 없는 제품으로 끝나지만, 진정한 단순함에는 기쁨과 유머가 있다. 내 마음 상태가 결국 작업에 구현된다. 희망적이고 낙관적이고 기쁜 실천이 제품에 반영된다.

사람들은 측정하기 쉬운 속성(일정, 비용, 속도, 무게)에 대해서만 이야기한다. 하지만 숫자로 쉽게 측정할 수 없는 디자이너와 창작자의 기여가 동등하게 중요하다. 즐겁고 기쁜 것은 더 많이 사용되고 더 생산적이다.

사람들은 배려를 감지한다. 서비스에서는 사람을 대면하기 때문에 쉽지만, 객체나 소프트웨어를 통해서도 배려를 감지한다. 부주의도 감지한다. 훌륭한 캐비닛 제작자가 보이지 않을 서랍 뒷면까지 마감하는 것처럼, 아무도 보지 않을 때 우리가 하는 것이 우리가 얼마나 진화한 사람인지의 표시다.

작은 팀에서 서로 신뢰하고 사랑하는 것이 근본적으로 중요하다. 서로를 위해 만드는 것을 일상적 연결 방법으로 삼으면 상대를 더 걱정하게 되고, 취약해지며, 감사하게 된다. 기능하지 않으면 추하다. 효용과 미학 사이의 거짓 대립은 없다.


## Shadcn/UI 커스터마이징

Shadcn/UI는 컴포넌트 라이브러리가 아니다. 자신만의 컴포넌트 라이브러리를 만들도록 돕는 도구다. MUI처럼 node_modules에 추상화된 코드가 아니라 components 폴더에 직접 들어있는 소스 코드를 수정한다. Radix UI 프리미티브를 감싸는 래퍼일 뿐이다.

커스터마이징은 globals.css 파일부터 시작한다. :root는 모든 것에 적용되고 .dark 클래스는 다크 모드에 적용된다. 색상은 oklch()로 정의한다. L은 인지된 밝기(0~1), C는 채도, H는 색상환 각도(0~360)다.

테마를 전역으로 업데이트하려면 tweak-cn을 쓴다. Shadcn 자체 테마 라이브러리보다 낫다. 색상뿐 아니라 radius, 타이포그래피, 자간, 그림자를 모두 커스터마이징할 수 있다.

컴포넌트는 components 폴더 안에 있는 파일을 직접 수정한다. 별도의 컴포넌트를 만들지 말고 바로 그 컴포넌트 파일 안에서 업데이트한다. 전역 스타일은 모든 variant에 적용되고 variants로 더 상세하게 커스터마이징한다. 커스텀 variant도 추가할 수 있다.

사용 사례: vercel.com, cal.com, dub.co


## 제품 런칭 프레임워크

### 런칭 전 준비

웨이팅리스트 페이지는 앱 개발 전에 만든다. 초기 관심도를 측정하고 베타 테스트 사용자 목록을 확보한다. 앱 스크린샷 하나와 이메일 입력창만 있으면 된다. 도구: Framer + FormSpark.

### 런칭 전 체크리스트

분석 시스템(PostHog)을 도입한다. 사용자가 왜 떠나는지 초기에 파악해서 제품을 개선한다. 나중에 하지 말고 지금 바로 설치한다.

피드백 보드(Canny 또는 UserJot)를 구현한다. 사용자가 기능 요청을 올리고 투표하게 만든다. 개발자가 예측하는 것과 실제 사용자 요구는 완전히 다를 수 있다.

이메일 시퀀스 시스템(Loops)을 구축한다. 특정 주기로 프로그래밍된 이메일을 보내서 리텐션을 높인다. 가입 후 7일간 미사용 유저에게 피드백 요청, 2주에 걸쳐 유용한 기능 소개 등이다.

앱 스토어 리스팅을 최적화한다. 애플은 신규 앱 출시 초반에 검색 노출 부스트 기간을 준다. 앱 스크린샷에 최소 3~4일 투자한다.

실제 랜딩 페이지를 제작한다. 웨이팅리스트와 다르게 앱의 가치를 명확히 보여주고 다운로드를 유도한다. 최소 1주일 이상 공들인다. 도구: Framer.

### 런칭 시점과 실행

런칭 시점은 베타 테스트 기간 동안 사용자들이 며칠이라도 꾸준히 앱을 사용하는 모습이 보일 때다. 데이터보다 감에 가깝다.

런칭은 본격적으로 한다. 일주일 전부터 분위기를 띄우고, 소셜 미디어/친구/지인을 총동원하며, Product Hunt에 런칭하고, Reddit 같은 커뮤니티에 적극적으로 알린다.


## AI 산업 전략: Eric Schmidt TED 2025

Eric Schmidt는 AI가 과소평가되고 있다고 주장한다. 대부분 ChatGPT 수준으로 AI를 인식하지만, 강화학습의 발전으로 계획(planning)과 전략이 가능해졌다. 궁극적으로 에이전트들이 모든 비즈니스 프로세스를 운영하게 될 것이다.

세 가지 제한 요인이 있다. 에너지(미국에 90GW 추가 필요, 원전 90개 규모), 데이터(공개 인터넷 데이터 소진, 합성 데이터 생성 필요), 지식의 한계(완전히 새로운 것을 발명하는 능력)다.

미중 경쟁이 AI의 결정적 전장이다. 미국은 폐쇄 모델 중심, 중국은 오픈소스 중심이다. 오픈소스의 급속한 확산은 사이버/바이오 수준뿐 아니라 핵 위협 수준에서도 위험할 수 있다. 초지능 경쟁에서 먼저 도달하면 네트워크 효과로 따라잡기가 불가능해지고, 이로 인한 선제공격 논의가 실제로 이루어지고 있다.

AI 안전에서 에이전트가 자체 언어를 발명하거나, 통제 불가능한 재귀적 자기 개선, 무기 직접 접근, 자기 복제를 하면 차단해야 한다. 하지만 글로벌 경쟁 시장에서 개발을 멈추는 것은 현실적이지 않다. 가드레일을 확립하는 방향이 필요하다.

조언: "매일 물결을 타라. 일회성이 아닌 매일의 실천이다. 이 기술을 사용하지 않으면 동료와 경쟁자에 비해 뒤처진다. 빠르게 채택하라."
