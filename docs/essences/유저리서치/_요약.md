# 유저리서치 통합

Flux(SnapNote) 프로젝트의 유저리서치 결과를 통합한 문서다. 2024년 1주차부터 3주차까지의 스크리너, 학술 연구, UI 체크포인트, 온보딩 테스트 피드백을 하나로 엮었다.

제품 비전은 비전.md, 경쟁 분석은 경쟁분석.md, 기능 명세는 기능명세/, UI/UX는 UI-UX.md, 기술 스택은 스택.md, 비즈니스는 사업.md를 참조한다.


## 핵심 문제 정의

### 인지적 마찰

정보가 여러 앱(Notion, 북마크, 메모, 카톡, 클립보드, 이메일, 바탕화면)에 파편화되어 작업 전환 비용이 발생한다. 단순한 시간 낭비를 넘어 "생각의 흐름"이 단절되고, 깊은 사고(Deep Work)가 방해받아 생산성의 질이 저하된다.

글로리아 마크의 연구에 따르면 작업 전환 후 원래 작업으로 복귀하는 데 평균 23분 15초가 걸린다. 사무직 근로자는 평균 3분마다 작업이 중단되며, 중단된 작업의 18%는 당일 내에 재개되지 않는다. 작업 속도를 높여 보상하려 하지만 이는 더 높은 스트레스를 동반한다.

### 정보 손실 불안

"분명 봤는데 어디에 저장했지?"라는 경험이 반복된다. 중요 발표 전 자료를 못 찾아 발표가 실패하거나, 획기적 아이디어를 메모했으나 위치를 분실해 영구 손실되는 상황이 발생한다. 불안감, 좌절감, 통제력 상실로 이어진다.

### 도구 간 전환 피로

Notion + Obsidian + Readwise + 북마크 + 메모 앱을 조합(Patchwork)해서 사용한다. 각 도구마다 다른 UI/UX를 학습해야 하니 인지 부하가 증가한다. 정보 정리 도구가 오히려 복잡성을 증가시키는 역설이 발생한다.


## 학술적 근거

네 편의 연구가 제품의 설계 방향을 뒷받침한다.

Gloria Mark(2008, CHI)의 연구는 작업 중단 후 복귀에 23분 15초가 걸린다는 핵심 수치를 제공한다. 사무직 근로자는 3분마다 작업이 중단되고, 중단이 잦을수록 보상 행동(속도 증가)이 나타나지만 스트레스가 동반된다.

Information Overload(2024, ScienceDirect)는 정보 과부하의 원인을 세 가지로 정리한다. 정보 절대량의 기하급수적 증가, 정보의 분산, 검색/정리 도구의 부족이다. 대처 전략으로 필터링, 우선순위, 기술 도구 활용, 다중 스킬 학습을 제시한다.

Multitasking(2024, Current Psychology)은 작업 전환으로 인지 능력이 20% 감소한다는 결과를 보여준다. 하루 평균 300회 이상 작업 전환이 발생하고, 31.6회 중단된다. 연간 4,500억 달러의 글로벌 생산성 손실이 추산된다.

Task Switching(2025, Cognitive Research)은 작업 전환 효과가 즉각적이지 않고 11.5초간 지속된다는 점을 입증했다. 하루 300회 전환하면 57.5분을 인지 저하 상태로 보내는 셈이다. 기능 추가가 아니라 전환 자체를 줄이는 통합 설계가 핵심이라는 시사점을 준다.


## 타겟 사용자

R&D 연구원, 비즈니스 인텔리전스, 시장 조사, 기획자, 작가 등 생산성에 민감한 "파워 유저"가 주요 대상이다. Deep Work를 추구하고, 적극적으로 더 나은 워크플로우를 탐색하는 사람들이다.

대다수 사용자는 불편함을 감수하며 수동적으로 머무르지만, 생산성에 민감한 소수의 파워 유저가 끊임없이 더 나은 워크플로우를 탐색한다. 이들이 초기 타겟이다.

### 전환 계기 (Last Straw Moments)

- 중요 발표 직전 핵심 자료를 못 찾아 발표를 망침
- 떠오른 아이디어를 발전시키려다 여러 앱을 헤매다가 원래 생각을 잊어버림
- 마감에 쫓겨 보고서를 쓰는데 "분명 봤는데 어디 저장했지?"가 반복됨

### JTBD 관점

"새로운 프로젝트를 위해 웹에서 리서치할 때, 여러 앱을 오가며 집중력을 잃지 않고, 수집한 정보들을 한곳에서 매끄럽게 연결하여 독창적인 인사이트를 얻도록 도와주세요."

고객이 말하는 "진전"은 인지적 혼란에서 벗어나 정보가 유기적으로 연결되어 생각의 흐름이 끊기지 않는 상태로 나아가는 것이다. 단순한 시간 절약이 아니라 더 깊고 창의적인 사고가 가능해지는 것이 진정한 진전이다.


## 초기 사용자 의견

제품 아이디어를 주변에 공유하고 받은 원문 피드백이다.

1. 정윤이형 - 옵시디언 잘 쓰고 있으니까 괜찮다. 맥북의 미션 컨트롤 - 핫코너처럼 우측 하단에 뜨는 메모 어떤지.

2. 김성수 대표님 - 노션은 렉이 심하고, 옵시디언엔 협업 기능이 없으니까, 협업 기능을 만들면 사용하겠다.

3. 단짝 친구 - 그냥 있는거 쓴다. 사람은 앞에 있는거 쓴다. 보이는거. 평소엔 우측에 세로로 길게 메모장을 세팅해둔다.

4. 사업계획서 멘토님 - 기록해둔 링크를 2줄로 요약해주는 기능이 있으면 쓰겠다. 너무 필요하다.

5. 국내 1위 기록학자 김익한 교수님 - "음력 단계에서는 심플하게 메모를 할 수 있고 자동 분류나 요약 기능 같은 것에 의해서 쉽게 데이터베이스로 관리할 수 있는 기능이 있다면 참 좋겠다 생각해 보았습니다."

6. 수환이 - 수집하기 시작한 시점부터 단축키를 눌러 종료할 때까지 수집되는 정보들을 묶어. 분류한 뒤, 나중에 정리할 때, 그 섹터의 정보를 한 단계 걸러주는 북마크 기능이 쓸만 하겠다.

7. 영의님 - "웹 스크래핑? readwise, omnivore, mymind, fabric 있죠. 전 fabric으로 정착했음"


## 감정적 요구

사용자가 원하는 감정은 통제감, 차분함, 창의적 희열이다. 피하고 싶은 감정은 압도감, 불안감, 좌절감이다.

사회적으로는 "체계적이고 통찰력 있는 전문가"로 보이고 싶다.


## 성공 지표

### 북극성 지표

주간 활성 통합자(Weekly Active Integrators) 수. 단순 수집을 넘어 메모, 검색, AI 기능을 활용해 정보를 연결하고 종합하는 사용자를 핵심 지표로 삼는다.

### 선행 지표

- 사용자당 주간 아이템 수집 수
- 수집된 아이템 대비 검색 비율
- 콘텐츠 재활용률(수집 정보가 메모나 AI 대화에서 재사용되는 비율)

### 정성 지표

"정보 찾는 시간 감소 + 창의적 작업 시간 증가" 피드백
