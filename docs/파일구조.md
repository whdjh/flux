# 파일구조

pnpm workspace + Turborepo 기반 모노레포. 앱별 코드는 `apps/`, 공유 코드는 `packages/`.

```
flux/
├── apps/
│   ├── backend/           # flux-be를 참조 (실코드는 별도 저장소)
│   ├── cli/               # 기능 검증용 CLI — UI 없이 핵심 루프 검증, packages/* 위에서 작동
│   └── frontend/
│       ├── web/           # Next.js (App Router) — 웹 + API Routes
│       ├── desktop/       # Tauri v2 — Next.js WebView 래핑
│       ├── mobile/        # React Native (Expo) — iOS/Android
│       └── extension/     # Chrome Extension MV3 (계획)
├── packages/
│   ├── shared/            # 엔티티 타입, 순수 TS 유틸, 공통 상수
│   ├── api-client/        # flux-be REST/WSS 클라이언트, Zod 스키마
│   ├── store/             # SQLite 스키마·쿼리 (플랫폼 바인딩은 apps가 주입)
│   ├── editor-core/       # loro 기반 에디터 코어 로직
│   └── ui/                # 웹/데스크톱 공용 컴포넌트 (모바일은 별도)
├── docs/                  # 기준 문서
│   ├── requirements/
│   ├── features/          # 기능 단위 명세
│   ├── design-system/
│   ├── screens/
│   └── memory/            # AI·사람 작업 맥락 자산
│       ├── essences/      # 원재료 (브레인스토밍·레퍼런스)
│       ├── prompts/       # 병렬 실행 프롬프트
│       └── context/       # 세션 기록 (MMDD.md)
├── .claude/               # AI 에이전트·룰 (worktrees/는 git worktree 임시 폴더, gitignore)
│   ├── agents/
│   └── rules/
├── CLAUDE.md              # AI 진입 문서
├── .gitmessage.txt        # 커밋 메시지 템플릿
├── package.json           # 루트 워크스페이스
├── pnpm-workspace.yaml
└── turbo.json
```

## 주요 경로

| 경로 | 역할 |
|------|------|
| `apps/cli` | 기능 검증용. UI 없이 packages/* 위에서 수집·정리·메모·검색·동기화 끝까지 작동 — 검증된 흐름을 web/desktop/mobile에 이식 |
| `apps/frontend/web` | 1순위 배포 타깃. SSR·API Routes·loro WASM |
| `apps/frontend/desktop` | Tauri로 web을 래핑 + OS 네이티브(포스트잇·트레이·단축키) |
| `apps/frontend/mobile` | RN Expo. 수집 중심(Share Sheet, 카메라, 음성) |
| `apps/frontend/extension` | 브라우저 수집 접점 (MV3) |
| `packages/shared` | 가장 아래. 누구나 import 가능 |
| `packages/api-client` | flux-be 프로토콜. REST + WSS + 재연결 |
| `packages/store` | SQLite 래퍼. CLI는 better-sqlite3(현재 작동), 웹은 wa-sqlite, 모바일은 op-sqlite, 데스크톱은 tauri-plugin-sql(계획) |
| `packages/editor-core` | loro 플러그인·바인딩. WASM/JSI 차이를 숨긴다 |
| `packages/ui` | 웹/데스크톱 전용 React 컴포넌트 (Tailwind) |
| `docs/memory/essences/` | 원재료(브레인스토밍·레퍼런스). AI가 기준 문서·기능 명세를 채울 때 입력으로 사용 |
| `docs/memory/context/` | 세션 기록. 사람이 다음 세션 재개할 때 읽음 |

## 의존 방향

```
apps/* ─→ packages/* ─→ packages/shared ─→ 외부
```

- `apps/` 간 직접 import 금지 (데스크톱이 웹을 import하지 않음 — 데스크톱은 web 번들을 WebView로 로드)
- `packages/` 간 순환 의존 금지
- `packages/shared`가 최하위. 다른 package를 import하지 않음
- `packages/ui`는 모바일에서 import 금지 (RN과 호환 안 됨)

## 네이밍 규칙

| 대상 | 규칙 | 예시 |
|------|------|------|
| 패키지 이름 | `@flux/<이름>` (scope 통일) | `@flux/shared`, `@flux/api-client` |
| 디렉토리 | kebab-case 소문자 | `api-client`, `editor-core` |
| 파일 (TS) | kebab-case 또는 PascalCase 컴포넌트 | `item-card.tsx`, `ItemCard.tsx` |
| 파일 (문서) | 한글 허용 | `docs/스택.md` |
| 타입 | PascalCase | `Item`, `Document`, `CreateItem` |
| 함수 | camelCase | `createItem`, `findById` |

## 배치 원칙

기능 단위로 응집 > 타입 단위로 분리. 한 기능이 여러 폴더에 흩어지지 않게.

```
# 나쁨 (타입 기준 분리)
web/src/
  components/
    ItemCard.tsx
  hooks/
    useItem.ts
  types/
    item.ts

# 좋음 (기능 기준 응집)
web/src/
  features/
    item/
      ItemCard.tsx
      useItem.ts
      types.ts
```

공통이 되는 순간 `packages/shared`나 `packages/ui`로 승격. 두 앱 이상에서 쓰는 로직은 앱 안에 두지 않는다.

## 문서·에센스 경계

| 구분 | 위치 | 특징 |
|------|------|------|
| 기준 (결정된 것) | `docs/*.md` | 스택·아키텍처처럼 확정. AI가 코드 작성 시 참고 |
| 기능 단위 명세 | `docs/features/*.md` | 한 기능 = 한 파일 |
| 원재료 | `docs/memory/essences/*` | 브레인스토밍·레퍼런스. 모델이 기준 문서 채울 때 입력 |
| 세션 기록 | `docs/memory/context/MMDD.md` | 한 것·근거·할 것. 다음 세션 재개용 |
