# 플랫폼

"수집 < 100ms", "인지 부하 최소화", "로컬 우선" 원칙에서 플랫폼 우선순위를 정했다. 3/2 스택 재검토에서 RN 단일에서 Next.js + RN 분할로 바뀌면서 우선순위도 조정했다.


## 우선순위

```
Web (Next.js) → Desktop (Tauri) → Chrome Extension (JS/TS) → iOS (RN Expo) → Android (RN Expo)
```

웹을 먼저 만들고 Tauri로 데스크톱을 래핑한다. 모바일은 RN Expo로 나중에 한다.

기존 순서는 iOS가 첫 번째였다. "영감은 이동 중에 떠오르니까 모바일이 먼저"라는 논리였다. 하지만 현실적으로 웹/데스크톱에서 핵심 루프(수집→정리→메모→검색)를 먼저 검증하고, 모바일로 수집 경로를 확장하는 게 효율적이다. 2인 팀에서 웹+모바일을 동시에 개발하기 어렵다.


## 1순위: Web

Next.js (App Router). SSR로 공유 링크 미리보기(OG 태그)를 지원하고, API Routes로 AI 프록시와 인증을 처리한다. loro는 WASM으로 브라우저에서 직접 실행한다. SQLite는 wa-sqlite(WASM)로 로컬 저장을 구현한다.


## 2순위: Desktop

Tauri v2. Next.js 웹 앱을 WebView로 래핑한다. 추가로 OS 네이티브 기능(포스트잇 창, 폴더 감시, 클립보드 감시, 글로벌 단축키, 시스템 트레이)을 Rust로 구현한다. 대부분 Tauri 공식 플러그인으로 커버하고, 커스텀 Rust는 최소화한다.

데스크톱 캡처 흐름은 모바일과 다르다. 앱을 여는 게 아니라 백그라운드에 상주하다가 전역 단축키로 팝업을 띄운다. 콜드 스타트가 아니라 핫 스타트라서 Tauri로 충분하다.

Rust 백엔드 지식이 그대로 쓰이고, 프론트엔드는 Web과 동일한 코드다.


## 3순위: Chrome Extension

JS/TS. MV3. 브라우저에서 바로 캡처하는 접점이다. 우클릭 컨텍스트 메뉴, 텍스트 선택 후 저장, 페이지 전체 클리핑, 현재 탭 URL 저장. 브라우저에서 정보를 소비하는 시간이 길기 때문에 여기서 바로 수집할 수 있어야 한다.


## 4순위: iOS

React Native (Expo, New Architecture). 모바일 수집의 핵심 접점이다. Share Extension이 핵심 진입점 — 브라우저, SNS, 유튜브 등 어디서든 공유 버튼으로 수집한다. 카메라 촬영, 클립보드 URL 감지, 음성 메모도 여기서 한다.

loro는 JSI로 네이티브급 성능을 낸다. SQLite는 op-sqlite로 로컬 저장한다. Share Extension과 위젯은 RN 네이티브 모듈로 구현한다.


## 5순위: Android

iOS와 같은 RN 코드베이스에서 나온다. 플랫폼별 분기는 OS 통합 기능(Share Extension → Intent Filter, 위젯 → App Widget)에서만 발생한다. 비즈니스 로직과 UI는 공유된다.


## 플랫폼별 수집 진입점

사용자가 "Flux에 저장한다"는 행위 없이, 기존 습관 그대로 하면 알아서 모이는 구조다.

Web/Desktop: 브라우저 확장으로 Alt+우클릭 수집, 드래그앤드롭. Tauri에서 폴더 감시, 클립보드 감시, 전역 단축키 팝업.

iOS/Android: 공유 시트(Share Sheet)가 핵심. 카메라 촬영, 갤러리 선택, 클립보드 URL 감지, 음성 메모.

Chrome Extension: 우클릭 컨텍스트 메뉴, 텍스트 선택 후 저장, 페이지 클리핑, 탭 URL 저장.


## 왜 Next.js + RN인가

처음에는 Swift/SwiftUI로 시작하려고 했다. cold start가 빠르고 OS 통합이 자연스럽기 때문이다. 하지만 2인 팀에서 Swift+Kotlin+React를 각각 감당할 수 없어서 RN 단일로 갔다.

RN 단일로 가니까 웹 품질이 문제였다. SSR이 안 되고, 공유 링크 미리보기가 불가능하고, 프론트엔드 생태계를 제대로 못 쓴다. 이주훈이 "나중에 Next.js로 바꾸면 더 힘들다"고 판단해서 처음부터 Next.js로 웹을 잡기로 했다.

결과적으로 웹/데스크톱(Next.js + Tauri)과 모바일(RN Expo)을 분리하되, 모노레포(pnpm workspace)로 비즈니스 로직을 공유한다. 코드베이스가 2개로 늘지만 각 플랫폼의 품질이 올라간다.
