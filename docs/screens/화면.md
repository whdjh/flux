# 화면

앱의 화면 구조를 정의한다. 깊이 모델(감시 → 캡처 → 포스트잇 → 몰입)별로 UI가 다르다. (이전 표기 "배경/순간/떠있음/몰입"은 `docs/아키텍처.md`·`essences/앱-재정의.md` 기준으로 통일.)


## 몰입 — 풀 뷰

풀 앱을 열고 아이템을 훑는 화면이다. 세 행위(모으다, 다시 보다, 쓰다) 중 "다시 보다"가 주로 일어난다.

### 구조

다섯 영역으로 나뉜다.

탭 바(최상단). 풀 뷰(⌂)와 노트가 탭으로 열린다. 풀은 항상 첫 탭에 고정된다. VS Code의 탭과 동일한 근육 기억을 쓴다. 배경을 메인보다 한 톤 낮추고(bg-muted) 비활성 탭 텍스트를 muted로 처리해 시선이 콘텐츠로 먼저 간다.

사이드바(좌측). 세 영역으로 나뉜다. 위쪽이 폴더(내가 정리한 분류), 가운데가 세션(수집 중인 맥락), 아래쪽이 타입 필터(아이템 종류별 바로가기). 폴더는 사용자가 만들고, 세션은 수집 흐름에서 자동으로 생긴다. ● 표시가 활성 세션이다. 타입 필터는 현재 맥락 안에서 해당 타입만 보여준다. 복수 선택 가능. 선택된 폴더/세션은 bg highlight만 주고, 활성 맥락 라벨은 툴바가 담당한다(중복 방지). Cmd+B로 토글, 드래그로 리사이즈.

툴바(메인 영역 상단). 왼쪽에 활성 맥락(📂 온보딩 리서치 ▾) + 아이템 수(42개). 오른쪽에 정렬(↕ 아이콘, 클릭 시 드롭다운)과 뷰 모드(⊞ 그리드 / ≡ 리스트). 텍스트를 최소화해 시각적 무게를 낮춘다.

메인 영역. 아이템 카드 그리드. 열 너비는 균일하고 카드 높이가 타입별로 달라 masonry 배치된다. 각 카드에 타입 아이콘, AI 요약, 키워드 칩(hover), 별 표시가 있다. 드래그로 노트에 임베드할 수 있다. 뷰 모드는 그리드(masonry)와 리스트 두 가지.

상태바(최하단). 평상시에는 동기화 아이콘(✓) 하나만 보인다. 문제가 있을 때만 텍스트가 확장된다(⚠ 오프라인 — 재연결 중...). 앱 버전은 설정 화면에 둔다. 20px.

#### 빈 화면

빈 화면은 "비어 있다"를 알리는 게 아니라 다음 행동을 안내한다.

```

### 전환/모션

모션은 장식이 아니라 피드백이다. 디자인 원칙 "즉각"을 따른다.

| 인터랙션 | 모션 | duration | easing |
|----------|------|----------|--------|
| 사이드바 토글 (Cmd+B) | 너비 슬라이드 | 150ms | ease-out |
| 사이드바 리사이즈 | 즉시 (드래그 추종) | 0ms | — |
| 카드 hover | shadow + border 전환 | 100ms | ease-in-out |
| 카드 드래그 | 축소(0.95) + 그림자 상승 | 100ms | ease-out |
| 뷰 모드 전환 (그리드↔리스트) | 레이아웃 전환 | 200ms | ease-out |
| 툴바 드롭다운 열기 | 아래로 펼침 | 100ms | ease-out |
| 상태바 텍스트 확장 | 페이드인 | 150ms | ease-in |
| 폴더/세션 트리 펼침 | 높이 전환 | 150ms | ease-out |
| 탭 전환 | 즉시 (콘텐츠 교체) | 0ms | — |

기본 원칙:
- 150ms 이하. 사용자가 "기다린다"고 느끼면 안 된다.
- reduce-motion 설정 시 모든 전환을 0ms로.
- 장식적 애니메이션(바운스, 오버슈트)은 쓰지 않는다.

|------|----------|
| 아이템 목록 | 카드 스켈레톤 4-8개 (그리드 배치 유지) |

### 반응형

| 1440px+ | 256px 기본, max 360px | 5-6열 | 대형 모니터 |
| 1280px (기준) | 256px 기본 | 4열 | 기본 설계 |
| 1024px | 256px, 접기 권장 | 3열 | 사이드바 접으면 4열 |
| 900px 미만 | 자동 접힘 | 3열 | 사이드바 오버레이 |

사이드바 접힘 동작:
- 1024px 이상: 사이드바 열림 기본. Cmd+B로 토글.
- 900px 미만: 사이드바 자동 접힘. 햄버거 또는 Cmd+B로 오버레이 열기.


### 다크 모드

브랜드 색상 미확정이라 구체적 HEX는 정하지 않는다. 시맨틱 토큰 구조만 정의한다.

| 토큰 | 라이트 역할 | 다크 역할 |
|------|-----------|----------|
| --bg | 흰 배경 | 어두운 배경 |
| --bg-muted | 탭 바, 사이드바 배경 | 탭 바, 사이드바 배경 (더 어둡게) |
| --surface | 카드, 팝오버 배경 | 카드, 팝오버 배경 (bg보다 밝게) |
| --border | 구분선, 카드 테두리 | 구분선, 카드 테두리 (밝은 회색) |
| --text | 본문 텍스트 | 본문 텍스트 (밝은) |
| --text-muted | 보조 텍스트, 캡션 | 보조 텍스트 (더 밝은) |
| --primary | 브랜드 색상 | 브랜드 색상 (밝기 조정) |
| --success | ✓ 동기화 | 동일 |
| --warning | ⚠ 오프라인 | 동일 |

다크 모드에서 주의할 점:
- 카드 shadow는 라이트에서만. 다크에서는 border 강조로 대체.
- 썸네일 위 ★ 오버레이는 반투명 배경 필요 (라이트/다크 모두).


## 몰입 — 우측 패널

풀 뷰 오른쪽에 붙는 멀티탭 패널이다. AI 채팅, 검색 결과, 아이템 상세를 탭으로 전환한다. Cursor의 오른쪽 사이드바, VS Code의 보조 패널과 같은 역할이다.

### 패널 구조

세 개 탭으로 구성된다.

💬 AI 탭. 활성 맥락(폴더/세션)의 아이템을 기반으로 대화한다. 아이템을 @로 멘션하거나, 세션 전체를 요약 요청할 수 있다. 채팅 메시지에서 아이템을 참조하면 인라인 칩으로 표시되고, 클릭하면 📄 상세 탭으로 전환된다.

🔍 검색 탭. 전체 풀 대상 검색 결과를 보여준다. 검색 바는 툴바(또는 Cmd+K)에서 트리거하고, 결과가 이 탭에 리스트로 나온다. 결과 아이템 클릭 시 📄 상세 탭으로 전환.

📄 상세 탭. 선택한 아이템의 전체 내용을 보여준다. 카드를 클릭하면 이 탭이 활성화된다. 메인 그리드에서 카드를 더블클릭하면 노트 에디터로 열리고, 싱글클릭은 이 상세 패널로 미리본다.

```

│  콘텐츠 영역              │  p: 12px
│                          │  flex: 1
│                          │

└──────────────────────────┘

너비: min 280px / default 380px / max 480px
드래그로 리사이즈. Cmd+Shift+B로 토글.
닫힌 상태가 기본. 필요할 때만 연다.
```

### 구조

왼쪽은 노트 에디터다. 마크다운 기반이고, 풀에서 드래그한 아이템을 임베드할 수 있다. [1] 같은 참조 번호로 아이템을 인라인 멘션한다.

오른쪽은 우측 패널과 같은 구조인데, 📄 상세 대신 📦 풀 탭이 들어간다. 노트를 쓰면서 풀의 아이템을 바로 찾아 참조하기 위해서다.

|----|-------------------|

| 🔍 검색 | 풀 전체 검색. 결과를 노트에 드래그 |
| 📦 풀 | 활성 맥락의 아이템 미니 그리드. 풀 뷰의 축소판 |

### 노트 에디터 서식

에디터 엔진은 미정이다. 듀얼 포맷을 지원한다. `.md` 파일은 마크다운 모드, `.txt` 파일은 경량 마크업 모드로 동작한다. 경량 마크업이 기본이다. 마크다운 문법은 토큰 낭비이고, 보이는 그대로 저장하는 메모 앱 철학과 맞지 않기 때문이다.

#### 경량 마크업 (.txt 기본)

```
현재 Cursor IDE + Gemini 2.5 Pro preview 조합
[LLM 벤치](https://livebench.ai/#/)

* 공식 링크
  [해커톤 규칙](https://worldslargesthackathon.devpost.com/rules)
  [커뮤니티 이벤트](https://app.getriver.io/beta/home)
  [공식 예시 사이트](https://thechainsmokers.com/)

@hackathon/files
```

| 문법 | 용도 |
|------|------|
| `[텍스트](URL)` | 클릭 가능한 링크. 긴 URL은 화면에서 `...` truncate, 저장은 전체 |
| `@경로` | 풀 아이템/폴더 참조. 클릭하면 해당 아이템으로 점프 |
| `*` | 불릿 포인트 |
| 2칸 들여쓰기 | 계층 구조 |

이 네 가지만 쓴다. 볼드, 이탤릭, 헤더 같은 문법은 없다.

#### 마크다운 모드 (.md)

`.md`로 저장하면 마크다운 모드가 활성화된다. `#` 헤더, `**볼드**`, `` `코드` ``, `>` 인용 등 표준 마크다운을 지원한다.

#### 슬래시 커맨드 (/)

모드별로 다르게 구성한다.

| 모드 | 커맨드 예시 |
|------|-----------|
| 경량 마크업 | /링크, /파일참조, /체크리스트 |
| 마크다운 | /헤더, /코드블록, /인용, /링크, /파일참조 |

#### 에디터 기능

- Ctrl+D 다중 선택, 멀티커서 편집 (에디터 엔진에 따라 지원 범위 다름)
- AI 자동완성 (Cursor 스타일, 메모 맥락 기반)
- 이미지 삽입 (드래그 앤 드롭, 클립보드 붙여넣기)
- 풀 아이템 임베드 (📦 풀 탭에서 드래그하거나 @ 멘션)

#### 에디터 레이아웃

```
┌──────────────────────────────────┐
│ 제목                              │  text-xl (20px), semibold
├──────────────────────────────────┤
│                                  │
│ 본문                              │  text-md (14px), regular
│                                  │  line-height: 1.5
│ * 불릿 포인트                     │  2칸 들여쓰기로 계층
│   [링크 제목](https://...)        │  링크: primary 색상, 밑줄
│                                  │
│ @hackathon/files                 │  참조: primary 색상, 칩 스타일
│                                  │
│                                  │  p: 24px (좌우), 16px (상하)
└──────────────────────────────────┘

제목과 본문 사이: 16px (spacing-4)
문단 간격: 빈 줄 1개 (line-height × 2)
```


## 감시 — 시스템 트레이

앱을 안 쓰고 있을 때의 유일한 접점이다. 폴더 감시, 클립보드 감시가 백그라운드에서 돌고, 수집이 일어나면 토스트로 알린다. AI가 자동으로 요약, 키워드, 분류를 붙인다. 정확도보다 마찰 0이 중요하다.

```
시스템 트레이 아이콘
──────────────────

데스크톱 우측 하단 (Windows) / 상단 메뉴바 (macOS)

              ┌─ 트레이 아이콘
              │
    ··· 🔔 📶 ◆
              ↑
            Flux 아이콘 (● 수집 중 / ○ 대기)

좌클릭 → 풀 앱 열기
우클릭 → 컨텍스트 메뉴
```

### 컨텍스트 메뉴

```

### 수집 토스트

백그라운드 수집이 일어나면 화면 우하단에 토스트가 뜬다. 3초 후 자동으로 사라진다.

```
화면 우하단
                         ┌──────────────────────────────┐
                         │  ◆  새 아이템 수집됨           │
                         │                              │
                         │  🔗 "UX 리서치 방법론 가이드"  │
                         │  AI 요약 생성 중...            │
                         │                              │
                         │  [ 보기 ]         3초 후 닫힘  │
                         └──────────────────────────────┘

w: 320px, h: auto
p: 12px
radius: 8px (radius-lg)
shadow: shadow-lg
text: 제목 13px/500, 요약 12px/400 muted
[ 보기 ] → 풀 앱에서 해당 아이템 열기
클릭 → 토스트 즉시 닫기
```

### 감시 상태 표시

| 트레이 아이콘 상태 | 의미 |
|-------------------|------|
| ◆ (filled) | 수집 활성, 정상 동작 |
| ◇ (outline) | 수집 비활성 또는 일시 중지 |
| ◆ + 숫자 배지 | 새로 수집된 미확인 아이템 수 |
| ⚠ | 동기화 실패 또는 오류 |


## 순간 — 빠른 캡처

지나가다 1~2초 안에 수집을 끝내는 화면이다. 글로벌 단축키(Cmd+Shift+C)로 트리거한다. AI가 2초 안에 요약을 보여주는 것이 즉각적 보상이다.

```
빠른 캡처 팝업 (화면 중앙 상단)

┌──────────────────────────────────────┐
│  ◆ 빠른 캡처                    × │
├──────────────────────────────────────┤
│                                      │
│  ┌──────────────────────────────┐   │
│  │ 🔍 URL, 텍스트, 또는 메모…    │   │  인풋: 자동 포커스
│  └──────────────────────────────┘   │
│                                      │
│  📂 온보딩 리서치 ▾   대상 맥락       │  활성 세션 자동 지정
│                                      │
│         [ 저장  ⌘↩ ]                │
│                                      │
└──────────────────────────────────────┘

w: 480px
shadow: shadow-lg
radius: radius-lg (8px)
인풋: h 40px, text 14px, 자동 포커스
맥락 선택: 12px, muted, 클릭 시 드롭다운
Esc → 닫기
⌘+Enter → 저장 후 닫기
```

### 입력 감지

인풋에 입력된 내용을 자동 감지해서 타입을 결정한다.

| 입력 | 감지 타입 | 동작 |
|------|----------|------|
| URL 붙여넣기 | 🔗 링크 | OG 데이터 자동 fetch |
| 이미지 붙여넣기 | 🖼 이미지 | 썸네일 미리보기 표시 |
| 텍스트 입력 | 📝 텍스트 메모 | 바로 저장 |
| 파일 드래그 | 해당 타입 | 파일 종류에 따라 분류 |


## 포스트잇 — 항상 위 작은 창

다른 작업 옆에 Flux를 띄워두는 상태다. 브라우저를 보면서 수집하고, 참조하고, 메모를 동시에 한다. "끊기지 않게" 원칙의 가장 극단적인 구현이다.

```
브라우저 위에 떠 있는 포스트잇

┌── 브라우저 ──────────────────────────────────────────┐
│                                                      │
│  UX 리서치 방법론 ─ Medium                            │
│                                                      │
│  사용자 리서치에서 가장 중요한 것은                     │
│  실제 사용자의 행동을 관찰하는 것이다.    ┌─ 포스트잇 ──────────┐
│  인터뷰만으로는 알 수 없는 부분이        │  ◆ 온보딩 리서치    📌 │
│  많다. 관찰과 인터뷰를 병행하면          ├─────────────────────┤
│  더 풍부한 인사이트를 얻을 수            │                     │
│  있다.                                │  관찰 + 인터뷰 병행   │
│                                       │  이 핵심.             │
│  다섯 가지 방법론을 비교하면            │                     │
│  다음과 같다.                          │  [Medium 글](https:…) │
│                                       │                     │
│  1. 사용성 테스트                      │  ─ ─ ─ ─ ─ ─ ─ ─ ─ │
│  2. 맥락적 질문법                      │  💡 관련: 인터뷰 녹음  │
│  3. 카드 소팅                          │  💡 관련: UX 가이드   │
│                                       ├─────────────────────┤
│                                       │  +  ⊞  ▤            │
│                                       └─────────────────────┘
│                                                      │
└──────────────────────────────────────────────────────┘

포스트잇은 항상 위(always-on-top)로 떠 있다.
```

### 포스트잇 구조

```
┌─────────────────────────────┐
│  ◆ 온보딩 리서치          📌  │  타이틀 바: 드래그로 이동
├─────────────────────────────┤
│                             │
│  메모 영역                   │  노트 에디터와 동일한 서식
│  (경량 마크업 / 마크다운)     │  (듀얼 포맷)
│                             │
│  * 관찰 + 인터뷰 병행이 핵심  │
│    [UX 아티클](https://...)  │
│                             │
│  ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ │  AI 연관 아이템 영역
│  💡 관련: 인터뷰 녹음 (3:42) │  클릭 → 풀 앱에서 열기
│  💡 관련: UX 리서치 가이드    │  최대 3개, 비침입적
│                             │
├─────────────────────────────┤
│  +  ⊞  ▤                   │  하단 툴바
└─────────────────────────────┘
```

### 포스트잇 영역별 스펙

타이틀 바.

```
┌─────────────────────────────┐
│  ◆ 온보딩 리서치          📌  │
└─────────────────────────────┘

h: 28px
◆ Flux 아이콘 (활성 맥락 표시)
텍스트: 포스트잇 제목 = 활성 세션/폴더명, 12px/500
📌: 항상 위 토글 (켜짐: primary, 꺼짐: muted)
더블클릭: 풀 앱에서 이 노트 열기
드래그: 창 이동
```

메모 영역.

```
p: 12px
text: 13px/400, leading 1.5
노트 에디터와 동일한 듀얼 포맷 (경량 마크업 / 마크다운)
풀 앱의 노트와 실시간 동기화 — 여기서 쓴 것이 풀 앱에서 이어진다
드래그 인: 브라우저에서 텍스트/링크/이미지를 드래그하면 아이템으로 수집 + 메모에 임베드
```

AI 연관 영역. 점선 아래에 AI가 조용히 관련 아이템을 제안한다. "떠있음에서 AI는 맥락 연결 역할"을 따른다.

```
구분: 1px dashed border
💡 아이콘 + 아이템 제목, 12px, muted
최대 3개. 스크롤 없이 보이는 만큼만.
클릭 → 풀 앱에서 해당 아이템 열기
메모 내용이 바뀌면 AI가 관련 아이템을 갱신한다.
비어 있으면 이 영역 자체가 숨겨진다.
```

하단 툴바.

```
┌─────────────────────────────┐
│  +  ⊞  ▤                   │
└─────────────────────────────┘

h: 24px
+: 새 포스트잇 열기
⊞: 풀 앱 열기 (포스트잇 → 몰입 전환)
▤: 포스트잇 목록 (열린 포스트잇 사이 전환)
icon: 14px, gap: 12px
```

### 포스트잇 치수

```
기본 크기: 280 × 360px
최소: 200 × 200px
최대: 480 × 600px
리사이즈: 우하단 모서리 드래그

투명도 (Liquid Glass):
  배경: oklch(... / 0.85)  — 약간 투명
  blur: 12px backdrop-filter
  border: 1px solid oklch(... / 0.16)
  shadow: shadow-md

비활성(포커스 해제) 시:
  배경: oklch(... / 0.6)   — 더 투명
  border: oklch(... / 0.08)
  메모 내용은 보이지만 흐릿해진다
```

### 포스트잇 ↔ 풀 앱 전환

| 방향 | 트리거 | 동작 |
|------|--------|------|
| 포스트잇 → 풀 앱 | ⊞ 버튼 또는 타이틀 더블클릭 | 풀 앱에서 같은 노트가 열린다 |
| 풀 앱 → 포스트잇 | 탭 바의 포스트잇 버튼 | 현재 노트가 포스트잇으로 분리된다 |
| 포스트잇에서 수집 | 브라우저 드래그 인 | 활성 맥락에 아이템 추가 + 메모에 임베드 |

전환 시 메모 내용이 끊기지 않는다. 포스트잇에서 쓰던 문장이 풀 앱에서 그대로 이어진다.
