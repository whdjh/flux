# 메모

## 목적

수집한 아이템을 엮어 사용자가 자기 생각을 만드는 공간이다. 정보 흐름의 "엮임" 단계 — 들어와서 쌓이고 걸러진 아이템에 자기 언어를 더한다.

코드명은 `Document`(노트), 행위 이름은 "메모"다. "메모를 적다"라는 행위로 만든 결과물이 "노트"다. 아이템이 가볍고(SQLite INSERT 한 번) 무관계면, 노트는 무겁고(loro CRDT 기반) 다른 아이템·노트와 연결된다.

## 입력

편집 행위
- 리치텍스트 입력 (제목, 본문)
- 슬래시(/) 커맨드 (제목·할 일·코드·인용·구분선·이미지·링크 등 블록 삽입)
- 텍스트 서식 (크기·볼드·이탤릭·밑줄·색상·배경)
- 체크리스트
- 이미지 삽입·하이퍼링크

아이템 임베드
- 메인 윈도우의 아이템 카드를 노트로 드래그
- 임베드된 아이템은 노트 안에서 카드 형태로 표시
- 클릭하면 원본 아이템 디테일로 점프

노트 간 링크
- 명시적 링크 (다른 노트 선택 → 인라인 링크 삽입)
- AI 연관 제안 (관련 노트·아이템을 우측 패널에 표시)

작동 위치
- 메인 윈도우 (전체 화면 편집기)
- 우측 사이드바 (검토하면서 옆에 띄움)
- 포스트잇 창 (→창 관리 참조, 투명·간소화 UI)

## 출력

저장 데이터
- `documents` 테이블: id, title, content (loro CRDT 바이트), updated_at
- `item_embeds` 테이블: document_id, item_id, position
- `document_links` 테이블: from_doc, to_doc

UI 피드백
- 자동 저장 (입력 정지 후 디바운스)
- 협업 모드일 때 다른 커서 실시간 표시 (→협업 참조)
- 우측 패널에 AI 연관 제안 (→AI 참조)

내보내기
- Markdown(.md) 다운로드
- PDF (→공유 참조)

이벤트
- `document.created/updated/deleted`
- `item.embedded` (item_id, document_id)

## 흐름

작성 루프
1. 사용자가 새 노트 생성 또는 기존 노트 열기
2. 슬래시 커맨드 또는 직접 입력으로 텍스트 작성
3. 우측 사이드바·메인 윈도우에서 아이템을 드래그해서 임베드
4. 입력 정지 후 디바운스 → loro 변경분이 로컬 저장 + 동기화 큐
5. AI가 노트 내용 기반 관련 아이템·노트 제안 (백그라운드)

검토→메모 루프
1. inbox 또는 폴더에서 아이템 검토
2. 별 표시·체크박스로 1차 거름 (→정리 참조)
3. 중요한 것을 우측 사이드바 메모로 드래그
4. 자기 생각을 덧붙여서 노트 완성

협업 편집
- 한 노트에 여러 사용자 동시 편집 시 loro가 충돌 자동 해소
- 커서 색상으로 사용자 구분
- 슬래시(/) 인라인 채팅 (→협업 참조)

## 예외

오프라인
- 로컬 편집 정상, loro 변경분이 동기화 큐에 보류
- 온라인 복귀 시 자동 병합 (CRDT라 충돌 없음)

임베드 아이템 삭제
- 원본 아이템이 삭제되어도 노트 안 임베드는 깨지지 않음
- soft delete + "[삭제된 아이템]" 표시

큰 노트
- 노트 하나가 수천 블록을 넘으면 가상 스크롤
- loro 문서 분할은 기본적으로 안 함 (사용자가 명시적으로 새 노트 생성)

권한
- 협업 노트에서 초대받은 사람은 모두 같은 편집 권한 (→협업 참조, 역할 구분 없음)

## 하지 않는 것

- 스프레드시트·데이터베이스 뷰 (Notion의 테이블·보드·캘린더)
- 코드 실행
- 수식 계산
- 위키 링크(`[[]]`)와 백링크 그래프 (Obsidian 영역)
- 자동 그래프 시각화 (노트 연결은 명시적 링크 + AI 제안으로 대체)
- 노트 폴더 구조 (노트 자체는 폴더에 안 들어감, 노트는 별도 리스트)
