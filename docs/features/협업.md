# 협업

## 목적

혼자 엮은 생각을 동료에게 넘길 때 앱 밖으로 나가지 않게 한다. 수집·정리·메모·검색이 한 앱에 있어서 흐름이 안 끊기는 게 핵심이라면, 협업은 그 흐름을 팀 단위로 확장한다.

수집+AI 정리+메모+협업이 한 앱에 있는 게 Flux의 포지셔닝이다(9장). 다만 핵심·강화·확장 레이어 중 협업은 확장이다 — 개인 흐름이 먼저 가치를 증명한 다음에 의미가 있다.

## 입력

초대
- 노트 소유자가 이메일·링크로 초대
- 초대 받은 사람이 수락 → 편집자로 등록
- 같은 권한 (역할 분리 없음)

편집 행위
- 실시간 동시 편집 (loro CRDT)
- 텍스트 입력·서식·아이템 임베드 (메모 기능 그대로)
- 슬래시(/) 인라인 채팅 호출
- 댓글 추가 (블록 단위)

표시
- 다른 사용자 커서 (색상 구분)
- 프로필 (아바타·이름)
- 활성 사용자 리스트

## 출력

실시간 반영
- 키 입력 단위 즉시 동기화 (WebSocket 실시간 채널)
- 충돌 자동 해소 (loro CRDT — 사용자 다이얼로그 없음)
- 다른 커서 부드러운 보간

채팅·댓글
- 인라인 채팅 (마우스 위치에서 슬래시로 호출, 휘발성)
- 블록 댓글 (특정 단락에 영속, 해결 처리 가능)
- 멘션 (`@사용자` → 알림)

이벤트
- `collab.user.joined/left` (document_id, user_id)
- `collab.cursor.moved` (실시간 채널)
- `comment.created/resolved`

## 흐름

초대 → 협업 시작
1. 소유자가 노트에서 "공유" 메뉴
2. 이메일로 초대 또는 편집 가능 링크 생성 (→공유 참조)
3. 초대받은 사람이 링크 열고 수락
4. 편집자로 권한 부여, 노트가 협업 모드 활성화

실시간 동시 편집
1. 두 명 이상 같은 노트 진입 → WebSocket 채널 연결
2. loro 변경분이 즉시 채널로 전송, 다른 클라이언트가 받아서 머지
3. 커서·선택 영역도 같은 채널로
4. 누군가 나가면 채널에서 해제, 일반 동기화로 복귀

인라인 채팅
- 사용자가 슬래시(/) 누름 → 마우스 커서 위치에 채팅 입력 활성
- 메시지 입력 → 다른 사용자 화면에 잠시 표시 (채팅창 활성 시 누적)
- 채팅 모드 종료하면 채팅 사라짐 (영속 안 함)

댓글
- 블록 옆 "댓글" 버튼 → 패널에서 작성
- 영속 저장, 해결 표시 가능
- 멘션 시 대상 사용자에게 알림

## 예외

권한 변경
- 초대 취소 (편집자 제거) → 다음 진입 시 접근 거부
- 노트 삭제 → 모든 협업 종료, 다른 사용자에게 알림

네트워크 끊김
- WebSocket 끊기면 일반 동기화로 폴백
- 재연결 시 변경분 머지 (CRDT라 자동)

동시 진입 폭주
- 같은 노트에 동시 사용자 많을 때 부하 분산
- 채널당 동시 연결 한도 (운영 정책)

악의적 편집
- 협업은 신뢰 기반 (초대 모델)
- 분쟁 시 소유자가 편집자 제거 가능
- 버전 비교 안 함 (diff 뷰 없음 의도적)

## 하지 않는 것

- 역할 기반 권한 관리 (읽기/쓰기/관리자 분리)
- 버전 히스토리 비교 (diff 뷰)
- 워크플로우 자동화 (승인 프로세스, 알림 규칙)
- 화상·음성 통화 (인라인 채팅·댓글까지만)
- 외부 사용자 게스트 모드 (가입한 사용자만)
