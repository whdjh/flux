# 검색

## 목적

쌓인 아이템과 노트를 다시 꺼낼 수 있게 한다. "잊지 않게" 원칙의 작동 지점 — 보존했는데 못 찾으면 잊은 것과 같다. 사용자가 정확한 단어를 기억 못 해도(유의어), 정확한 분류를 모르더라도(의미 기반), 자주 쓰는 것(무게)이 위로 오게.

## 입력

검색 트리거
- 메인 윈도우 상단 검색 버튼·단축키 (Cmd/Ctrl+K)
- 우측 사이드바에서 노트 작성 중 인라인 검색
- 검색어 (자유 텍스트, 한국어·영어 혼용)

검색 모드
- 키워드 검색 (정확/부분 일치)
- 의미 기반 검색 (임베딩 유사도, 유의어 포함)
- 두 모드 토글 가능

검색 대상
- 아이템: 제목, URL, AI 요약, 키워드, 본문(텍스트인 경우), OCR 결과(이미지)
- 노트: 제목, 본문 텍스트, 임베드된 아이템 메타

## 출력

결과 정렬
- 1차: 매칭 점수 (키워드 BM25 또는 의미 유사도)
- 2차: 무게 (열림 횟수 + 별 표시 + 노트 참조 횟수, 7장)
- 3차: 최신순

결과 표시
- 통합 리스트 (아이템·노트 섞임)
- 매칭 부분 하이라이트
- AI가 맥락 고려 관련 항목을 함께 제안 (별도 섹션)

UI
- 즉시 검색 (입력하는 동안 디바운스 후 결과 갱신)
- 결과 클릭 → 해당 아이템·노트로 점프
- 정렬 토글 (점수 우선 ↔ 최신 우선)

이벤트
- `search.executed` (query, mode, result_count) — 사용 패턴 학습용

## 흐름

키워드 검색
1. 사용자가 검색어 입력
2. 로컬 SQLite FTS5 인덱스 조회
3. 무게로 가중치 적용해서 정렬
4. 결과 즉시 표시 (로컬 우선)

의미 기반 검색
1. 사용자가 의미 모드 토글
2. 검색어를 임베딩 모델에 보냄 (OpenRouter)
3. 로컬 임베딩 인덱스에서 유사도 검색 (sqlite-vss 또는 유사)
4. 무게 가중치 + AI 맥락 고려 결과
5. 키워드 결과와 통합

AI 연관 제안
- 사용자가 노트 작성 중일 때 노트 내용 기반으로 백그라운드 검색
- 우측 패널에 "관련 아이템" "관련 노트" 자동 표시
- 명시적 검색이 아닌 추론

## 예외

빈 결과
- "결과 없음" 대신 유사 키워드 제안 또는 의미 검색 권유
- 한 번도 수집 안 한 키워드는 외부 검색 권유 (앱 안에서는 처리 안 함)

매우 큰 데이터
- 인덱스가 커지면 로컬 검색이 느려짐 → 청크 단위 점진 표시
- 백엔드 풀텍스트 인덱스 보조 (선택적)

오프라인
- 키워드 검색은 로컬 FTS5라 정상
- 의미 검색은 임베딩 모델 호출 필요 → 마지막 임베딩만 로컬에서 사용, 새 검색어는 큐에 보류 또는 키워드로 폴백

권한
- 협업 노트는 권한 있는 사용자만 검색 결과에 노출
- 로컬 전용 아이템(sync_file=off)은 해당 기기에서만

## 하지 않는 것

- 불리언 검색 (AND/OR/NOT 명시 연산자)
- 정규식 검색
- 외부 웹 검색 (앱 안의 데이터만)
- 자율 에이전트 검색 (사용자 명시 트리거만, AI는 제안만)
