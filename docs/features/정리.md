# 정리

## 목적

수집한 아이템을 사용자가 다시 찾을 수 있게 구조화한다. 단, 수집 시점에 분류를 강요하지 않는다 — 그게 흐름을 끊는다. AI는 메타데이터(요약·키워드)만 자동으로 붙이고, 폴더 배치는 활성 맥락이 있으면 거기, 없으면 inbox로 간다. 분류는 사용자가 검토하면서 자연스럽게 일어난다.

폴더는 "과거를 정리하는 도구"고, 세션은 "미래를 향한 도구"다. 두 축이 다르다. 폴더는 이미 수집한 것을 끌어다 넣는 트리, 세션은 "지금부터 이 주제야"를 선언하면 앞으로 수집되는 것이 자동으로 담기는 시간+주제 묶음이다.

## 입력

폴더 조작
- 폴더 생성·수정·삭제·이동 (좌측 사이드바 트리에서)
- 아이템을 폴더로 드래그
- 폴더 중첩 (parent_id로 트리 구성)

세션 조작
- 세션 시작·종료 (사용자 명시 트리거)
- AI 자동 세션 생성 (시간·주제 클러스터 감지)
- 한 아이템을 여러 세션에 동시 소속

뷰 조작
- 정렬 토글 (최신순, 오래된순)
- 보기 모드 전환 (그리드, 벽돌, 양쪽 정렬, 리스트)
- 카테고리 폴더 (텍스트 하이라이팅·링크·이미지·동영상·클립보드·스크린샷) 자동 분류

활성 맥락
- 사용자가 폴더·세션을 열어둔 상태가 활성 맥락
- 다음 수집부터 해당 맥락으로 자동 배치

## 출력

자동 배치
- 활성 맥락 있음 → 해당 폴더·세션
- 활성 맥락 없음 → inbox
- 카테고리 폴더는 타입에 따라 자동 (이중 소속)

무게 신호
- 열림 횟수 + 별 표시 + 노트 참조 횟수 합산
- 검색 정렬과 AI 연결 제안의 근거 (7장)

UI
- 좌측 사이드바: 폴더 트리, 세션 리스트, 카테고리 폴더 (All, 텍스트, 링크, 이미지, 동영상, 클립보드, 스크린샷)
- 메인 윈도우: 4가지 뷰 (그리드/벽돌/양쪽/리스트), 정렬 토글
- All 폴더: 모든 콘텐츠 (단, 클립보드·스크린샷은 제외, 카테고리 폴더에서만 보임)

이벤트
- `folder.created/updated/deleted/moved`
- `session.opened/closed`
- `item.moved` (폴더 간 이동)

## 흐름

폴더 정리
1. 사용자가 좌측 사이드바에서 폴더 생성
2. inbox 또는 다른 폴더에서 아이템을 드래그
3. SQLite item.folder_id 갱신, 동기화 큐에 push
4. UI 즉시 반영, 백그라운드 동기화

세션 운영
1. 사용자가 "세션 시작" 또는 AI가 자동 제안 (시간+주제 클러스터)
2. 활성 맥락으로 표시, 이후 수집되는 아이템이 자동 소속
3. 사용자가 "세션 종료" 또는 비활성 시간 임계 초과
4. 닫혀도 연결 살아있음 — 닫힌 컨테이너가 아니라 열린 맥락 레이어

검토 루프
1. 사용자가 inbox 또는 폴더를 연다
2. AI가 붙인 요약·키워드 보면서 훑는다
3. 별 표시·노트 참조 같은 행위가 무게에 누적된다
4. 검색·연결 제안 결과 정렬에 무게가 반영된다

## 예외

빈 상태
- 폴더에 아이템 0개여도 정상 (검토 미완료 상태)
- 빈 폴더 삭제는 사용자 명시 액션만 (자동 정리 안 함)

소속 충돌
- 한 아이템이 여러 세션에 속할 수 있음 (정상)
- 카테고리 폴더와 사용자 폴더 동시 소속 (정상, 다른 축)

이동 실패
- 부모 폴더가 자기 자손이 되는 순환 이동 → 거부
- 동기화 충돌 시 server-wins 또는 사용자 확인 (→동기화 참조)

세션 자동 생성 오작동
- AI가 잘못 묶었을 때 사용자가 분리·병합 가능
- 모델은 제안만, 실행은 사용자

## 하지 않는 것

- 명시적 태그 시스템 (폴더·세션·카테고리로 충분)
- 자동 중복 제거 (같은 URL이라도 다른 맥락에서 수집했을 수 있음)
- 복잡한 필터 조합 (속성 A이고 B이면서 C가 아닌 것 같은 불리언)
- 수집 시점 분류 강요 (수집 책임 — 흐름 깨지 않게)
- 자동 정리 실행 (AI 제안만, 사용자 실행)
