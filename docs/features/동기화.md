# 동기화

## 목적

세 행위(수집·검토·메모)가 기기를 넘나든다. 폰에서 수집하고 노트북에서 검토·메모하는 흐름이 끊기지 않게 한다. "잊지 않게" 원칙이 데이터 안전성과 연결되는 지점 — 한 기기를 잃어도 다른 기기에서 그대로다.

기존 도구의 마찰을 제거한다. 수동 sync 버튼 없음, 충돌 다이얼로그 없음, 기기별 분리된 데이터 없음. 사용자는 동기화를 의식하지 않는다.

## 입력

자동 트리거
- 앱 시작
- 네트워크 복귀
- 로컬 변경 발생 (debounce)
- 협업 노트 진입 시 실시간 채널 오픈

수동 트리거
- 강제 동기화 버튼 (디버그·재해 복구 용도)
- 로컬 전용 토글 (`sync_file=off`로 해당 바이너리만 제외)

대상
- 아이템 (메타데이터·바이너리)
- 노트 (loro CRDT 변경분)
- 폴더·세션·임베드 관계
- 무게 신호 (열림 횟수, 별 표시)

## 출력

상태 표시
- 동기화됨 (서버·로컬 일치)
- 오프라인 대기 (변경 있음, 큐에 보류)
- 로컬 전용 ("이 아이템은 {기기명}에만 있음" 다른 기기에서 표시)
- 충돌 해소 중 (실시간 협업)

이벤트
- `sync.completed` (uploaded, downloaded counts)
- `sync.failed` (reason, retry_at)
- `item.synced/document.synced`

API
- 일반 채널: `POST /api/sync/batch` (변경 묶음)
- 실시간 채널: WSS `/api/collab/{document_id}` (loro updates)

## 흐름

일반 동기화 (배치)
1. 로컬에서 변경 발생 → 동기화 큐에 push
2. debounce 후 큐를 묶어서 `POST /api/sync/batch`
3. 서버가 적용·브로드캐스트 → 다른 기기 pull
4. 다른 기기가 로컬에 머지

실시간 협업 동기화
1. 사용자가 노트를 연다 → WebSocket 연결
2. loro 변경분이 즉시 채널로 전송
3. 다른 사용자에게 즉시 반영, 커서·선택 영역도 같이
4. 노트 닫으면 채널 종료, 일반 동기화로 복귀

오프라인 → 온라인 복귀
1. 오프라인 동안 모든 변경이 로컬 큐에 누적
2. 네트워크 복귀 감지 → 큐 순서대로 전송
3. 서버가 충돌 해소 (CRDT라 자동, 메타는 last-write-wins 또는 사용자 확인)
4. 다른 기기의 변경분 pull → 로컬 머지

선택적 로컬 전용
1. 사용자가 큰 바이너리에 sync_file=off 토글
2. 메타데이터만 동기화, 파일 자체는 해당 기기에만
3. 다른 기기에서 "이 아이템은 {기기명}에만" 표시

## 예외

충돌
- 노트(loro CRDT): 자동 해소, 사용자 개입 없음
- 메타데이터: last-write-wins 기본, 중요 충돌은 사용자 확인 다이얼로그
- 동시 삭제·편집: 편집 우선 (삭제는 soft delete라 복원 가능)

네트워크 실패
- 지수 백오프 재시도 (1s → 2s → 5s → 30s → 60s 상한)
- 큐 영속화 (앱 재시작해도 보존)
- UI에 "오프라인" 인디케이터 표시

서버 거부 (auth, quota)
- 401 → 재로그인 유도
- 413 (큰 파일) → 사용자에게 sync_file=off 권장
- 429 → 백오프 후 재시도

큰 변경 묶음
- 한 번에 50MB 초과 시 청크 분할 전송
- 진행률 표시

## 하지 않는 것

- 선택적 동기화 (이 폴더만 이 기기에 — sync_file 토글로 대체)
- P2P 동기화 (서버 경유 필수)
- 사용자 충돌 해소 강제 (CRDT로 자동, 다이얼로그 없음 원칙)
- 동기화 일시정지 토글 (의도적 — 흐름 끊김 방지)
