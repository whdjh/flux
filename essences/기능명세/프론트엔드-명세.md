# Flux 프론트엔드 기능명세서

## 기술 스택

**핵심: Next.js (TypeScript)**

| 구분 | 기술 | 역할 |
|------|------|------|
| 웹 | Next.js (App Router) | SSR, API Routes(AI 프록시, 인증), 공유 링크 |
| 데스크톱 | Tauri v2 | Next.js React 컴포넌트를 WebView에서 렌더링 + OS 네이티브 기능(Rust) |
| 모바일 | React Native (Expo) | 네이티브 앱. UI는 RN으로 별도 작성, 비즈니스 로직은 공유 |
| 브라우저 확장 | Chrome Extension MV3 + React | 수집 전용 |

**Tauri(Rust)가 담당하는 OS 기능**: 포스트잇 창(always on top), 폴더 감시, 클립보드 감시, 글로벌 단축키, 시스템 트레이. 대부분 Tauri 공식 플러그인으로 커버하고, 커스텀 Rust는 최소화.

**공통 기술**

| 구분 | 선택 |
|------|------|
| 로컬 DB | SQLite (Tauri: tauri-plugin-sql, RN: op-sqlite, 웹: wa-sqlite) |
| 상태 관리 | Zustand |
| 스타일 | Tailwind CSS (모바일: NativeWind) |
| 에디터 CRDT | loro |
| AI | OpenRouter API (Next.js API Routes로 프록시) |
| 모노레포 | pnpm workspace |

**코드 공유 구조**

```
packages/
  core/       — 엔티티 타입, 비즈니스 로직 (순수 TS)
  store/      — SQLite 스키마, 쿼리 (순수 TS, 바인딩만 플랫폼별)
  ai/         — OpenRouter 클라이언트, 요약/키워드 파이프라인 (순수 TS)
  sync/       — 동기화 프로토콜 (순수 TS)
  ui/         — 공유 컴포넌트 (웹/데스크톱 공유, 모바일은 별도)

apps/
  web/        — Next.js (웹 + API)
  desktop/    — Tauri (web의 React 컴포넌트 + Rust 네이티브)
  mobile/     — React Native (Expo)
  extension/  — Chrome Extension MV3
```

## 컴포넌트 설계: Flat + Compound 패턴

### 원칙

모든 컴포넌트가 두 패턴을 다 지원할 필요는 없다. 기준은 **내부 구조를 사용자가 제어할 필요가 있는가**.

- **Flat만**: 내부 구조가 고정. 변형은 props로 충분. 단순한 UI 요소.
- **Compound만**: 내부 구조를 자유롭게 조합해야 의미 있는 것. 간편 사용이 불필요.
- **Flat + Compound**: 기본 사용은 간단히(flat), 커스텀이 필요하면 열어줌(compound). **이 패턴은 "자주 쓰이면서 + 맥락에 따라 내부가 달라지는" 컴포넌트에만 적용.**

```tsx
// Flat + Compound 예시: ItemCard
// Flat — 기본 사용 (한 줄로 끝)
<ItemCard item={item} onStar={toggleStar} />

// Compound — 커스텀 필요할 때 (포스트잇에서 축약된 카드 등)
<ItemCard.Root item={item}>
  <ItemCard.Thumbnail />
  <ItemCard.Title />
  {/* AI 요약은 빼고 커스텀 액션만 */}
  <ItemCard.Actions>
    <StarButton />
  </ItemCard.Actions>
</ItemCard.Root>
```

### 패턴 분류

#### Flat만 (내부 구조 고정, props로 충분)

| 컴포넌트 | 이유 |
|----------|------|
| `Button` | variant, size, icon 정도면 충분 |
| `Badge` | 라벨 + 색상. 내부 구조 없음 |
| `Avatar` | src + fallback. 항상 동일 |
| `Tooltip` | trigger + content. 구조 변할 일 없음 |
| `Toggle` | on/off. 단순 |
| `StarButton` | 별 토글. 단순 |
| `SyncStatus` | ✓ / ⟳ / ⚠ 상태 표시 |
| `ViewToggle` | 그리드/벽돌/리스트 전환 |
| `Spinner` | 로딩 표시 |
| `Divider` | 구분선 |

#### Compound만 (조합이 본질, 간편 사용 불필요)

| 컴포넌트 | 이유 |
|----------|------|
| `SplitPane` | `<SplitPane><Pane /><Pane /></SplitPane>` — 패널 수와 내용이 항상 다름 |
| `CommandPalette` | `<CommandPalette><Group><Item /></Group></CommandPalette>` — 그룹과 아이템 구성이 맥락마다 다름 |
| `ContextMenu` | `<ContextMenu><Item /><Separator /><Item /></ContextMenu>` — 메뉴 구성이 항상 다름 |
| `SlashCommand` | `<SlashCommand><Option icon={} label="" /></SlashCommand>` — 명령 목록이 확장됨 |
| `NoteEditor` | 블록 기반. 내부 블록 조합이 본질 |
| `ChatWindow` | `<ChatWindow><MessageList /><Input /></ChatWindow>` — 고정할 이유 없음 |

#### Flat + Compound (자주 쓰이고 + 맥락에 따라 내부가 달라짐)

| 컴포넌트 | Flat (기본) | Compound (커스텀) | 왜 둘 다 필요한가 |
|----------|------------|-------------------|------------------|
| `ItemCard` | `<ItemCard item={item} />` | `<ItemCard.Root><ItemCard.Thumbnail /><ItemCard.Title /></ItemCard.Root>` | 풀에서는 풀카드, 포스트잇에서는 축약, 검색 결과에서는 하이라이트 포함 등 맥락마다 다름 |
| `Sidebar` | `<Sidebar />` | `<Sidebar.Root><Sidebar.Section title="폴더"><FolderTree /></Sidebar.Section></Sidebar.Root>` | 기본 구성이 있지만, 향후 섹션 추가/재배치 가능성 |
| `TabBar` | `<TabBar tabs={tabs} />` | `<TabBar.Root><TabBar.Tab><CustomIcon /><TabBar.Close /></TabBar.Tab></TabBar.Root>` | 기본은 단순하지만, 핀 탭/드래그/커스텀 아이콘 등 변형 |
| `Toast` | `<Toast message="저장됨" />` | `<Toast.Root><Toast.Icon /><Toast.Message /><Toast.Action label="실행취소" /></Toast.Root>` | AI 요약 완료 토스트는 액션 버튼이 필요 |
| `Modal` | `<Modal title="삭제" onConfirm={} />` | `<Modal.Root><Modal.Header /><Modal.Body>{children}</Modal.Body><Modal.Footer /></Modal.Root>` | 확인 모달은 flat, 설정/초대 모달은 compound |
| `SearchResult` | `<SearchResult item={item} />` | `<SearchResult.Root><SearchResult.Highlight /><SearchResult.Meta /><SearchResult.AIContext /></SearchResult.Root>` | 기본 검색 결과 vs AI 맥락 포함 결과 |
| `FolderTree` | `<FolderTree folders={folders} />` | `<FolderTree.Root><FolderTree.Node><FolderTree.Node /></FolderTree.Node></FolderTree.Root>` | 기본은 데이터만 넘기면 되지만, 드래그 타겟/커스텀 아이콘 등 필요할 수 있음 |
| `SessionCard` | `<SessionCard session={session} />` | `<SessionCard.Root><SessionCard.Title /><SessionCard.ItemCount /><SessionCard.AIBadge /></SessionCard.Root>` | 사이드바에서는 축약, 풀뷰에서는 상세 |

### 구현 패턴

```tsx
// Flat + Compound 동시 지원 구현 방식

// 1. Compound 파츠 정의
const Root = ({ item, children }: { item: Item; children?: ReactNode }) => {
  // item을 Context로 제공
  return <ItemCardContext.Provider value={item}>
    <div className="...">{children ?? <DefaultLayout />}</div>
  </ItemCardContext.Provider>
}
const Thumbnail = () => { /* context에서 item 읽음 */ }
const Title = () => { /* context에서 item 읽음 */ }
const Actions = ({ children }: { children: ReactNode }) => { ... }

// 2. 기본 레이아웃 (Flat이 쓰는 것)
const DefaultLayout = () => (
  <>
    <Thumbnail />
    <Title />
    <AISummary />
    <Actions><StarButton /></Actions>
  </>
)

// 3. Flat 진입점
const ItemCard = ({ item, onStar, ...props }: ItemCardProps) => (
  <Root item={item} {...props} />
  // children이 없으므로 DefaultLayout 렌더링
)

// 4. Compound 노출
ItemCard.Root = Root
ItemCard.Thumbnail = Thumbnail
ItemCard.Title = Title
ItemCard.Actions = Actions

export { ItemCard }
```

핵심: Flat은 `children`이 없을 때 `DefaultLayout`을 렌더링. Compound는 `children`으로 내부를 직접 구성. Context로 데이터를 공유해서 prop drilling 없음.

## 공용 컴포넌트

### 패턴 기준

- **Flat만** — 내부 구조가 고정. 어디서 쓰든 같은 모양. props로 변형 충분.
- **Compound만** — 내부 조합이 본질. 간편 진입점 불필요.
- **Flat + Compound** — 기본은 간단히 쓰고, 맥락에 따라 내부를 열어서 구성. "나중에 열 수도 있다"면 처음부터 둘 다 지원.

### Inputs

| 컴포넌트 | 패턴 | 설명 |
|----------|------|------|
| Button | Flat | variant(primary/secondary/ghost/danger), size, icon 유무로 충분 |
| TextField | Flat + Compound | 기본은 라벨+입력. 검색용은 아이콘+클리어 버튼, 메모용은 자동 높이 등 내부가 달라짐 |
| Autocomplete | Compound | 입력+드롭다운+필터 조합이 본질. CommandPalette, 검색 입력에서 활용 |
| Checkbox | Flat | 체크/해제. 라벨 유무 정도 차이 |
| Switch | Flat | on/off 토글 |
| Toggle | Flat | 그룹 내 단일/복수 선택 (뷰 모드 전환 등) |

### Data Display

| 컴포넌트 | 패턴 | 설명 |
|----------|------|------|
| Avatar | Flat | 이미지 또는 이니셜 표시. 크기 variant |
| Badge | Flat | 숫자나 점 표시 |
| Chip | Flat | AI 키워드, 분류 제안 태그에 사용. 삭제 가능 옵션 |
| Divider | Flat | 구분선. 수평/수직 |
| Icon | Flat | 아이콘 래퍼. 크기, 색상 |
| Tooltip | Flat | 호버 시 설명 표시 |

### Feedback

| 컴포넌트 | 패턴 | 설명 |
|----------|------|------|
| Skeleton | Flat | 로딩 placeholder. 텍스트/원형/사각형 variant |
| Toast | Flat + Compound | 단순 메시지는 flat. AI 완료 토스트는 액션 버튼이 필요해서 내부 구성이 달라짐 |
| Modal | Flat + Compound | 확인/삭제 모달은 flat. 설정/초대 모달은 내부를 자유롭게 구성 |
| Alert | Flat + Compound | 단순 경고는 flat. 액션 포함 알림은 내부가 달라짐 |

### Surface

| 컴포넌트 | 패턴 | 설명 |
|----------|------|------|
| Accordion | Flat + Compound | 사이드바 섹션 접기/펼치기. 기본은 제목+내용이지만, 커스텀 헤더가 필요할 수 있음 |

### Navigation

| 컴포넌트 | 패턴 | 설명 |
|----------|------|------|
| TabBar | Flat + Compound | 기본은 탭 목록만 넘기면 됨. 핀 탭, 커스텀 아이콘, 드래그 등 내부가 달라짐 |
| Sidebar | Flat + Compound | 기본 구성이 있지만 섹션 추가/재배치 가능 |
| ContextMenu | Compound | 메뉴 항목 구성이 매번 다름 |
| Dropdown | Flat + Compound | 기본은 옵션 목록만 넘기면 됨. 커스텀 옵션 렌더링이 필요할 수 있음 |

### Layout

| 컴포넌트 | 패턴 | 설명 |
|----------|------|------|
| SplitPane | Compound | 패널 수와 내용이 항상 다름 |

### Utils

| 컴포넌트 | 패턴 | 설명 |
|----------|------|------|
| CommandPalette | Compound | 그룹과 아이템 구성이 맥락마다 다름. Cmd+K |
| Popover | Flat + Compound | 기본은 내용만 넘기면 됨. 복잡한 팝오버는 내부 구성 필요 |

### 요약

- **Flat만 (11개)**: Button, Checkbox, Switch, Toggle, Avatar, Badge, Chip, Divider, Icon, Tooltip, Skeleton
- **Flat + Compound (10개)**: TextField, Toast, Modal, Alert, Accordion, TabBar, Sidebar, Dropdown, Popover
- **Compound만 (4개)**: Autocomplete, ContextMenu, SplitPane, CommandPalette

## 기능 명세

### 1. 수집

**데스크톱**
- 앱 내 드래그앤드롭 (이미지, 텍스트, 파일)
- 클립보드 감시 → 토스트 "저장할까요?" 또는 자동 저장
- 폴더 감시 → 지정 폴더 새 파일 자동 수집
- 브라우저 확장: Alt+우클릭 → 선택 텍스트/이미지/링크 수집

**모바일**
- Share Extension (iOS/Android): 다른 앱 공유 시트에서 Flux 선택
- 카메라 촬영 / 갤러리 선택
- 클립보드 URL 감지 → 배너 "이 링크 저장?"
- 음성 메모 녹음 → STT 텍스트 변환

**공통**
- 수집 시 메타데이터 자동 저장: 제목, URL, 파비콘, 출처 앱, 타임스탬프
- 수집 → UI 반영 **< 100ms**
- 수집 직후 AI 요약/키워드 비동기 처리 (→ AI 참조)

### 2. 정리

- 폴더 트리: 중첩 가능, 드래그 정렬, 우클릭 메뉴(이름변경/삭제/새 하위폴더)
- 세션 목록: 진행 중 상단 고정, AI 자동 세션은 배지 구분
- 뷰 모드 토글: 그리드 / 벽돌(Pinterest) / 양쪽정렬 / 리스트
- 정렬: 최신순 / 오래된순 / 무게순(열림횟수+별+참조횟수)
- 별 표시: 아이템 카드에서 ★ 토글
- AI 분류 제안: 카드에 "📂 OO에 넣을까요?" 칩 표시 → 탭(수락) / ✕(거부) / 길게눌러 수정

### 3. 메모 (노트 에디터)

- loro CRDT 기반 리치텍스트 에디터
- 서식: H1~H3, 볼드, 이탤릭, 밑줄, 취소선, 텍스트 색상, 인라인 코드, 인용 블록
- 슬래시(/) 커맨드: `/item`(아이템 임베드), `/note`(노트 링크), `/ai`(AI 호출), `/checklist`, `/image`, `/divider`
- 아이템 임베드: 아이템을 노트로 드래그 → 인라인 카드(제목+요약+출처+썸네일). 클릭 시 원본 열기
- 노트 간 링크
- 체크리스트, 이미지 삽입, 하이퍼링크
- 타이핑 지연 < 16ms (60fps)

### 4. 검색

- Cmd+K → 커맨드 팔레트 겸 검색
- 실시간 검색 (디바운스 200ms)
- 검색 대상: 제목, 본문, AI 요약, AI 키워드, 노트 제목
- 의미 기반 검색 (유의어 포함, 벡터 유사도)
- 무게 높은 항목 우선 표시
- 결과 하단에 "관련 노트" AI 제안

### 5. AI

- 수집 시 자동 요약(1~3줄) + 키워드(3개) 백그라운드 생성
- 분류 제안 → 수락/거부/수정 (정리 섹션과 연동)
- 세션 자동 생성 제안 (시간+내용 유사도 기반)
- AI 채팅: RAG 기반 대화, 수집 데이터를 컨텍스트로 사용
  - 스트리밍 응답
  - 참조 아이템 인라인 소스 카드 표시
- 음성 대화: STT(입력) + TTS(응답 읽기)
- 모델 선택 (OpenRouter, Next.js API Routes로 프록시)
- **AI의 모든 행위는 제안 — 자동 실행 없음**

### 6. 협업

- 노트 공유 버튼 → 초대 링크 생성
- 초대받은 사람은 동등 편집 권한 (역할 구분 없음)
- 실시간 동시 편집 (loro CRDT + WebSocket)
  - 커서 위치 브로드캐스트, 색상 구분
  - 상단 접속자 프로필 아바타 표시
- 댓글: 텍스트 선택 → 댓글 달기, 사이드 패널 스레드
- 인라인 채팅 (슬래시로 호출)

### 7. 동기화

- 기기 간 자동 동기화 (데스크톱 ↔ 모바일 ↔ 웹)
- 일반: 변경 배치 전송 (5초 디바운스 또는 30개 누적)
- 협업 모드: WebSocket 즉시 전송
- 오프라인 작업 → 온라인 복귀 시 자동 병합
- 로컬 전용 아이템 옵션 (동기화 제외 가능)
- 상태바에 동기화 상태 표시

### 8. 공유

- 노트 → 읽기 전용 링크 생성 (웹 뷰어로 열림)
- 링크 수신자 → "편집자로 초대" 가능 (→ 협업 전환)
- 내보내기: PDF / Markdown

### 9. 창 관리 (데스크톱)

- 포스트잇 모드: 항상 위 투명 창, 수집 입력바 + 최근 수집 미리보기 + 메모 영역
- 분할 뷰: 2/3/4분할 프리셋
- 사이드바 토글 & 리사이즈
- 탭 재정렬, 핀 고정
- 레이아웃 상태 자동 저장/복원
- Cmd+Shift+F → 포스트잇 토글

## 리뷰 코멘트

개념.md와 앱-재정의를 기준으로 검토했다. 기능 명세 9개는 앱-재정의 8장과 일치한다. 컴포넌트 설계와 Flat+Compound 패턴도 잘 잡혀있다. 아래는 보강이 필요한 부분이다.

### 빠진 개념 세 가지

세션(Session)이 정리 섹션(line 269)에서 "세션 목록"으로 등장하지만, 정의가 없다. 세션은 폴더와 다른 세 가지가 있다. 시작/종료 시각이 있고, AI가 자동으로 만들 수 있고, 하나의 아이템이 여러 세션에 속할 수 있다. 닫혀도 연결이 살아있는 "열린 맥락 레이어"다. 폴더와 완전히 다른 컨테이너이므로 별도 정의가 필요하다.

활성 맥락이 빠져있다. "지금 수집 대상으로 지정된 폴더나 세션"이 활성 맥락이다. 수집된 아이템이 어디로 가는지를 결정한다. 수집 기능 명세에 이 개념이 없으면 수집 흐름이 불완전하다.

깊이 모델이 빠져있다. 배경→순간→떠있음→몰입, 네 단계로 사용자의 현재 몰입도를 나타낸다. 창 관리(포스트잇 모드, 분할 뷰)가 이 모델에 기반한 설계인데 연결이 드러나지 않는다. MVP 6번 "깊이별 인터페이스"에서 이미 언급하고 있으니 근거가 되는 모델을 명시하면 좋겠다.

### 근거 확인 필요

동기화 섹션(line 319) "5초 디바운스 또는 30개 누적"은 앱-재정의에 없는 숫자다. 이주훈이 직접 결정한 거라면 근거를 적어두면 좋겠고, 출처가 불분명하면 확인이 필요하다.

MVP 순서(line 346) "수집 < 100ms가 제품 존재 이유"는 살짝 다르다. 100ms는 UI 반응 성능 목표이고, 제품 존재 이유는 "몰입한 사람의 흐름을 지키는 것"이다. 네 원칙 — 끊기지 않게 > 시키지 않게 > 잊지 않게 > 기다리지 않게 — 이 순서로 설계 우선순위가 정해진다.

### 용어

ItemCard 설명(line 104) "풀에서는 풀카드"에서 "풀"이 정의 없이 쓰이고 있다. 개념.md의 설계 어휘에 풀 모델(들어옴→쌓임→걸러짐→엮임→나감)이 정의되어 있으니 참조하거나, 여기서는 "메인 뷰에서는" 정도로 바꾸는 게 명확하다.
