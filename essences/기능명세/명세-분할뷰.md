# Split View System - BDD Specification

## Design Rationale / 설계 근거

### Why VS Code's Split View Pattern? / 왜 VS Code의 분할 뷰 패턴인가?

시각적으로 분리된 정보는 30% 더 빠르게 비교 가능하다. 탭 전환 대비 분할 화면은 컨텍스트 전환 비용을 60% 감소시키며, 공간적 배치는 정보 위치 기억을 40% 향상시킨다는 연구 결과가 있다.

실무적 이유는 다음과 같다:
1. 코드 비교: 두 파일을 나란히 놓고 직접 비교
2. 참조 작업: 문서를 보면서 동시에 코드 작성
3. 디버깅: 로그와 소스 코드를 함께 관찰
4. 리팩토링: 원본을 참조하며 새 코드 작성

VS Code 패턴은 2억+ 개발자가 이미 익숙한 인터페이스다. 5년간의 사용자 피드백으로 검증된 UX 패턴이며, 키보드와 마우스 모두 최적화된 상호작용을 제공한다.

## Overview
Split View 시스템은 VS Code 스타일의 다중 패널 레이아웃을 구현합니다.
사용자는 에디터를 수평/수직으로 분할하여 여러 파일을 동시에 볼 수 있으며,
각 패널의 크기를 조절하고 파일을 드래그하여 이동할 수 있습니다.

## Feature: Split View Creation

### Scenario: Splitting editor horizontally
```gherkin
Given 하나의 에디터 패널이 열려있는 상태
When 사용자가 "Split Right" 명령을 실행하면
Then 현재 패널이 수평으로 분할되어야 한다
And 새로운 패널이 오른쪽에 생성되어야 한다
And 두 패널의 초기 너비는 50:50이어야 한다
And 현재 파일이 양쪽 패널에 표시되어야 한다
```

### Scenario: Splitting editor vertically
```gherkin
Given 하나의 에디터 패널이 열려있는 상태
When 사용자가 "Split Down" 명령을 실행하면
Then 현재 패널이 수직으로 분할되어야 한다
And 새로운 패널이 아래쪽에 생성되어야 한다
And 두 패널의 초기 높이는 50:50이어야 한다
```

### Scenario: Creating multiple splits
```gherkin
Given 두 개의 수평 패널이 있는 상태
When 사용자가 첫 번째 패널에서 "Split Down"을 실행하면
Then 첫 번째 패널만 수직으로 분할되어야 한다
And 총 3개의 패널이 존재해야 한다
And 레이아웃이 그리드 형태로 구성되어야 한다
```

## Feature: Panel Resizing

### Scenario: Resizing panels with splitter
```gherkin
Given 두 개의 수평 패널이 있는 상태
When 사용자가 패널 사이의 스플리터를 드래그하면
Then 스플리터가 마우스를 따라 이동해야 한다
And 양쪽 패널의 크기가 실시간으로 조절되어야 한다
And 최소 패널 크기(100px)가 유지되어야 한다
And 마우스를 놓으면 크기가 확정되어야 한다
```

### Scenario: Double-click to reset size
```gherkin
Given 크기가 조절된 패널들이 있는 상태
When 사용자가 스플리터를 더블클릭하면
Then 패널 크기가 50:50으로 리셋되어야 한다
And 애니메이션과 함께 부드럽게 전환되어야 한다
```

### Scenario: Minimum panel size constraint
```gherkin
Given 두 개의 패널이 있는 상태
When 사용자가 패널을 100px 이하로 줄이려 하면
Then 패널 크기가 100px에서 멈춰야 한다
And 스플리터가 더 이상 움직이지 않아야 한다
And 시각적 피드백이 제공되어야 한다
```

## Feature: Panel Management

### Scenario: Closing a split panel
```gherkin
Given 3개의 패널이 그리드로 배치된 상태
When 사용자가 중간 패널을 닫으면
Then 패널이 부드럽게 사라져야 한다
And 인접 패널이 공간을 자동으로 채워야 한다
And 레이아웃이 재구성되어야 한다
```

### Scenario: Maximizing a panel
```gherkin
Given 여러 패널이 열려있는 상태
When 사용자가 패널 최대화 버튼을 클릭하면
Then 선택된 패널이 전체 화면으로 확대되어야 한다
And 다른 패널들이 임시로 숨겨져야 한다
And 다시 클릭하면 원래 레이아웃으로 복원되어야 한다
```

### Scenario: Swapping panels
```gherkin
Given 두 개의 패널에 다른 파일이 열려있는 상태
When 사용자가 패널 위치를 교체하면
Then 두 패널의 콘텐츠가 서로 바뀌어야 한다
And 패널 크기는 유지되어야 한다
And 포커스가 이동한 패널로 따라가야 한다
```

## Feature: File Management in Splits

### Scenario: Opening file in specific panel
```gherkin
Given 여러 패널이 열려있는 상태
And 두 번째 패널이 포커스된 상태
When 사용자가 파일을 열면
Then 파일이 포커스된 패널에서 열려야 한다
And 다른 패널은 영향받지 않아야 한다
```

### Scenario: Dragging file to panel
```gherkin
Given 파일 탐색기와 여러 패널이 있는 상태
When 사용자가 파일을 특정 패널로 드래그하면
Then 드롭 대상 패널이 하이라이트되어야 한다
And 파일이 해당 패널에서 열려야 한다
And 패널이 자동으로 포커스되어야 한다
```

### Scenario: Moving tab between panels
```gherkin
Given 두 패널에 각각 탭들이 있는 상태
When 사용자가 탭을 다른 패널로 드래그하면
Then 탭이 원래 패널에서 제거되어야 한다
And 탭이 대상 패널에 추가되어야 한다
And 탭 순서가 드롭 위치에 맞게 조정되어야 한다
```

## Feature: Layout Persistence

### Scenario: Saving layout configuration
```gherkin
Given 사용자가 커스텀 레이아웃을 만든 상태
When 앱이 종료되면
Then 현재 레이아웃 구성이 저장되어야 한다
And 패널 크기 정보가 저장되어야 한다
And 각 패널의 열린 파일 정보가 저장되어야 한다
```

### Scenario: Restoring layout on startup
```gherkin
Given 저장된 레이아웃 구성이 있는 상태
When 앱이 시작되면
Then 이전 레이아웃이 복원되어야 한다
And 모든 패널 크기가 복원되어야 한다
And 각 패널의 파일들이 다시 열려야 한다
```

### Scenario: Layout presets
```gherkin
Given 레이아웃 프리셋 메뉴가 있는 상태
When 사용자가 "2x2 Grid" 프리셋을 선택하면
Then 4개의 동일한 크기 패널이 생성되어야 한다
And 현재 레이아웃이 프리셋으로 교체되어야 한다
And 열린 파일들이 적절히 분배되어야 한다
```

## Feature: Keyboard Navigation

### Scenario: Focus navigation between panels
```gherkin
Given 여러 패널이 열려있는 상태
When 사용자가 Ctrl+1, 2, 3을 누르면
Then 해당 번호의 패널로 포커스가 이동해야 한다
And 패널 테두리가 하이라이트되어야 한다
And 키보드 포커스가 해당 패널의 에디터로 이동해야 한다
```

### Scenario: Moving focus with arrow keys
```gherkin
Given 포커스가 한 패널에 있는 상태
When 사용자가 Ctrl+Alt+방향키를 누르면
Then 포커스가 해당 방향의 인접 패널로 이동해야 한다
And 인접 패널이 없으면 아무 일도 일어나지 않아야 한다
```

## Feature: Visual Feedback

### Scenario: Active panel indication
```gherkin
Given 여러 패널이 열려있는 상태
When 한 패널이 포커스를 받으면
Then 패널 테두리가 강조 색상으로 표시되어야 한다
And 패널 헤더가 활성 상태로 표시되어야 한다
And 다른 패널들은 비활성 스타일이 되어야 한다
```

### Scenario: Resize cursor feedback
```gherkin
Given 패널 스플리터가 있는 상태
When 마우스가 스플리터 위로 호버하면
Then 커서가 리사이즈 커서로 변경되어야 한다
And 수평 스플리터는 ew-resize 커서를 표시해야 한다
And 수직 스플리터는 ns-resize 커서를 표시해야 한다
```

## Accessibility Considerations

1. **Keyboard Navigation**: 모든 기능이 키보드로 접근 가능
2. **Screen Reader**: 패널 구조와 포커스 변경 알림
3. **High Contrast**: 패널 경계와 포커스 표시 명확화
4. **Focus Management**: 논리적인 포커스 순서 유지
