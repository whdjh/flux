# 스택

Electron + React 기반 데스크톱 앱 보일러플레이트의 기술 스택, 아키텍처, 개발 환경을 정리한 문서다. 영감 수집 도구를 만들기 위한 3단계 로드맵의 Stage 1에 해당한다.


## 프로젝트 목적

VS Code와 Chrome의 검증된 UX 패턴을 결합한 데스크톱 앱 기반을 구축한다. "20억 사용자가 이미 익숙한 인터페이스를 재발명하지 않고, 핵심 기능 개발에 집중한다"는 철학이다.

로드맵은 세 단계로 나뉜다. 첫째, Electron 보일러플레이트로 견고한 기반을 구축한다. 둘째, 성능 지표에 따라 Tauri 마이그레이션을 검토한다. 셋째, 최종 영감 수집 도구를 완성한다.

## 아키텍처

### 레이어드 구조

Presentation Layer(React)가 최상위에 있고, Application Layer(비즈니스 로직), Integration Layer(VS Code/Chrome 통합), Infrastructure Layer(Electron)가 순서대로 이어진다.

### 프로세스 구조

Electron은 세 가지 프로세스로 나뉜다. Main Process(Node.js)가 윈도우 관리, IPC 통신, 파일 시스템 접근, DB 연결을 담당한다. Renderer Process(Chromium)가 React 앱, Monaco Editor, UI 컴포넌트를 실행한다. Preload Script가 contextBridge로 안전한 API만 노출하는 브릿지 역할을 한다.

### IPC 통신

타입 안전한 IPC 계약을 사용한다. `src/shared/ipc/contracts.ts`에 계약을 정의하고, `src/backend/interfaces/ipc/`에 핸들러를 구현한 뒤, Renderer에서 `window.electronAPI`로 접근한다.

```typescript
// 계약 정의
export interface FileAPI {
  listDirectory(path: string): Promise<FileItem[]>;
}

// 사용
const files = await window.electronAPI.file.listDirectory(path);
```

### Clean Architecture (Backend)

domain 레이어는 순수 비즈니스 로직을 담고 프레임워크에 독립적이다. application 레이어는 Use Cases와 서비스 레이어를 담는다. infrastructure 레이어는 Drizzle ORM, Supabase, 파일 시스템 어댑터를 담는다.


## 보안

### 3-Layer Defense 시스템

보안은 다층 방어(Defense-in-Depth) 전략을 사용한다. 각 레이어가 독립적으로 작동해서, 하나가 우회되더라도 다른 레이어가 공격을 차단한다.

Layer 1(Zod Validation)은 런타임 타입 검증과 포맷 검증을 수행한다. 경로 최대 4096자, 파일 최대 10MB, 위험 패턴 검출(null bytes, 제어 문자)을 포함해 9개 스키마가 있다.

Layer 2(Rate Limiting)는 슬라이딩 윈도우 알고리즘으로 채널별 요청을 제한한다. 읽기 20/초, 쓰기 10/초, 삭제 5/초로 DoS 공격을 방지한다.

Layer 3(Path Validation)은 경로 정규화, path traversal 차단, 화이트리스트 기반 기본 경로 검증의 3단계로 동작한다.

전체 검증 오버헤드는 요청당 1ms 미만이다. 133개 보안 테스트가 100% 통과한다. 보안 점수는 8.5/10(Production Ready)이다.


## 개발 워크플로우

### Demo-First

모든 새 기능은 `demos/`에서 시작한다. 빠르게 프로토타입하고 검증이 끝나면 `features/`로 승격한다. 이렇게 실험과 안정성을 분리한다.

```
demos/ → 프로토타입 → 검증 → features/ → 프로덕션 → 배포
```

### 기능 개발 공식

Feature를 `src/features/`에 만들고, Page를 `src/routes/`에서 조립하고, `src/renderer.tsx`에서 라우터에 등록한다. 다중 패널 레이아웃은 Page가 여러 Feature를 조립하는 방식이다.

### 컴포넌트 구조

VS Code 스타일 3-panel 레이아웃을 사용한다. LeftSidebar는 파일 탐색기, MainViewArea는 분할뷰와 탭, RightSidebar는 AI 채팅 등 보조 도구다. MasterLayout이 패널 상태와 키보드 단축키를 관리한다.


## 환경 설정

### 환경변수

```bash
DATABASE_URL="postgresql://..."     # Drizzle ORM (Main Process)
VITE_SUPABASE_URL="https://..."     # Supabase URL (Renderer, VITE_ 접두사 필수)
VITE_SUPABASE_ANON_KEY="eyJ..."     # Supabase Anon Key (Renderer)
```

DATABASE_URL은 Main 프로세스에서 `process.env`로 접근한다. VITE_ 접두사가 붙은 변수는 Renderer에서 `import.meta.env`로 접근한다.

### Vite 설정

3개 설정 파일이 각 프로세스를 담당한다.

- `vite.main.config.ts`: Main Process (Node.js, CJS)
- `vite.preload.config.ts`: Preload (최소 코드, CJS)
- `vite.renderer.config.ts`: Renderer (React + Tailwind 플러그인, HMR)

Path Alias `@/`을 TypeScript, Vite, Vitest 세 곳 모두에 설정해야 작동한다.

### 주요 명령어

```bash
# 개발
npm start                    # Electron 개발 서버 (HMR)
npm run make                 # 프로덕션 빌드

# 테스트
npm test                     # Vitest 실행
npm run test:ui              # Vitest UI
npm run test:coverage        # 커버리지

# DB
npx drizzle-kit push         # 스키마 적용
npx drizzle-kit generate     # 마이그레이션 생성
npx drizzle-kit studio       # GUI

# 코드 품질
npm run lint                 # ESLint
```

### 초기 셋업

Electron Forge의 `vite-typescript` 템플릿으로 시작한다. React, Tailwind CSS, React Router, Supabase, Drizzle ORM, Shadcn UI를 순서대로 설정한다. Shadcn UI는 Electron-Vite 구조를 감지하지 못하므로 임시 `vite.config.ts`를 만들어 init 후 삭제하는 우회가 필요하다.


## Tauri 마이그레이션 전략

프론트엔드 코드의 80-90%는 Electron이나 Tauri나 동일하다. React 컴포넌트, Tailwind 스타일, 라우팅, Shadcn UI, 클라우드 백엔드(Supabase, OpenRouter, Elasticsearch) 모두 그대로 쓴다.

바뀌는 부분은 10-20%다. 로컬 파일 처리(Node.js fs -> Rust std::fs), 파일 감시(chokidar -> notify), 이미지 처리(Sharp -> image-rs), SQLite(better-sqlite3 -> sqlx), IPC(Electron IPC -> Tauri Command)만 재작성하면 된다. 총 8-12주 예상이다.

마이그레이션은 데이터 기반으로 결정한다. Phase 1(0-3개월)에서 Electron MVP로 시장 검증하고, Phase 2(3-6개월)에서 성능 지표를 측정한다. 성능 불만 30% 이상, 대량 파일 처리 요구 증가 등 조건이 2개 이상 만족하면 Phase 3(6-9개월)에서 Tauri로 전환한다.

환경 감지 어댑터로 두 런타임을 동시에 지원할 수 있다.

```typescript
const isTauri = window.__TAURI__ !== undefined;
export const backend = {
  async readFile(path: string) {
    return isTauri ? invoke('read_file', { path }) : electronAPI.readFile(path);
  }
};
```


## 기능 현황

### 구현 완료 (레이아웃 클론코딩)

- VSCode Tabs: 90%
- File Explorer: 92%
- Split View: 90%
- Chrome Tabs: 85%
- Monaco Editor: 50%

### PRD 7대 기능

정리(50%)와 메모(50%)는 기존 레이아웃을 활용해 진행 중이다. 수집, 창관리, 검색, AI 어시스턴트, 협업은 미시작(0%)이다.

수집은 크롬 확장프로그램 개발이 필요하다(2-3주). 검색은 로컬 SQLite FTS + Elasticsearch 연동이다(1-2주). AI는 OpenRouter 연동 + 채팅 UI다(1-2주). 협업은 Supabase Realtime 기반 실시간 동기화다(2-3주).


## 코드 규칙

반말을 쓴다. SOLID 원칙과 Clean Architecture를 준수한다. DRY 원칙으로 중복을 제거하고, YAGNI로 필요 없는 기능은 만들지 않는다. 함수명은 구현 방법이 아닌 목적을 표현한다. 매직 넘버 대신 상수를 사용한다.

모든 기능은 demos/에서 시작하고, 절대 경로(@/)를 사용하고, shared/components/ui/를 먼저 확인한다. 하드코딩 색상은 금지하고 테마를 사용한다. BDD 방식으로 테스트를 작성한다.
