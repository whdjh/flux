# Chrome 소스 매핑

Chrome의 C++ 구현을 TypeScript/React/Web Animations API로 매핑하는 방법.

## 개요

Chrome은 C++와 Chromium 플랫폼 API를 사용한다. 우리는 TypeScript, React, Web Animations API를 사용한다. 이 문서는 각 Chrome 기능을 어떻게 Web 기술로 매핑했는지 명시한다.

## 애니메이션 상수

| Chrome C++ | 우리 구현 | 근거 |
|-----------|---------|-----|
| `kDragAnimationMs = 167` | `CHROME_ANIMATION_CONSTANTS.kDragAnimationMs = 167` | 동일한 값 사용 |
| `kTabAnimationDurationMs = 200` | `CHROME_ANIMATION_CONSTANTS.kTabAnimationDurationMs = 200` | 동일한 값 사용 |
| `kCloseAnimationMs = 200` | `CHROME_ANIMATION_CONSTANTS.kCloseAnimationMs = 200` | 동일한 값 사용 |
| `kDragOpacity = 0.75` | `CHROME_ANIMATION_CONSTANTS.kDragOpacity = 0.75` | 동일한 값 사용 |
| `kEaseOut = cubic-bezier(0, 0, 0.2, 1)` | `CHROME_ANIMATION_CONSTANTS.kEaseOut = 'cubic-bezier(0, 0, 0.2, 1)'` | Material Design "Fast Out Slow In" |

**근거**: Chrome 팀이 사용자 테스트를 통해 최적화한 값. 변경하면 Chrome과 다른 느낌.

## 애니메이션 방식

### Bounds 애니메이션

| Chrome C++ | 우리 구현 | 근거 |
|-----------|---------|-----|
| `SetBounds(x, y, width, height)` | `element.animate([{flexGrow, minWidth}])` | Web에서 가변 너비 구현 |
| 직접 width/height 조작 | `flexGrow: 0 → 1` 애니메이션 | CSS Flexbox로 가변 너비 |
| Layout 재계산 기반 | Web Animations API | GPU 가속 자동 활용 |

**근거**:
- Chrome은 C++ 레벨에서 bounds를 직접 조작
- Web에서는 Flexbox로 가변 너비를 구현하는 게 자연스러움
- Web Animations API가 GPU 가속을 자동으로 활용
- `flexGrow: 0 → 1`이 Chrome의 "공간을 나눠가지는" 동작과 등가

### Opacity 미사용

| Chrome C++ | 우리 구현 | 근거 |
|-----------|---------|-----|
| Opacity 속성 사용 안 함 | Opacity 속성 사용 안 함 | **Chrome 방식 그대로** |
| Width 0으로 숨김 | `width: 0 !important`, `overflow: hidden` | 동일한 접근 |

**근거**:
- Chrome 소스 코드에 명시: "opacity나 scale 변환 없음"
- Opacity: 0을 쓰면 요소가 보이지 않지만 레이아웃 공간 차지
- Width: 0만 사용하면 공간을 완전히 차지하지 않음
- **이것이 간격이 생기지 않는 핵심**

### Animation Fill Mode

| Chrome C++ | 우리 구현 | 근거 |
|-----------|---------|-----|
| 애니메이션 후 최종 상태 유지 | 탭 추가: `fill: 'none'` | CSS 기본값으로 복귀 |
| | 탭 닫기: `fill: 'forwards'` | 제거 전까지 width: 0 유지 |

**근거**:
- 탭 추가: 애니메이션 후 `flex: 1`로 자연스럽게 전환
- 탭 닫기: DOM 제거 전까지 width: 0 유지 필요
- `fill: 'forwards'`가 inline style로 고정되면 React 리렌더 시 충돌 → `onfinish`에서 cleanup

## 드래그앤드롭 알고리즘

### Drop Index 계산

| Chrome C++ | 우리 구현 | 근거 |
|-----------|---------|-----|
| `GetInsertionIndexForDraggedBounds()` | `calculateDropIndex(mouseX)` | 동일한 알고리즘 |
| 모든 탭 위치 순회 | `for (let i = 0; i < tabElements.length; i++)` | 동일한 접근 |
| `CalculateIdealX()` - 이상적 x 좌표 | `rect.left + rect.width / 2` - 중심점 | 탭 중심 기반 |
| 거리 최소화 | 마우스 X < 탭 중심이면 그 위치 | 동일한 로직 |

**근거**:
- Chrome은 각 탭의 "ideal X"를 계산해서 거리 최소화
- Web에서는 `getBoundingClientRect()`로 실제 위치 측정
- 탭 중심점 기준이 가장 자연스러운 드롭 느낌

### Index 조정

| Chrome C++ | 우리 구현 | 근거 |
|-----------|---------|-----|
| `if (min_distance_index > first_dragged_tab_index)` | `if (calculatedIndex > draggedIndex)` | 동일한 조건 |
| `min_distance_index -= num_dragged_tabs` | `calculatedIndex -= 1` | 우리는 탭 1개만 드래그 |

**근거**:
- 드래그된 탭을 `splice()`로 제거하면 배열 인덱스 변경
- 오른쪽으로 이동 시 인덱스를 1 감소시켜야 올바른 위치
- Chrome은 여러 탭 드래그 가능 (`num_dragged_tabs`)
- 우리는 현재 1개만 (`-= 1`)

### Real-time Shifting

| Chrome C++ | 우리 구현 | 근거 |
|-----------|---------|-----|
| Layout 재계산으로 탭 이동 | `animateTabShift(tabId, element, shift)` | Web Animations API 사용 |
| 167ms 애니메이션 | `duration: kDragAnimationMs` (167ms) | 동일한 타이밍 |
| `transform: translateX()` | `transform: translateX(${shift}px)` | 동일한 CSS 속성 |

**근거**:
- Chrome은 layout 재계산 → 우리는 명시적으로 `translateX` 애니메이션
- GPU 가속을 위해 `transform` 사용 (width 대신)
- 167ms 타이밍으로 Chrome과 동일한 부드러움

## 탭 너비 관리

### 가변 너비 시스템

| Chrome C++ | 우리 구현 | 근거 |
|-----------|---------|-----|
| 탭들이 공간을 나눠가짐 | `.chrome-tab { flex: 1 }` | CSS Flexbox |
| `min-width`, `max-width` 제약 | `min-width: 36px`, `max-width: 240px` | 동일한 값 |
| Bounds 계산 후 설정 | Flex가 자동 계산 | Flexbox의 장점 활용 |

**근거**:
- Chrome은 C++에서 직접 너비 계산
- Web에서는 Flexbox가 자동으로 처리
- `flex: 1`이 "공간을 균등하게 나눔"을 자연스럽게 구현
- 최소/최대 너비 제약은 CSS로 간단히

## 이벤트 처리

### 드래그 이벤트

| Chrome C++ | 우리 구현 | 근거 |
|-----------|---------|-----|
| Windows 드래그 이벤트 | HTML5 Drag and Drop API | 표준 Web API |
| `OnDragStarted()` | `handleDragStart(e)` | 동일한 시점 |
| `OnDragMoved()` | `handleDragOver(e)` | 마우스 이동 추적 |
| `OnDragCompleted()` | `handleDrop(e)` | 드롭 완료 시점 |

**근거**:
- Chrome은 플랫폼별 드래그 API
- Web은 HTML5 Drag and Drop API가 표준
- 이벤트 시점과 데이터는 동일

### 탭 전환

| Chrome C++ | 우리 구현 | 근거 |
|-----------|---------|-----|
| `OnTabClicked()` | `handleTabClick(tabId)` | 클릭 이벤트 |
| Active 상태 관리 | `activeTabId` state | React state 관리 |
| 시각적 피드백 | `.chrome-tab.active` CSS | 동일한 스타일 |

## 상태 관리

### Chrome TabStrip

| Chrome C++ | 우리 구현 | 근거 |
|-----------|---------|-----|
| `std::vector<Tab*> tabs_` | `tabs: ChromeTab[]` state | React state |
| Observer 패턴 | React re-render | React의 반응형 |
| 직접 DOM 조작 | Virtual DOM | React가 최적화 |

**근거**:
- Chrome은 C++ 객체 배열
- React는 state로 관리 → 변경 시 자동 리렌더
- Virtual DOM이 최소한의 DOM 업데이트만 수행

## 렌더링 최적화

### GPU 가속

| Chrome C++ | 우리 구현 | 근거 |
|-----------|---------|-----|
| C++ 레벨 GPU 제어 | Web Animations API 자동 가속 | 브라우저가 최적화 |
| Composited Layer | `transform`, `opacity` 애니메이션 | Compositing 트리거 |
| 직접 GPU 명령 | 브라우저 렌더링 엔진 | 추상화 레벨 차이 |

**근거**:
- Chrome은 C++에서 GPU를 직접 제어
- Web은 브라우저 렌더링 엔진에 위임
- `transform` 속성은 자동으로 GPU 가속
- Web Animations API가 최적화된 경로 사용

## 허용되는 차이

이런 차이는 허용 가능:

1. **구현 언어**: C++ vs TypeScript
2. **플랫폼 API**: Windows API vs Web API
3. **상태 관리**: Observer 패턴 vs React state
4. **렌더링**: 직접 DOM 조작 vs Virtual DOM
5. **가변 너비**: 직접 계산 vs Flexbox

**이유**: 플랫폼 차이. 중요한 건 **사용자가 보는 동작이 동일**한 것.

## 허용되지 않는 차이

이런 차이는 절대 안 됨:

1. **타이밍 변경**: 167ms → 150ms (❌)
2. **Opacity 추가**: Chrome은 안 쓰는데 우리만 씀 (❌)
3. **알고리즘 변경**: 탭 중심 → 탭 좌측 기준 (❌)
4. **인덱스 조정 누락**: `calculatedIndex -= 1` 안 함 (❌)
5. **시각적 차이**: 간격, 속도감, 느낌 다름 (❌)

**이유**: 사용자 경험이 Chrome과 달라짐.
