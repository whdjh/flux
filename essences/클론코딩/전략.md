# 클론 코딩 전략

원본 소스를 보고 동일하게 구현하는 방법.

## 클론 코딩이란

원본 소스 코드를 참조해서 동일하게 구현.

## 워크플로우

### 링크 정리

클론 코딩할 기능의 원본 소스 링크를 모아둔다. 파일명과 GitHub URL만 기록한다.

```markdown
# 소스-링크.md

tab_strip.cc
https://github.com/.../tab_strip.cc

tab_drag_controller.cc
https://github.com/.../tab_drag_controller.cc
```

달랑 원칙대로 링크만 넣는다.

### 코드 가져오기

구현을 시작할 때 원본 소스를 실제로 가져온다.

**Firecrawl MCP 사용**
```bash
# 최초 1회 설정
claude mcp add firecrawl -e FIRECRAWL_API_KEY=your-key -- npx -y firecrawl-mcp
```

WebFetch나 curl로 GitHub 접근이 막힐 때 Firecrawl을 쓴다. GitHub UI나 접근 제한을 우회해서 소스를 가져올 수 있다.

가져온 코드는 별도 파일로 저장하거나 JSDoc 주석에 붙인다.

### 매핑하며 구현

원본 코드를 보면서 구현한다. 1:1 매핑을 시도한다. 매핑이 되면 체크 표시한다. 안 되면 왜 안 되는지 기록하고 대안을 찾는다.

```typescript
/**
 * 원본: OriginalClass::OriginalMethod()
 * Source: file.cc#L123
 *
 * 매핑:
 * ✅ FunctionA() → functionA()
 * ✅ CONSTANT_X → CONSTANT_X
 * ❌ NativeAPI() → 직접 매핑 불가
 *    대안: WebAPI() 사용
 *    이유: 플랫폼 차이
 */
function implementedMethod() {
  // 구현
}
```

주석에 매핑 결과를 기록한다. 코드가 스스로 문서가 된다.

### 의존성 따라가기

막히면 관련 파일을 찾아서 또 가져온다. 이해될 때까지 링크를 따라간다.

```
구현 중 막힘
→ 의존하는 클래스 발견
→ 그 파일 링크 찾기
→ 코드 가져오기
→ 반복
```

### 완성도 검증

구현이 끝나면 원본과 비교해서 빠진 부분을 찾는다. grep으로 원본 메서드를 추출하고 현재 구현과 대조한다.

```bash
# 원본 메서드 추출
grep -E "(protected|private|public)" 원본파일.ts

# 하나씩 체크
# ✅ 완전 구현
# ⚠️ 단순화 (이유 기록)
# ❌ 미구현 (다음 단계)
```

체크하다 보면 단순화한 부분이나 빠뜨린 기능을 발견할 수 있다. 발견하면 우선순위를 정해서 다음 Phase에 넣는다.

## 핵심

원본 코드를 복사해올 수 있으면 복사해온다. 복사한 코드를 보면서 1:1 매핑을 시도한다. 안 되면 기록하고 대안을 찾는다.

시행착오를 줄이는 방법은 원본을 계속 참조하는 것이다.
