# 클론코딩 에센스

프로젝트 개요는 비전.md, 기술 스택은 스택.md, 아키텍처는 아키텍처.md를 참조한다. 이 파일은 클론코딩 기록만 담는다.

리서치도구(Flux) 프로젝트의 핵심 UI 기능을 VSCode, Chrome 등의 원본 소스를 참조해 1:1로 클론코딩한 기록이다.


## 클론코딩 전략

원본 소스를 보고 동일하게 구현하는 방법이다.

먼저 원본 소스 링크를 모은다. 파일명과 GitHub URL만 기록한다. 구현을 시작할 때 원본 소스를 실제로 가져온다. WebFetch나 curl로 GitHub 접근이 막힐 때 Firecrawl MCP를 쓴다.

가져온 코드를 보면서 1:1 매핑을 시도한다. 매핑이 되면 체크 표시한다. 안 되면 왜 안 되는지 기록하고 대안을 찾는다. JSDoc 주석에 원본 파일명과 라인 번호를 기록한다. 막히면 의존하는 파일을 찾아서 또 가져온다. 이해될 때까지 반복한다.

구현이 끝나면 원본과 비교해서 빠진 부분을 찾는다. 원본 메서드를 추출하고 현재 구현과 대조해서 완전 구현, 단순화, 미구현으로 분류한다.

핵심은 시행착오를 줄이는 것이다. 원본을 계속 참조하면 된다.


## Chrome Tabs

Chromium 탭 시스템의 C++ 구현을 Web Animations API로 재현했다. 구현 현황 98%, 시각 테스트 미완료.

### 아키텍처

Chromium의 핵심 컴포넌트는 세 가지다. TabStripAnimator가 모든 애니메이션을 관리한다. TabDragController가 드래그 이벤트를 처리한다. Tab 클래스가 개별 탭을 렌더링한다. Chrome은 Bounds 애니메이션(width/height 직접 변경)을 사용하고, opacity나 scale transform은 사용하지 않는다.

우리 구현 파일:
- ChromeTabsDemo.tsx: 데모 페이지
- ChromeTabs.tsx: tab_strip.cc, tab.cc 매핑
- chrome-tab-animator.ts: tab_strip_animator.cc 매핑
- chrome-tabs.css: tab_style_views.cc 매핑

### 애니메이션 상수

Chromium 값을 그대로 사용한다. kDragAnimationMs = 167(드래그 중 이동), kTabAnimationDurationMs = 200(탭 추가), kCloseAnimationMs = 200(탭 닫기), kDragOpacity = 0.75(드래그 투명도), easing은 cubic-bezier(0, 0, 0.2, 1)(Material Design "Fast Out Slow In")이다. 이 값들은 Chrome 팀이 사용자 테스트로 최적화한 것이다.

### 핵심 구현

Web Animations API로 Chrome의 bounds 애니메이션을 재현한다. 탭 추가/닫기에서 opacity를 절대 사용하지 않는다. Chrome도 opacity를 전혀 안 쓴다. Opacity: 0을 쓰면 요소가 안 보여도 flex layout에서 공간을 차지해서 간격이 생긴다. Width: 0만 사용하면 공간을 완전히 차지하지 않아서 간격이 없다.

Flex-grow 방식을 사용한다. Chrome은 탭들이 공간을 나눠가진다. 고정 픽셀 너비 대신 flexGrow를 애니메이션해서 가변 너비를 구현한다. 탭 너비는 min 36px, max 240px다.

드롭 인덱스 계산은 Chrome 알고리즘을 재현한다. 탭 중심점 기반으로 계산하고, 드래그된 탭이 제거될 것을 고려해서 인덱스를 조정한다(`if (calculatedIndex > draggedIndex) calculatedIndex -= 1`). 이 인덱스 조정이 Chrome의 자연스러운 드래그 느낌의 핵심이다.

실시간 shifting은 useEffect로 구현한다. dropIndex가 변경될 때마다 모든 탭의 위치를 167ms 애니메이션으로 업데이트한다. 탭 너비는 getBoundingClientRect()로 실시간 측정한다. 가변 너비이므로 하드코딩하지 않는다.

Animation 객체는 Map으로 추적한다. 새 애니메이션 시작 시 이전 것을 cancel()로 즉시 중단한다. fill: 'forwards' + onfinish 콜백으로 애니메이션 후 inline style로 고정한다.

### 완료된 기능

Phase 2에서 NewTabButton(28x28px, hover/active 효과), Phase 3에서 탭 스크롤(좌우 스크롤 버튼, 휠 스크롤), Phase 4에서 탭 그룹(8가지 색상, 그룹 헤더, 접기/펼치기, CRUD)을 구현했다.

### 허용되는 차이 vs 허용 안 되는 차이

허용되는 차이: 구현 언어(C++ vs TypeScript), 플랫폼 API(Windows API vs Web API), 상태 관리(Observer 패턴 vs React state), 가변 너비(직접 계산 vs Flexbox), GPU 가속(직접 제어 vs 브라우저 자동). 판단 기준은 사용자가 Chrome과 구별할 수 없으면 허용이다.

허용 안 되는 차이: 타이밍 변경(167ms, 200ms 값 반드시 동일), Opacity 사용, 알고리즘 변경, 인덱스 조정 누락, 시각적 차이.

### 미구현

탭 미리보기(tab_hover_card_bubble_view.cc, P3), 여러 탭 동시 드래그, 고정 탭, 탭을 새 창으로 분리.

### 검증 방법

4가지 방법을 사용한다. 코드 리뷰로 상수와 알고리즘을 확인한다. Chrome과 나란히 놓고 시각적으로 비교한다. DevTools Performance로 타이밍을 측정한다. 실제 사용해서 동작을 확인한다.


## VSCode Tabs

VS Code 탭 시스템(editorTabsControl.ts 518줄, multiEditorTabsControl.ts)을 React + Zustand로 재현했다. 49개 기능 중 49개 구현(100%).

### 아키텍처

3개 계층으로 나뉜다. Core 계층은 순수 로직(상태 관리, 드래그 처리, 분할 알고리즘), Integration 계층은 React 통합(컴포넌트, 훅), IPC 계층은 멀티 윈도우 통신이다.

핵심 설계 결정:
- 좌표계: 다중 창에서 글로벌 화면 좌표계 사용(`globalX = clientX + window.screenX`)
- 상태 관리: Zustand 선택(Redux는 boilerplate 과다, Context API는 리렌더링 문제)
- 드래그앤드롭: 네이티브 HTML5 Drag and Drop API만 사용(라이브러리 없음)
- 분할 알고리즘: 드래그 위치에 따라 30% threshold로 상하좌우/center 방향 결정
- IPC: Main Process를 중계자로 사용하는 Auxiliary Window 패턴
- 성능: React.memo, useMemo, CSS transform, 드래그 피드백 30ms 디바운싱

### 매핑 패턴

VSCode와 React 간 변환 패턴: constructor → useState/useRef, getter/setter → useMemo/useCallback, create() → useEffect, dispose() → useEffect cleanup, updateOptions() → props 변경 시 자동 재렌더링, DI 서비스(9개) → Custom hooks, EventEmitter → React state + callbacks.

### 구현 파일

- EditorTabsControl.tsx: editorTabsControl.ts + multiEditorTabsControl.ts 매핑
- EditorActionsToolbar.tsx: editorTitleControl.ts 매핑
- EditorBreadcrumbs.tsx: breadcrumbs.ts 매핑
- tabsStore.ts: Zustand 상태 관리
- contextMenuService.ts, keybindingService.ts: 서비스 레이어
- useAuxiliaryWindowReceiver.ts: auxiliaryWindowService.ts 매핑
- useContextKey.tsx: contextkey.ts 매핑 (10개 Context Key)
- dnd.ts: 드래그앤드롭 유틸리티
- editor-tabs-control.css: 359줄, VSCode 4개 CSS 파일(308줄) 통합

### 주요 기능

탭 렌더링(멀티/싱글), 드래그앤드롭(순서 변경, 새 창 열기), 컨텍스트 메뉴, 닫기/고정/Sticky 탭, 경로 축약(shorten), 보조 창 분리(Alt+드래그), 키보드 단축키, 탭 래핑(여러 줄), 스크롤 버튼, 브레드크럼 네비게이션, 다중 선택(Ctrl/Shift Click).

### CSS 매핑

CSS 변수로 기본 색상을 정의한다(VSCode는 테마 시스템 사용). z-index hierarchy는 VSCode와 동일하게 구현했다: 0(tab base), 6(active/dirty border-top), 8(sticky-tab), 10(active border-bottom), 11(drag overlay/dnd border), 12(actions).

Sizing 모드 3가지(fit/fixed/shrink)를 완전 구현했다. position: sticky도 실제 동작한다. Tab label gradient fade(5px)를 추가했다. 닫기 버튼은 VSCode가 display: none→initial을 쓰는 반면, 우리는 opacity: 0→1로 부드러운 전환을 구현했다.

### 새 창(Auxiliary Window) IPC

탭을 윈도우 밖으로 드래그하면 새 BrowserWindow를 생성하는 기능이다. 흐름: 사용자 Alt+드래그 → maybeCreateAuxiliaryEditorPartAt() → IPC로 Main Process에 창 생성 요청 → BrowserWindow 생성 + 화면 경계 검사 → 앱 로드 → IPC_EDITOR.RECEIVE_EDITOR_DATA 전송 → 새 창에서 useAuxiliaryEditorData hook이 수신 → 탭 자동 생성 → 원본 창에서 탭 닫기. 9개 자동화 테스트 통과.

### 미구현

싱글 탭 모드(singleEditorTabsControl.ts, P3), 탭 없음 모드(noEditorTabsControl.ts, P3).
