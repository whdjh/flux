# 스킬 가이드

설치된 스킬 빠른 참조. 바로 쓸 수 있게 핵심만 담았다.

## 개발/기술

webapp-testing으로 Playwright 테스트를 돌린다. 서버 관리 스크립트(`with_server.py`)가 서버를 자동으로 시작/종료한다. 핵심은 정찰 후 행동 패턴이다. networkidle을 기다린 후 DOM을 검사하고 액션을 실행한다.

```python
# 기본 패턴
page.goto('http://localhost:5173')
page.wait_for_load_state('networkidle')  # 필수!
page.screenshot(path='inspect.png')      # DOM 검사
page.locator('button').click()           # 액션 실행
```

mcp-builder가 MCP 서버 개발을 돕는다. 4단계를 따른다: 리서치(API 문서 완독) → 구현(공통 유틸부터) → 리뷰(품질 체크리스트) → 평가(10개 질문). 에이전트 중심 설계가 핵심이다. API 래핑이 아니라 워크플로우 툴을 만든다. 에러 메시지는 다음 단계를 제안한다.

시작은 간단하다. WebFetch로 MCP 프로토콜 문서(`https://modelcontextprotocol.io/llms-full.txt`)를 읽고, Python이면 FastMCP, TypeScript면 MCP SDK를 쓴다.

frontend-design로 독창적인 UI를 만든다. AI 느낌을 피한다: 중앙 정렬 남용, 보라 그라데이션, 균일한 둥근 모서리, Inter 폰트. 대신 프로덕션급 인터페이스를 만든다.

## 창작/디자인

algorithmic-art로 p5.js 생성 예술을 만든다. 2단계다. 먼저 알고리즘 철학을 작성한다. "Organic Turbulence: 자연 법칙에 제약된 혼돈. 플로우 필드, 파티클, 다층 노이즈로 밀도 맵 생성." 같은 식으로 4-6문단. 그 다음 p5.js로 표현한다. 시드 랜덤성으로 재현 가능한 변형을 만들고 시드 네비게이션으로 탐색한다.

canvas-design로 PNG/PDF 비주얼 아트를 만든다. algorithmic-art와 비슷하게 디자인 철학을 먼저 정의한다("Brutalist Joy", "Chromatic Silence"). 90% 비주얼, 10% 텍스트로 구성한다.

theme-factory로 아티팩트에 테마를 입힌다. 10개 프리셋이 있다: Ocean Depths, Sunset Boulevard, Forest Canopy, Modern Minimalist, Golden Hour, Arctic Frost, Desert Rose, Tech Innovation, Botanical Garden, Midnight Galaxy. `theme-showcase.pdf`로 미리 보고 선택한다. 커스텀 테마도 만들 수 있다.

brand-guidelines로 Anthropic 브랜드를 적용한다. Dark(#141413), Light(#faf9f5), Orange(#d97757), Blue(#6a9bcc), Green(#788c5d). 헤딩은 Poppins, 본문은 Lora. 24pt 이상이면 자동으로 헤딩 폰트 적용.

## 커뮤니케이션

internal-comms로 내부 문서를 작성한다. 3P 업데이트, 뉴스레터, FAQ, 상태 보고서, 인시던트 보고서를 지원한다. 커뮤니케이션 타입을 식별하면 `examples/` 디렉토리에서 가이드라인을 로드한다. 3P 업데이트는 `examples/3p-updates.md`, 뉴스레터는 `examples/company-newsletter.md`를 쓴다.

## 문서 작업

document-skills로 Office 문서를 다룬다. 이미 설치되어 있다.

xlsx로 스프레드시트를 다룬다. 수식 계산하고 조건부 서식 적용하고 피벗 테이블로 분석한다. docx로 워드 문서를 편집한다. 변경 추적하면서 댓글 달고 스타일 통일한다. pptx로 프레젠테이션을 만든다. 마스터 슬라이드 쓰고 레이아웃 잡고 차트 넣는다. pdf는 다기능이다. 텍스트/테이블 추출하고 페이지 병합/분할하고 폼 필드 읽고 쓴다.

## 메타

skill-creator로 커스텀 스킬을 만든다. 구조는 간단하다.

```
skill-name/
├── SKILL.md (필수)
│   ├── name: skill-name
│   ├── description: 언제 쓸지 명확히
│   └── 마크다운 지침
└── 리소스 (선택)
    ├── scripts/     실행 코드
    ├── references/  문서
    └── assets/      파일
```

description이 자동 활성화를 결정한다. "This skill should be used when..."처럼 3인칭으로 쓴다.

## 사용법

명시적으로 언급하는 게 확실하다. "Use the webapp-testing skill to test login flow"처럼 스킬 이름을 직접 쓴다. "Use the theme-factory skill to apply Ocean Depths theme"도 명확하다.

익숙해지면 암묵적으로도 된다. "Playwright로 E2E 테스트 작성해줘"라고 하면 webapp-testing이 활성화된다. "프레젠테이션에 테마 적용해줘"는 theme-factory를 부른다. "Excel 파일에서 데이터 추출해줘"는 document-skills의 xlsx를 쓴다. description이 요청과 매칭되면 자동으로 활성화되는 거다.

처음엔 명시하는 게 안전하다. 특히 비슷한 스킬이 여러 개일 때.
