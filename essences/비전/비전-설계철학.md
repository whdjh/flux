# 디자인 철학

← [문서 네비게이션](../00-시작/00-시작하기.md)

## 핵심 철학

> "최고의 인터페이스는 인터페이스가 없는 것이다. 그 다음은 이미 아는 인터페이스다."

창의성은 도구가 생각의 보이지 않는 연장선이 될 때 가장 잘 흐른다고 믿습니다.

## 기본 원칙

### 1. 인지 부하 최소화

#### 새로운 인터페이스의 문제점

모든 새로운 패턴은 다음을 요구합니다:
- 작업 기억 할당
- 패턴 학습 시간
- 오류와 복구 사이클
- 인지 전환 비용

#### 우리의 접근법: 기존 멘탈 모델 활용

```
사용자의 생각: "파일을 정리해야 해"
기존 앱: "우리만의 독특한 정리 시스템을 배워보세요!"
우리 앱: "어디서나 쓰던 폴더를 그대로 사용하세요."
```

**결과**: 기본 작업에 대한 인지 부담 제로

### 2. 몰입 상태 유지

#### 몰입 공식

```
몰입 상태 = (도전 - 기술) + 명확한 목표 + 즉각적 피드백
            ________________________________________________
                        최소한의 마찰
```

#### 몰입을 위한 디자인 결정

- **모달 다이얼로그 없음**: 모든 것은 인라인 또는 비차단 방식
- **예측 가능한 애니메이션**: 200ms 일관성
- **키보드 우선**: 손은 키보드에 그대로
- **조용한 작업**: 불필요한 확인 없음
- **모든 것을 자동 저장**: 수동 저장에 대한 걱정 없음

### 3. 점진적 복잡성

#### 양파 모델

```
Layer 1 (표면): 기본 작업
  - 드래그 앤 드롭
  - 클릭하여 열기
  - 간단한 정리

Layer 2 (발견 가능): 강력한 기능
  - 키보드 단축키
  - 분할 뷰
  - 일괄 작업

Layer 3 (고급): 프로 도구
  - 사용자 정의 워크플로우
  - API 접근
  - 자동화
```

**원칙**: 각 레이어는 그 자체로 완전하고 유용합니다

### 4. 시각적 정보 계층

#### F-패턴 현실

사용자는 F-패턴으로 인터페이스를 스캔합니다:

```
━━━━━━━━━━━━━━━  (1차 스캔)
━━━━━━━━━
━━━━━━           (2차 스캔)
━━━━
━━               (3차 스캔)
```

**우리의 레이아웃 대응**:
- 왼쪽 패널: 탐색 (주요)
- 중앙: 콘텐츠 (집중)
- 오른쪽 패널: 도구 (보조)

### 5. 즉각적인 피드백

#### 100ms 규칙

```
0-100ms:    즉시 (피드백 불필요)
100-300ms:  빠름 (미묘한 피드백)
300-1000ms: 로딩 중 (명확한 피드백)
1000ms+:    느림 (진행 표시기)
```

**구현**:
- 수집: < 100ms (즉시 느껴짐)
- 검색: < 100ms (즉각적인 결과)
- 애니메이션: 200ms (부드럽지만 추적 가능)
- 파일 작업: 1초 이상 시 진행 표시

## 미학 철학

### 형태는 기능을 따른다... 그리고 다듬어진다

#### 1단계: 기능적
완벽하게 작동하게 만들기

#### 2단계: 사용 가능
직관적으로 만들기

#### 3단계: 아름다움
즐겁게 만들기

**우리는 절대 단계를 건너뛰지 않습니다**

### 시각적 원칙

#### 대비를 통한 명확성

```
높은 대비:  중요한 동작
중간 대비:  일반 콘텐츠
낮은 대비:  보조 정보
```

#### 일관성이 신뢰를 만든다

- 같은 동작 = 같은 위치
- 같은 의미 = 같은 색상
- 같은 중요도 = 같은 크기

#### 의미 있는 움직임

모든 애니메이션은 반드시:
1. 정보를 전달
2. 맥락을 유지
3. 자연스럽게 느껴짐
4. 성능을 고려

## 아키텍처 철학

### 로컬 우선, 클라우드 보강

#### 왜 로컬 우선인가?

```
로컬:
✓ 즉시 (0ms 지연)
✓ 비공개 (당신의 데이터)
✓ 신뢰성 (항상 작동)
✓ 빠름 (네트워크 불필요)

클라우드:
+ 동기화 (여러 기기)
+ 백업 (안전성)
+ 협업 (팀)
+ AI (향상된 기능)
```

**철학**: 핵심 기능은 절대 네트워크에 의존하지 않습니다

### 데이터 소유권

#### 당신의 데이터는 당신의 것

- 표준 형식 (마크다운, JSON)
- 모든 것을 내보내기 가능
- 독점적 잠금 없음
- 로컬 저장소 기본

### 기능으로서의 성능

#### 성능 예산

```
애니메이션:   60fps (프레임당 16ms)
상호작용:     <100ms 응답
검색:         <100ms 결과
로드:         <1s 전체 앱
```

**트레이드오프**: 성능보다 기능을 희생합니다

## 상호작용 철학

### 직접 조작

#### 보고, 만지고, 움직이기

- 파일을 드래그하여 정리
- 패널 직접 크기 조정
- 모든 곳에서 인라인 편집
- 즉각적인 시각적 피드백

### 모드 없는 디자인

#### 모드 없음 = 혼란 없음

```
나쁨:  "편집 모드" 클릭 → 편집 → "저장" 클릭
좋음:  텍스트 클릭 → 편집 → 자동 저장
```

**원칙**: 인터페이스는 항상 모든 동작에 준비되어 있어야 합니다

### 되돌릴 수 있음

#### 모든 동작은 취소 가능

- 실행 취소/다시 실행 스택
- 삭제 전 휴지통
- 버전 기록
- 비파괴적 편집

**결과**: 사용자는 두려움 없이 탐험합니다

## 멘탈 모델 정렬

### 파일 시스템 은유

#### 왜 작동하는가

```
물리적 세계:     디지털 세계:      우리 앱:
서류함        → 컴퓨터 파일    → 정보
├── 폴더       → ├── 디렉토리    → ├── 카테고리
└── 문서       → └── 파일        → └── 콘텐츠
```

**보편적 이해**: 40년 이상의 컴퓨팅이 모든 사람을 훈련시켰습니다

### 브라우저 은유

#### 탭 = 다중 컨텍스트

```
브라우저:          우리 앱:
여러 페이지      → 여러 항목
탭 전환         → 컨텍스트 전환
북마크          → 컬렉션
기록           → 타임라인
```

브라우저 탭은 보편적으로 사용되는 패턴이다.

## 진화 철학

### 표준으로 시작, 가장자리에서 혁신

#### 혁신 그라데이션

```
Core (익숙함) ←────────────→ Edges (새로움)
파일 트리                        AI 분류
탭                            의미 검색
드래그 앤 드롭                    스마트 제안
```

**원칙**: 혁신은 익숙한 패턴을 대체하지 않고 향상시켜야 합니다

### 사용자 중심 개발

#### 듣고, 배우고, 만들기

1. 사용자가 X로 어려움을 겪음
2. X가 왜 어려운지 이해
3. 증상이 아닌 근본 원인 해결
4. 실제 사용자와 테스트
5. 행동 기반 반복

### 지속 가능한 복잡성

#### 복잡성 예산

복잡한 기능이 추가될 때마다:
- 두 가지가 더 간단해져야 함
- 또는 한 가지를 제거해야 함

**결과**: 앱은 더 강력해지지만 더 복잡해지지 않습니다

## 디자인 결정 프레임워크

### 디자인 선택 시 질문:

1. **익숙한가?**
   - 기존 멘탈 모델을 사용하는가?
   - 플랫폼 규칙을 따르는가?

2. **필요한가?**
   - 실제 사용자 문제를 해결하는가?
   - 더 간단한 해결책이 없는가?

3. **빠른가?**
   - 성능 예산을 충족하는가?
   - 즉각적으로 느껴지는가?

4. **학습 가능한가?**
   - 사용하면서 발견 가능한가?
   - 점진적 공개를 따르는가?

5. **되돌릴 수 있는가?**
   - 사용자가 취소할 수 있는가?
   - 비파괴적인가?

하나라도 "아니오"라면 디자인을 재고려하세요
