  VSCode의 코드의 필요한 부분을 그대로 가져와 사용하는게 최적화도, UI, UX도 좋을 것 같으니
  그렇게 방향성을 잡고도 있어.
  이미 만들어진 파일들과 폴더들과 코드들에서

  Chrome 탭 시스템 또한 마찬가지야.

드래그 시스템

탭 이동 애니메이션이 패널 드롭 존과 겹침

VS Code의 검증된 분할 로직에 Chrome의 부드러운 애니메이션만 추가하면 돼

탭 순서 변경 Chrome 애니메이션이었다가 탭 영역을 벗어나면 똑 떼져서 VSCode 가 가진 탭 분할 코드의 형태가 되는거지.
 1. 탭바 내부 (isDetached=false): Chrome 스타일로 탭들이 좌우로 슬라이딩하면서 재정렬
  2. 탭바 외부 (isDetached=true): VS Code 스타일로 드롭존이 나타나고 패널 분할 가능

https://chromium.googlesource.com/chromium/src/+/2accab56152b3890473024585376ab231268c015/chrome/browser/ui/views/tabs/tab_drag_controller.cc

아키텍쳐를 설계할 때 나뭇가지 노드와 리프 노드를 설계했었잖아.
지금 나뭇가지를 뻗어야 했는데, 리프만 너무 만들었나봐. 통제, 제어가 안되는 느낌이네.
그러니 지금의 방향성은 효율과 효용성을 높이기 위해 리팩토링의 필요성이 느껴져.
폴더 구조를 추가해야 하는거지. 파일 시스템, 탭 시스템, 분할 시스템 때문에.
폴더 구조를 어떻게 설계할까?

 ★ Insight ─────────────────────────────────────
  Chrome 로컬 드래그는 탭바 bounds로 정확히 감지하는데, HTML5 드래그는 50px 임계값을 쓰고 있어서
  일관성이 없어. 둘 다 탭바 bounds 기반으로 통일해야 해.
