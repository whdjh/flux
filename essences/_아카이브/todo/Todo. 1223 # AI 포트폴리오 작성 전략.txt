# AI 포트폴리오 작성 전략

포트폴리오는 수학이다. 한 가지만 틀려도 전체 신뢰도가 무너진다. 평가자는 1분에 3장을 넘긴다. 이해가 안 되는 순간 흐름이 끊긴다.

**자소서 작성은 [자소서-작성-전략.md](./자소서-작성-전략.md) 참고**

---

## 뉘앙스 원칙

객관적 동사는 제3자 시점처럼 들린다. 주관적 동사로 바꿔야 진솔하게 들린다.

**변환표**:
- 체험했다, 경험했다 → 느꼈다, 알게 되었다, 배웠다
- 입증했다, 증명했다 → 사실만 진술 (동사 제거)
- 완수했다, 달성했다 → 마쳤다, 끝냈다, 완료
- 성공시켰다 → 마쳤다, 했다
- 향상시켰다 → 키웠다, 향상됐다

예시:
```
나쁜 예: React를 2일 학습하고 프로덕션 개발을 해낸 빠른 학습 능력을 입증했다.
좋은 예: React를 2일 학습하고 프로덕션 개발을 해냈다.
```

사실만 진술하면 더 강력하다. 평가자가 직접 판단하게 한다.

## AI-스럽지-않게-쓰기

AI 글은 패턴이 있다. 평가자가 눈치채면 신뢰가 떨어진다.

**8가지 금지 패턴**:
1. 과장 수식어: "뛰어난", "탁월한", "혁신적인"
2. 클리셰: "새로운 장을 열었다", "패러다임 전환"
3. 추상 표현: "시너지 효과", "범용적 솔루션"
4. 완벽주의: "완벽하게", "완전히", "최고의"
5. 감정 과잉: "매우 흥분했다", "엄청나게 기뻤다"
6. 제3자 시점: "그는", "이 개발자는"
7. AI-like 동사: "완수했다", "달성했다", "입증했다"
8. 개인 프로젝트명: ft_transcendence, 스냅노트, minishell

**개인 프로젝트명이 특히 위험한 이유**:
평가자는 "ft_transcendence가 뭐지?"라고 생각한다. 흐름이 끊긴다.

```
나쁜 예: ft_transcendence 프로젝트에서 트라우마를 겪었다.
좋은 예: 42Seoul의 마지막 과제에서 트라우마를 겪었다.
```

## 수학적 정확성

**검증 체크리스트**:
- [ ] 날짜 정확 (GPT-3.5 출시일: 2023.01)
- [ ] 숫자 정확 (프로젝트 기간, 금액, 인원)
- [ ] 사실 정확 (회사명, 기술명, 직책)
- [ ] 시간 순서 (A 이후 B)
- [ ] 인과관계 (A 때문에 B)

## Writing Style

서술형 중심으로 자연스럽게 흐른다.

**핵심**:
- 레이블 제거 ("핵심:", "왜:", "결과:" 쓰지 않기)
- 반말 사용 (~한다, ~이다)
- 연결어 활용 (이렇게 하면, 그래야, 때문이다)
- 2-3문장 문단

**리스트는 언제 쓰나**:
- 파일/항목 나열
- 단계별 명령어
- 체크리스트

설명은 서술형으로 쓴다.

## 달랑원칙

불필요한 것을 배제한다.

1. 핵심만: 불필요한 설명 제거
2. 단일 책임: 한 문서 = 한 목적
3. 빠른 참조: 스캔 가능하게
4. 한글 파일명: 명확하게
5. 실용성: 즉시 사용 가능하게
6. 범용성: 하드코딩된 경로 금지

## 작성 후 검토

**뉘앙스 원칙**:

**AI-스러움**:
- [ ] 과장 수식어 제거
- [ ] 클리셰 제거
- [ ] 개인 프로젝트명 제거

**서사**:
- [ ] 실패→성장 서사 있음
- [ ] 감정 표현 있음
- [ ] 구체적 디테일 있음

**정확성**:
- [ ] 날짜 정확
- [ ] 숫자 정확
- [ ] 사실 정확

**가독성**:
- [ ] 5초 안에 이해됨
- [ ] 혼란 요소 없음
