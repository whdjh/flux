# 프로젝트 폴더 구조 / Project Structure

## 전체 구조 개요

```
electron-boilerplate/
├── src/                    # 소스 코드 루트
│   ├── demos/             # 실험적 프로토타입
│   ├── features/          # 검증된 기능 모듈
│   ├── app/               # 코어 인프라
│   ├── shared/            # 공통 유틸리티
│   ├── main/              # Main Process (Node.js)
│   ├── backend/           # 백엔드 로직
│   ├── routes/            # 라우팅
│   ├── styles/            # 글로벌 스타일
│   ├── test/              # 테스트 유틸리티
│   ├── __tests__/         # 통합 테스트
│   ├── main.ts               # Main process 진입점
│   ├── preload.ts            # Preload script
│   ├── renderer.tsx          # Renderer 진입점
│   └── index.css             # 글로벌 CSS
├── public/                 # 정적 자산
├── docs/                   # ADR, BDD, 가이드
├── docs-overview/          # 프로젝트 개요 문서
├── research/               # 리서치 자료
├── package.json              # 프로젝트 설정
├── tsconfig.json             # TypeScript 설정
├── vite.*.config.ts          # Vite 설정
├── forge.config.ts           # Electron Forge 설정
└── drizzle.config.ts         # Drizzle ORM 설정
```

## 핵심 폴더 상세 설명

### 1. `src/demos/` - 실험 공간

새로운 아이디어를 빠르게 프로토타입하고 검증하는 공간이다.

**특징**:
- 빠른 실험 우선
- 코드 품질보다 속도
- 사용자 피드백 수집
- 실패해도 괜찮음

**구조**:
```
demos/
├── chrome-tabs/                    # Chrome 탭 애니메이션 데모
│   ├── ChromeTabsDemo.tsx
│   └── components/
├── vscode-tabs/                    # VS Code 탭 시스템 데모
│   ├── VSCodeTabsDemo.tsx
│   └── components/
├── file-explorer/                  # 파일 탐색기 데모
│   ├── FileExplorerDemo.tsx
│   └── components/
├── split-view/                     # Split View 데모
│   ├── VSCodeCloneSplitView.tsx
│   └── index.ts
├── integrated-vscode/              # 통합 VS Code 레이아웃
│   └── IntegratedVSCodeDemo.tsx
├── components/                     # 데모용 공통 컴포넌트
│   └── DemoHeader.tsx
└── DemoIndex.tsx                   # 데모 인덱스 페이지
```

**사용 시기**:
-  새로운 UI 패턴 테스트
-  써드파티 라이브러리 평가
-  사용자 경험 검증
-  성능 벤치마크

**이동 조건**:
-  사용자 피드백 긍정적
-  기술적 실현 가능성 확인
-  성능 요구사항 충족
→ `features/`로 이동

### 2. `src/features/` - 프로덕션 기능

검증되고 안정적인 프로덕션 레벨 기능 모듈을 담는다.

**특징**:
- 높은 코드 품질
- 완전한 테스트 커버리지
- 문서화 완료
- 유지보수 가능

**구조** (예상):
```
features/
├── editor/                         # 에디터 기능
│   ├── components/
│   │   ├── Editor.tsx
│   │   ├── EditorToolbar.tsx
│   │   └── EditorStatusBar.tsx
│   ├── hooks/
│   │   ├── useEditor.ts
│   │   └── useEditorState.ts
│   ├── types/
│   │   └── editor.types.ts
│   ├── utils/
│   │   └── editor-utils.ts
│   └── index.ts
├── file-explorer/                  # 파일 탐색기
│   ├── components/
│   ├── hooks/
│   ├── types/
│   └── index.ts
└── workspace/                      # 워크스페이스 관리
    ├── components/
    ├── hooks/
    └── index.ts
```

**품질 기준**:
-  Unit Tests (80%+ coverage)
-  Integration Tests
-  Type Safety
-  Error Handling
-  Documentation
-  Accessibility (WCAG AA)

```
│   │   ├── tabs.tsx
│   │   └── tooltip.tsx
│   └── layout/                    # 레이아웃 컴포넌트
├── hooks/                         # 커스텀 훅
│   ├── useTheme.ts
```

**구조**:

**책임**:

- 윈도우 생성/관리

## 개발 워크플로우

### 새 기능 개발 프로세스

```
1⃣ src/demos/new-feature/
   - 빠르게 프로토타입 작성
   - 사용자 피드백 수집
   - 기술 검증

2⃣ src/demos/new-feature/ (refine)
   - 피드백 반영
   - 코드 정리
   - 테스트 추가

3⃣ src/features/new-feature/
   - 프로덕션 품질 코드
   - 완전한 테스트
   - 문서화

4⃣ src/app/ (integration)
   - 메인 앱에 통합
   - 라우팅 추가
   - 최종 검증

5⃣ Production
   - 배포
   - 모니터링
```

```typescript
//  Good
import { Button } from '@/shared/components/ui/button'
import { useEditor } from '@/features/editor/hooks/useEditor'
import { FileExplorer } from '@/features/file-explorer'

//  Bad
import { Button } from '../../../shared/components/ui/button'
```

### Import 순서
```typescript
// 1. External dependencies
import React from 'react'
import { useNavigate } from 'react-router-dom'

// 2. Internal shared
import { Button } from '@/shared/components/ui/button'

// 4. Local
import { Header } from './Header'
```

## 폴더 선택 가이드

### 어디에 코드를 넣을까?

```
새로운 아이디어/실험
→ src/demos/

검증된 기능 모듈
→ src/features/

재사용 가능한 UI 컴포넌트
→ src/shared/components/ui/

재사용 가능한 비즈니스 로직
→ src/shared/hooks/ or src/shared/utils/

코어 인프라/통합
→ src/app/

Main process 로직
→ src/main/

데이터베이스/API
→ src/backend/

라우팅 설정
→ src/routes/
```

## 코드 찾기 팁

### 특정 기능 찾기
1. `src/features/` 먼저 확인
2. 없으면 `src/demos/` 확인
3. 공통 컴포넌트는 `src/shared/` 확인

### VS Code/Chrome 관련 코드
```
src/app/integrations/vscode/    # VS Code 통합
src/app/integrations/chrome/    # Chrome 통합
```

### UI 컴포넌트
```
src/shared/components/ui/       # Radix UI 기반 컴포넌트
```

### 데이터베이스
```
src/backend/db/schema/          # Drizzle 스키마
```

## 폴더 크기 가이드라인

| 폴더 | 파일 수 | 설명 |
|------|--------|------|
| `demos/` | 무제한 | 실험 공간, 자유롭게 추가 |
| `features/[feature]/` | 10-30 | 너무 크면 분할 고려 |
| `shared/components/ui/` | 20-50 | Radix UI 기반, 필요시 추가 |
| `app/` | 50-100 | 코어 인프라, 신중히 추가 |
