# 3-Layer Security Defense System

**완전한 보안 설계 문서**

---

## 시스템 개요

Electron의 IPC(Inter-Process Communication)는 renderer 프로세스가 main 프로세스의 powerful Node.js APIs에 접근할 수 있게 합니다. 이는 보안 위험이 높아, **3단계 독립 방어 시스템**을 구현했습니다.

### 설계 철학

**"Defense-in-Depth"** - 단일 실패점(Single Point of Failure) 제거

- 각 레이어는 독립적으로 작동
- 하나의 레이어가 우회되어도 다른 레이어가 보호
- 빠른 실패 (Fast Fail) 전략으로 성능 최적화

## Layer 상세 분석

### Layer 1: Zod Validation

**파일**: \`src/shared/validation/schemas.ts\`

**역할**: 타입 안전성 + 기본 패턴 차단

\`\`\`typescript
// Example Schema
const SinglePathSchema = z.object({
  path: z.string()
    .min(1, 'Path cannot be empty')
    .max(4096, 'Path exceeds maximum length')
    .refine(
      (path) => !PathValidator.hasDangerousPatterns(path),
      'Path contains dangerous patterns'
    ),
});
\`\`\`

**차단하는 공격**:
- Type confusion attacks
- Empty/null path injections
- Oversized payload attacks (10MB limit)
- Basic path traversal (\`../\` patterns)
- Invalid filename characters (\`<>:"|?*\`)

**테스트 코드**:
\`\`\`typescript
it('should validate input at Zod layer before PathValidator', async () => {
  const handler = createValidatedHandler(SinglePathSchema, async (_, input) => {
    serviceSpy(input.path);
    return true;
  });

  // Empty path should be caught by Zod
  await expect(handler(event, { path: '' })).rejects.toThrow();
  
  // Service should never be called
  expect(serviceSpy).not.toHaveBeenCalled();
});
\`\`\`

### Layer 2: Rate Limiting

**파일**: \`src/backend/infrastructure/middleware/IPCRateLimiter.ts\`

**역할**: DoS 공격 방어 + 리소스 보호

**알고리즘**: Sliding Window

\`\`\`typescript
class IPCRateLimiter {
  checkLimit(channel: string): boolean {
    const now = Date.now();
    const limit = this.getLimitForChannel(channel);

    // Clean up old timestamps outside window
    const cutoff = now - limit.window;
    record.timestamps = record.timestamps.filter(ts => ts > cutoff);

    // Check if limit exceeded
    if (record.timestamps.length >= limit.max) {
      return false; // Rate limit exceeded
    }

    // Record this request
    record.timestamps.push(now);
    return true;
  }
}
\`\`\`

**Rate Limit 설정 근거**:

| Channel | Max | Window | Rationale |
|---------|-----|--------|-----------|
| \`file:readFile\` | 20 | 1000ms | 읽기는 비교적 안전, 높은 한도 |
| \`file:writeFile\` | 10 | 1000ms | 쓰기는 위험, 낮은 한도 |
| \`file:deleteItem\` | 10 | 1000ms | 삭제는 복구 불가, 신중한 제한 |
| \`file:listDirectory\` | 50 | 1000ms | 목록 조회는 저비용, 높은 한도 |

**테스트 코드**:
\`\`\`typescript
it('should check rate limit independently of validation', async () => {
  const rateLimiter = getGlobalRateLimiter();
  rateLimiter.setLimit('test:operation', { max: 2, window: 1000 });

  // First two requests should succeed
  await expect(handler(event, { path: '/valid/path1' })).resolves.toBe('/valid/path1');
  await expect(handler(event, { path: '/valid/path2' })).resolves.toBe('/valid/path2');

  // Third request should be rate limited
  await expect(handler(event, { path: '/valid/path3' })).rejects.toThrow('Rate limit exceeded');
});
\`\`\`

### Layer 3: Path Validation

**파일**: \`src/shared/utils/pathValidation.ts\`

**역할**: 파일 시스템 접근 제어 (깊이 있는 방어)

**전략**: Whitelist-based access control

\`\`\`typescript
class PathValidator {
  isPathSafe(requestedPath: string): boolean {
    // 1. Normalize path
    const normalized = path.normalize(path.resolve(requestedPath));

    // 2. Check for path traversal
    if (normalized.includes('..')) {
      return false;
    }

    // 3. Verify within allowed base paths
    return Array.from(this.allowedBasePaths).some(basePath =>
      normalized.startsWith(basePath)
    );
  }
}
\`\`\`

**보안 메커니즘**:
1. **Path Normalization**: 상대 경로 → 절대 경로 변환
2. **Traversal Detection**: \`..\` 시퀀스 탐지
3. **Base Path Verification**: 허용된 디렉토리 내부 확인

**Example**:
\`\`\`typescript
// Allowed base paths
const allowedPaths = ['/home/user/documents', '/home/user/projects'];

// Valid paths
validator.validatePath('/home/user/documents/file.txt');        // 
validator.validatePath('/home/user/documents/subfolder/a.txt'); // 

// Invalid paths
validator.validatePath('/home/user/documents/../../../etc/passwd'); // 
validator.validatePath('/etc/passwd');                               // 
\`\`\`

## 설계 이점

### 1. Defense-in-Depth

각 레이어가 독립적으로 작동하므로 단일 실패점이 없습니다.

**시나리오: Layer 1 우회 시도**
\`\`\`
공격자: Zod validation 우회 방법 발견
  ↓
Layer 2: 여전히 rate limit 적용 (DoS 방지)
  ↓
Layer 3: 여전히 path validation 적용 (파일 시스템 보호)
  ↓
결과: 공격 실패
\`\`\`

### 2. Layer Isolation

각 레이어는 독립적으로 테스트 가능합니다.

### 3. Performance Optimization

레이어 순서가 성능에 최적화되어 있습니다:
- Layer 1 (가장 빠름) - Fast fail
- Layer 2 (빠름) - Quick check
- Layer 3 (보통) - Deep validation

### 4. Zero Trust Architecture

\`\`\`
"Trust nothing, verify everything"

- Renderer 프로세스는 잠재적으로 악의적이라고 가정
- 모든 입력은 기본적으로 불신
- 모든 요청은 3단계 검증 통과 필수
\`\`\`

## Week 3: CSP & Security Headers (Browser-Level Security)

### 목표

Week 1-2에서 **파일 시스템 보안**을 강화했다면, Week 3에서는 **브라우저 레벨 보안**을 추가하여 defense-in-depth를 완성합니다.

### 추가된 보안 레이어

#### Layer 4: Content Security Policy (CSP)

브라우저에서 실행 가능한 리소스를 제한한다.

**구현**: \`src/backend/infrastructure/security/csp.ts\`

**주요 디렉티브**:
\`\`\`typescript
// Development Mode (Vite HMR 지원)
{
  'default-src': ["'self'"],
  'script-src': ["'self'", "'unsafe-eval'"],  // Vite HMR
  'style-src': ["'self'", "'unsafe-inline'"], // Tailwind CSS
  'connect-src': ["'self'", 'ws://localhost:*', 'https://*.supabase.co'],
  'worker-src': ["'self'", 'blob:'],          // Monaco Editor
  'object-src': ["'none'"]
}

// Production Mode (Strict)
{
  'default-src': ["'self'"],
  'script-src': ["'self'"],                   // No unsafe-eval
  'style-src': ["'self'", "'unsafe-inline'"],
  'connect-src': ["'self'", 'https://*.supabase.co'],
  'worker-src': ["'self'", 'blob:'],
  'object-src': ["'none'"]
}
\`\`\`

**차단하는 공격**:
- XSS (Cross-Site Scripting) - 악성 스크립트 실행 차단
- Code Injection - 외부 스크립트 로드 차단
- Data Exfiltration - 허용되지 않은 도메인으로 데이터 전송 차단
- Clickjacking (X-Frame-Options과 함께)

#### Layer 5: Security Headers

HTTP 보안 헤더로 추가 보호를 제공한다.

**구현**: \`src/backend/infrastructure/security/securityHeaders.ts\`

**주요 헤더**:
\`\`\`typescript
{
  'X-Frame-Options': 'DENY',                 // Clickjacking 방지
  'X-Content-Type-Options': 'nosniff',       // MIME sniffing 방지
  'Referrer-Policy': 'strict-origin-when-cross-origin', // 정보 누출 방지
  'Permissions-Policy': 'geolocation=(), microphone=(), camera=()'  // 브라우저 기능 제한
}
\`\`\`

**환경별 프리셋**:
- **Strict**: 프로덕션 (최대 보안)
- **Balanced**: 일반 사용 (균형잡힌 보안)
- **Lenient**: 개발 (디버깅 허용)
