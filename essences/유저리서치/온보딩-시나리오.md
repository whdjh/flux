# 프로젝트 온보딩 시나리오

빈 프로젝트를 문서화된 프로젝트로 만드는 흐름이다.


## 골격

project-init을 실행한다. 프로젝트가 뭔지 몰라도 된다. CLAUDE.md 골격, context/, .gitmessage.txt가 생긴다. 맥락 없이 동작하는 범용 인프라다.

빈 레포라면 이 산출물로 초기 커밋을 만든다. 그 다음 docs 브랜치를 분기한다. 문서화가 끝나면 main에 머지한다.

CLAUDE.md에는 한 줄 설명만 채운다. 나머지는 맥락이 쌓인 후에.


## 수확

맥락을 모은다. 두 종류다.

팀에서 이미 나눈 대화, 합의, 메모를 정리하는 것. 텍스트를 직접 붙여넣거나, 말로 설명하면 .md로 기록한다. 이게 첫 에센스다.

산재한 파일을 수집하는 것. 경로를 하나씩 알려주면 에이전트가 에센스/로 가져온다.

전량 수집이 원칙이다. 에이전트가 "무관해 보여서" 뺀 파일은 나중에 되돌릴 수 없다. 제외는 사람이 직접 확인한 뒤에만 허용한다.


## 정리

에센스가 수백 개로 모이면 2단계로 정리한다.

tree-planner가 전체 파일을 읽고 토픽 구조를 설계한다. 출처별이 아니라 토픽별로 묶는다. "스택 관련 결정 뭐였더라?" 할 때 토픽이 먼저 떠오르니까.

_structure.md를 draft로 만든다. 각 파일이 어디로 가는지, 중복과 무관 파일이 뭔지 명시한다. 확인하면 진행한다.

Phase 1에서 파일을 토픽 폴더로 이동한다. 중복은 _중복/, 무관 파일은 _아카이브/로 분리한다.

Phase 2에서 각 폴더를 하나의 .md로 합친다. 중복 제거하고, 서술형으로 정리하고, 원본 목록은 "소스 파일" 섹션에 남긴다. 토픽별로 에이전트를 병렬 실행한다. 한 에이전트에 토픽 2개 이상 넣으면 프롬프트가 넘친다.

통합이 끝나면 토픽 폴더를 삭제한다. 원본은 .md에 들어갔다.


## 문서 생성

guide-filler가 레시피와 에센스를 읽고 CLAUDE.md의 {TODO}를 채운다. 에센스가 부족한 섹션은 [TODO]로 남긴다.

recipe-checker가 완성도를 검증한다. 어떤 섹션이 채워졌고, 어떤 게 [TODO]인지 보고한다.

여기까지 끝나면 main에 머지한다.


## 코드 구조 설계

CLAUDE.md가 채워졌으니 맥락이 충분하다. dev 브랜치를 만들고 tree-planner에게 코드 구조를 설계하게 한다.

에센스 정리 때 토픽 구조를, 여기서 코드 구조를 설계한다. 같은 에이전트를 다른 맥락에서 쓴다.


## 분해

기능이 3개 이상이면 병렬로 나눈다.

feature-decomposer가 CLAUDE.md와 코드 구조를 읽고 work unit으로 쪼갠다. 공유 파일은 Phase 1로 분리하고 나머지는 Phase 2에서 병렬로 진행한다.

prompt-builder가 각 work unit을 독립 세션용 프롬프트로 만든다.


## 구현

각 work unit을 독립 세션에서 구현한다.

planner → tdd-guide → code-reviewer 순서다. 인증이나 API 코드라면 security-reviewer도 돌린다.

세션이 끝나면 context-writer가 context/MMDD.md를 생성한다.


## 전체 흐름

```
골격       project-init → 초기 커밋 → docs 브랜치
수확       팀 소통 정리 + 에센스 전량 수집
정리       tree-planner → Phase 1(분류) → Phase 2(통합)
문서 생성   guide-filler → recipe-checker → main 머지
구조 설계   dev 브랜치 → tree-planner(코드 구조)
분해       feature-decomposer → prompt-builder
구현       (planner → tdd-guide → code-reviewer) × N → context-writer
```
