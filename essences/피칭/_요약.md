# 피칭

## 자기소개

크몽에서 자동화, AI 에이전트 카테고리에서 활동하는 프리랜서 개발자다. 다작하는 프로그래머가 되는 것이 목표다.

42Seoul에서 C/C++로 시스템 프로그래밍과 객체지향을 익혔다. 메모리 관리, 포인터, STL을 다루며 저수준부터 고수준까지 경험했고, 하루 150명과 만나며 동료 코드 리뷰를 통해 협업 능력을 길렀다.

2023년 1월 GPT-3.5 출시를 계기로 AI 학습을 시작했다. GPTers에서 퍼퓸투데이 CTO를 맡아 300개 AI 도구를 테스트하고 LangChain과 벡터 DB를 선정했다. 네이버 시향 리뷰 2만개를 LLM으로 분석해 비정형 텍스트를 구조화된 키워드로 변환하는 프롬프트를 수십 번 개선했다. 조향사와 매일 협업하며 정확도를 높였고, 벡터 DB 기반 개인화 추천 시스템을 구축해 글로벌 향수 브랜드 Buly와 Jovoy에 B2B 납품했다. 1,500만원 프로젝트를 마쳤다.

React를 2일 만에 학습해 프로덕션을 개발했고, Cursor AI를 2023년 7월 Beta부터 유료로 사용하며 AI 기반 개발 방법을 익혔다. 이후 AI 협업 개발 방법론을 정립하고, 실험과 프로덕션을 분리하는 워크플로우를 설계했다.

2025년 2개 해커톤에 참가했다. 헬스 코치 AI에서는 LangGraph로 Multi-Agent 시스템을 구현하고, LSTM과 Neural Fusion으로 건강 데이터 예측 모델을 만들었다. 건강 모니터링 해커톤에서는 29시간 동안 LangChain과 Claude로 데이터 파이프라인을 설계해 공동 4위를 했다.


## SKALA 지원

AI를 비즈니스 가치로 만드는 개발 경험을 쌓아왔다. 강점은 빠른 학습 능력과 AI 도구 활용이다. 다만 기업 환경에서의 실무 경험과 대규모 프로덕션 시스템 경험이 부족하다. 개인 프로젝트와 프리랜서 경험으로 역량을 키웠지만, 수백만 사용자를 대상으로 하는 서비스 운영과 큰 팀 단위 개발 프로세스를 경험하지 못했다.

SKALA에서 기업급 시스템 개발과 실무 노하우를 배우고 싶다. 실제 사용자 데이터를 다루며 확장 가능한 아키텍처를 설계하는 방법을 익히고, AI를 안정적으로 비즈니스에 통합하는 경험을 쌓아 신뢰할 수 있는 AI 서비스를 만드는 개발자로 성장하겠다.

클라우드 경험은 2024년 11월부터다. Supabase(PostgreSQL + Drizzle ORM + Realtime), MongoDB Atlas Vector Search, Vercel Serverless를 프로젝트마다 요구사항에 맞게 선택해서 사용했다. SKALA에서는 AWS, Azure, GCP 같은 기업용 클라우드를 배우고 싶다.


## 프로젝트: Flux (지식 관리 도구)

AI 기반 수집, 검색, 협업으로 흩어진 정보를 통합 관리하는 데스크톱 애플리케이션이다. 웹서핑 중 흩어진 정보를 한 곳에 모아 체계적으로 관리하는 문제를 해결한다.

링크, 텍스트 하이라이팅, 이미지 같은 웹 요소들을 단축키 하나로 수집하고, AI로 정리하고, AI로 검색하고, AI 어시스턴트와 아이디어를 만드는 과정까지 지원한다. 노션같은 메모와 협업도 된다. 자료가 북마크, 카카오톡, 다운로드 폴더, 스크린샷 폴더, 클립보드 등에 흩어져 있는 전환 비용을 줄여주는 것이 목적이다.

기술 스택은 스택.md, 핵심 기능은 기능명세/ 참조.

### 개발 방식

팀원 3명이 각자 프롬프트를 만들어 종합한 뒤, Bolt에서 각 20번 이내로 병렬 Zero-Shot 제작 후 가장 가까운 결과물을 기반으로 수정하며 시작했다.

## AI 디버깅 사고 과정 (React 드래그 버그)

React + interact.js 드래그 이동 기능에서 요소가 항상 북쪽 벽에 붙는 버그를 분석한 기록이다.

핵심 문제는 transform과 left/top 스타일을 함께 사용하면서 상태 업데이트와 DOM 변경 사이의 타이밍 불일치가 발생한 것이다. useEffect의 의존성 배열에 machine.x, machine.y가 포함되어 있어 드래그 종료 후 스토어 업데이트 시 interact가 재설정되고, JSX의 data-x/data-y 바인딩이 리렌더링마다 초기화되면서 드래그 상태와 충돌했다.

분석 과정에서 다룬 가설들: data-x/data-y 동기화 문제, restrict modifier의 endOnly 설정, useEffect 클로저의 stale 값, transform 초기화와 리렌더링 사이의 깜빡임, NaN 전파 가능성 등이다.

제안된 해결 방향은 세 가지다. 드래그 중에는 ref로 로컬 위치를 관리하고 드래그 완료 시에만 전역 스토어를 업데이트하는 방식, left/top만 사용하고 transform을 제거하는 방식, restrict modifier를 임시 제거해서 원인을 격리하는 방식이다.
