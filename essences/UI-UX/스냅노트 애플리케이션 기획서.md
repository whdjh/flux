# 사업계획서

1단계: 문제인식
  "[어떤] 문제를 겪고 있는 고객을 [이렇게] 도와주니 [이런] 반응을 보이던데요?"
  "정보 과부하에 시달리는 사람들에게 효율적인 생산성 향상 프로그램을 x"
  "정보 과부하에 시달리는 사람들에게 정보 수집 지도를 주니 .."
  "정보 과부하에 시달리는 사람들에게 링크, 즐겨찾기만을 정리해주는 MVP를 주니 혁신적이라는 반응을 보이던데요?" o or 세모
  "지식 노동자들에게 AI 기반 자동화된 정보 수집 및 관리 시스템을 제공하는 크로스 플랫폼 메모 애플리케이션"
  "사실 지식 노동자들 뿐만 아니라. 모든 지식인들을 위한 것"
  "번아웃 해결 도구"
> 본인의 경험을 바탕으로 창업 배경을 서술했는가?

> 고객이 누구인지 명확하게 정의했는가?

> 고객이 느끼는 불편함을 한 가지로 좁혔는가?

> 고객이 현재 어떻게 불편함을 해결하고 있는지 서술했는가?

> 통계적 수치는 수집한 고객 데이터로 도출한 결론을 뒷받침하고 있는가?

> 통계적 수치를 적정량만 넣었는가?

-------------------
2단계: 실현 가능성
  "[지식 노동자들에게 AI 기반 자동화된 정보 수집 및 관리 시스템을 제공하는 크로스 플랫폼 메모 애플리케이션]"

이 공식에 100% 일치하지 않아도 좋아요. 중요한 건 고객이 갖는 혜택을 중심으로 우리 아이템을 한 문장으로 요약해 설명하는 거예요. 이걸 기준으로 써내려가면 한결 더 수월해진다는 걸 느낄 수 있을 거예요.

덧붙여서,

> "빅데이터와 생성형 AI기술을 융합한 인플루언서 마케팅 올인원 솔루션"
> "블록체인 기반 비상장 기업 주식 거래 플랫폼"

이렇게 내 기술을 자랑하는 표현, 이른바 ‘Buzzword’(그 시대 유행하는 전문 용어 ex: 빅데이터, 블록체인, AI)를 나열하는 방식으로 사업 아이템을 설명해서는 안 돼요. 심사위원이 이해하지 못하는 건 물론이고, 사업계획서 작성하는 거 자체가 더 까다로워지거든요.

...지식 노동자들의 세컨드 브레인....?

> 고객의 문제를 해결해 줄 사업 아이템을 한 문장으로 정의했는가?
> 아이템 개발 관련 내용과 기능 관련 내용을 나누어서 작성했는가?
> 어떤 아이템을 누가 어떻게 개발할 건지 명시하고 있는가?
> 어떤 지표를 확보할 건지 밝히고 있는가?
> 구체적인 판매 계획이 들어 있는가?
> 이미지, 표, 도식을 활용해 설명하고 있는가?

3단계: 성장 전략
> 개발 부분에서의 단기-중기-장기 액션 플랜이 있는가?
> 판매 부분에서의 단기-중기-장기 액션 플랜이 있는가?
> 사업비 세부 지출 내역 작성을 위한 견적을 받아두었는가?
> 채용이 필요한 직무의 연차별 평균 급여를 찾아보았는가?
> 사업비는 인건비와 외주용역비를 나누어 적었는가?
> 실현 가능한 성장 곡선을 그렸는가?
> 해외 진출 가능성을 언급하고 있는가?

4단계: 팀 구성

✅️ 팀 구성 작성 체크리스트 4가지

> 대표의 이력에서 이 사업을 시작한 이유가 보이는가?
> 대표자가 실무에도 관여하고 있음을 보여주고 있는가?
> 팀원들의 이력은 사업 분야에 맞게 서술돼 있는가?
> 고용 계획, 파트너쉽 활용에서 적극성이 드러나는가?

--

사업계획서 작성 가이드라인만 드리면 바로 적용하기가 어렵겠죠? 그래서 저희 팀이 작성했던 <이유식 사업> 사례를 가지고 왔어요.

평범한 사업계획서는 보통 아래처럼 진행돼요.

> "요즘 엄마들이 아기 식단 짜는 것에 육아시간의 30%를 쓴다는 통계가 있어요"
> "아이들은 소중하니까, 맞춤형 식단이 필요해요"
> "이런 솔루션은 아직 없어요"
> "마침 이유식 시장도 급성장하고 있다고 해요"
> "제가 맞춤형 식단 앱을 만들어 볼게요"

못 쓴 사업계획서는 아니지만 선택받을 만큼 매력적인 사업계획서는 아니에요.

이번 글에서 설명한 사업계획서 작성 가이드라인을 적용해서 다시 써볼게요.

> "아기 식단을 제대로 짜려면 책 2-3권은 읽어야 한다고 하네요"
> "동네 엄마 30명을 대상으로 아기 식단 짜는 걸 도와줬는데 편리하다며 20명이 또 해달라고 했어요"
> "입소문이 나서 다 소화하지 못할 만큼 많은 엄마들이 새로 신청했어요"
> "이 서비스를 자동화해서 무료로 배포할 생각이에요"
> "엄마들이 많은 산후조리원을 시작으로요"
> "150만 엄마들의 육아 필수 앱으로 거듭나 유아 식품 커머스까지 할 계획이에요"
> "우리 팀은 개발 역량이 뛰어난 팀이에요. 지금 이유식 판에서 앱 개발은 저희 팀이 앞서 가요"

같은 사업 아이템을 두고도 어떻게 사업계획서를 작성하느냐에 따라서 달라진다는 게 느껴지죠?

선택받는 사업계획서에는 “실현 가능한가?”, “시장이 있나?”, “경쟁력이 있고 크게 키울 수 있나?” 이렇게 3가지 질문에 매력적인 답이 있어야 한다는 걸 꼭 기억하세요!
우리는 매일 엄청난 양의 정보를 접하고 있습니다. 특히 지식 노동자, 연구자, 작가, 기업가들은 이 정보의 홍수 속에서 중요한 내용을 효과적으로 수집하고 관리하는 데 어려움을 겪고 있습니다.

한 소프트웨어 엔지니어는 '하루에 최소 20개의 기술 문서와 50개 이상의 코드 스니펫을 검토하는데, 이를 체계적으로 정리하고 나중에 찾아보는 것이 큰 부담이 된다'라고 말합니다. 한 마케팅 전문가는 '매일 100개 이상의 이메일, 20개의 업계 뉴스, 수십 개의 소셜 미디어 포스트를 확인하지만, 정작 필요할 때 관련 정보를 찾지 못해 답답함을 느낀다'고 토로합니다.

현재 이들은 Evernote, Notion, Google Keep, Obsidian 등 여러 앱과 도구를 조합해 사용하거나, 단순히 브라우저 북마크나 스프레드시트 같은 비효율적인 방식으로 정보를 관리하고 있습니다. 이는 시간 낭비뿐만 아니라 중요한 정보의 손실로 이어집니다.

McKinsey Global Institute의 최근 조사에 따르면, 지식 노동자의 76%가 정보 과부하로 인한 스트레스를 경험하고 있으며, 하루 평균 2.5시간을 단순히 정보를 찾고 정리하는 데 사용한다고 합니다. 이는 연간 약 625시간, 금전적으로 환산하면 직원 1인당 약 $15,000의 손실을 의미합니다.

더욱 심각한 것은, IDC 보고서에 따르면 기업들이 보유한 데이터의 90%가 제대로 활용되지 않고 있다는 점입니다. 이는 혁신의 기회를 놓치고, 경쟁력을 저하시키는 주요 원인이 되고 있습니다.

이러한 상황은 단순한 불편함을 넘어, 개인과 조직의 생산성과 창의성을 심각하게 저해하고 있습니다. 효율적인 정보 관리 도구의 필요성이 그 어느 때보다 절실한 시점입니다.

윈도우에서 실행되는 프로그램 - 창 크기를 사용자가 조정하게 될 것인데, 모든 사용자가 에너지 소모를 덜 하게  도와주고 싶음.. 그래서 우측 상단..?에 그리드를 보여주며 그리드의 칸(줄) 마다 기억할 수 있게 모양이나 색이나 인덱스나 px 숫자를(이게 제일 낫겠다) 보여줘서 창 크기에 맞출 수 있게 하고싶음. 우측 상단보다 창을 기준으로 가로 세로 사이즈를 928px 이런식으로 말고 작은 숫자로(124이나 8, 64 이런식) 나타내고 싶음. 창 크기를 4px 단위로만 변경할 수 있게 하면 도움이 될 거란 생각. 가로 세로 비율을 고정시켜야 할 지 고정시키지 말아야 할 지 생각 고민중(고정시키지 말아야 할 것 같은데, 편하게 할 아이디어좀)

## 1. 프로젝트 개요
### 1.1 제품정의:
"스냅노트"는 사용자 경험을 최우선으로 하는 자동화된 메모 애플리케이션입니다. 심플한 인터페이스와 AI 기반 자동 정리 기능을 결합해 최소한의 노력으로 최대의 정보 관리 효율성을 달성합니다.

### 1.2 컨셉
- '심플한 메모'
- '최소한의 에너지로 데이터 수집'
- '예측 가능한 자동 분류'
- '프라이버시'
- '협업 기능'
- 'AI를 활용한 자동 태깅, 분류, 내용 요약, 주요 키워드 추출'

- '사용자 경험 최우선'
- '직관적인 UI로 학습 곡선 최소화'
- '사용자의 작업 흐름을 방해하지 않는 설계'
- '최소한의 사용자 노력으로 최대의 정보 관리 효율성 달성'
- '적당한 커스터마이즈로 사용자가 어플을 설정하며 들 에너지도 최소화'

### 1.3 타겟
- 정보 과부하에 시달리는 사람들: 키워드 - 지식 노동자, 연구자, 작가, 기업가(대표님들), 개발자, PM, 기획자 
- 25-45세 지식 노동자, 특히 IT 업계 종사자

### 1.4 차별화 포인트
- 원클릭 스크래핑: 한 번에(단 한 번의 터치) 스크래핑, 빠른기록
- Rust 기반 고성능: Rust를 사용해 검색 엔진, 스크래핑, 자동 요약과 정리, 메모 속도를 최대한 빠르게.
- AI 기반 자동 정리: 저장된 정보를 자동으로 요약, 태깅, 분류
- 검색: 태그 or 키워딩 기능으로 검색이 직관적이게. 의미기반 시멘틱 검색기능.
- UI: 직관적인 UI로 학습 곡선 최소화
- UX: 사용자 중심 최우선의 UX로 사용자의 에너지를 아껴주는 프로그램
- 프라이버시 중시:  종단간 암호화와 로컬 우선 저장으로 메모 내용 절대적 보호. 블록체인으로도 믿음을 줄 수도 있음. (사용자 인식: 종단간 암호화와 로컬 우선 저장으로 보호 -> 그냥 그럼. 블록체인으로 보호 -> 절대적으로 보호되는거 알고있음.)
- 크로스 플랫폼: 모든 플랫폼 PC, 아이폰, 안드로이드에서 똑같은 수집이 가능하고 같은 내용 공유.
- 클라우드: 옵시디언처럼 클라우드를 서비스.
- 실시간 협업: 하지만 노션처럼 협업도 가능.
- 백그라운드 실행

### 1.5 주요 목표
- 빠른 기록: 사용자의 웹서핑에 방해 안되게 즉시 수집&기록
- 자동 정리: 자동 정리 및 요약, 분류, 검색 최적화
- 협업: Todo: 협업 방식 고르기.
- 직관적인 UI/UX:  사용자 경험을 최우선으로, 학습 곡선x, 직관적인 UI
- 크로스 플랫폼: PC & 모바일 작업 공유

## 6. 기술 스택

### 6.1 프론트엔드
- Tauri: 경량 크로스 플랫폼 프레임워크 (선택 이유: 네이티브 성능, 작은 번들 크기)
- React  + TypeScript : 컴포넌트 기반 UI 개발, 정적 타입 지원 (선택 이유: 생산성, 유지보수성)
- TailwindCSS: 유틸리티 퍼스트 CSS 프레임워크 (선택 이유: 빠른 UI 개발, 일관성)
- WebAssembly(WASM): 성능 중심 모듈 구현 (선택 이유: 네이티브에 가까운 성능)

### 6.2 백엔드
- Rust (Actix-web 4.x): 고성능 웹 서버 (선택 이유: 안정성, 속도, 메모리 안전성)
- Tokio: 비동기 런타임 (선택 이유: 효율적인 리소스 관리)

### 6.3 데이터베이스
- PostgreSQL 14+: 메인 데이터베이스, JSON 지원 (선택 이유: 확장성, 복잡한 쿼리 지원)
- SQLite 3.x: 로컬 저장 및 오프라인 모드용 (선택 이유: 가벼움, 내장 가능)
- Redis 6.x: 캐싱, 세션 관리 (선택 이유: 빠른 읽기/쓰기 성능)
- Qdrant: 벡터 유사도 검색 엔진 (선택 이유: 효율적인 유사 메모 검색)

### 6.4 AI 및 NLP
- Claude-3.5-sonnet: 고급 자연어 처리 및 생성 (선택 이유: GPT-4 대비 우수한 성능)
- Rust-bert: 경량 BERT 모델 구현 (선택 이유: 빠른 텍스트 분석)
- lindera: Rust 기반 형태소 분석기 (선택 이유: 다국어 지원)
- fasttext-rs: 빠른 텍스트 분류 및 임베딩 (선택 이유: 효율적인 텍스트 분류)

### 6.5 검색 엔진
- Tantivy: Rust 기반 전문 검색 엔진 (선택 이유: 빠른 검색 속도, Rust 생태계 통합)
- ElasticSearch ?
### 6.6 보안
- ring: 암호화 라이브러리 (선택 이유: 검증된 보안성)
- jsonwebtoken: JWT 기반 인증 (선택 이유: 표준 준수, 확장성)

### 6.7 협업 및 동기화
- yrs: Rust 기반 CRDT 구현체 (선택 이유: 실시간 협업에 최적화)
- tokio-tungstenite: WebSocket 지원 (선택 이유: 실시간 통신)

### 6.8 기타
- tracing: Rust 로깅 및 계측 프레임워크 (선택 이유: 상세한 모니터링)
- lapin: RabbitMQ 클라이언트 (선택 이유: 메시지 큐 처리)
- Prometheus + Grafana: 모니터링 및 시각화 (선택 이유: 실시간 성능 모니터링)

1. 협업 기능 강화 (김성수 대표님): Phase 3에서 노션 스타일의 실시간 공동 편집 구현

## 9. 추가 고려사항

- 기억의 궁전 개념 적용:
  - 가상의 3D 공간에 메모를 배치하여 시각적 기억 강화
  - 사용자가 자신만의 가상 공간을 설계하고 메모를 배치할 수 있는 인터페이스 제공
- 키워드 중심 메모법 최적화: AI가 추출한 키워드를 중심으로 메모 구조화 및 연결
- 책갈피 기능: 중요 메모나 자주 접근하는 메모에 빠르게 접근할 수 있는 기능
- 웹페이지 UI 추가 개선: 데스크톱 앱과 일관된 경험을 제공하면서도 웹 환경에 최적화된 UI 설계
- 확장 플러그인 시스템: 사용자 정의 기능 추가를 위한 API 및 개발 키트 제공
- 비즈니스 모델: 기본 기능 무료, 고급 AI 기능 및 대용량 클라우드 저장소는 구독제 운영
