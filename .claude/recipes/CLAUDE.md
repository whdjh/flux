# 레시피

프로젝트 식별 · 빌드/실행 · 절대 규칙 · 문서 동기화 · 맥락 관리

## 레퍼런스

- [How to Write a Great CLAUDE.md — Tembo](https://www.tembo.io/blog/how-to-write-a-great-claude-md) — 200개 instruction 한계, progressive disclosure, 포인터 원칙

- [The Complete Guide to CLAUDE.md — Builder.io](https://www.builder.io/blog/claude-md-guide) — 모듈화, 300줄 제한

## 핵심 원칙

Evaluating AGENTS.md 논문의 결론이다. CLAUDE.md에 많이 넣을수록 AI가 똑똑해지는 게 아니라, 불필요한 지시를 충실히 따르느라 비용이 늘고 성공률이 떨어진다.

200줄 이하를 유지한다. 이 제한을 넘으면 AI가 규칙을 선택적으로 무시하기 시작한다. "있으면 좋겠다" 수준의 가이드는 전부 rules/나 skills/로 분리한다.

포함하는 것:

- 빌드/테스트/린트 명령어
- 리포 고유 도구와 환경변수
- 절대 규칙 3-5개 (어기면 프로젝트가 깨지는 것만)
- 문서 동기화 트리거
- 스킬 인덱스 (필요할 때만 로드)

제외하는 것:

- 디렉토리 구조 (stale되면 AI를 적극 방해, package.json이나 코드에서 읽을 수 있음)
- README 내용 중복
- 상세 코딩 스타일 (rules/coding-style.md로 분리, 커밋 형식은 .gitmessage.txt)
- 기술 스택 나열 (package.json/pyproject.toml에 이미 있음)
- "있으면 좋겠다" 가이드

## 필요한 에센스

- [ ] 프로젝트 개요 (저장소명, 한 줄 설명)
- [ ] 빌드/실행 명령어 (패키지 매니저, dev 서버, 빌드, 테스트, 린트)
- [ ] 환경변수 목록 (.env 파일, 필수/선택 구분)
- [ ] 절대 규칙 (수정 금지 파일, 보안 경고, 프로젝트 함정)
- [ ] 문서 동기화 대상 (코드 변경 시 업데이트할 문서)
- [ ] .claude/ 설정 현황 (rules/, skills/, commands/ 등)

## 만드는 법

### 1. 프로젝트 식별

CLAUDE.md의 첫 줄이다. AI가 "이 프로젝트가 뭔지" 5초 안에 파악할 수 있어야 한다.

```markdown
# CLAUDE.md

{프로젝트가 뭘 하는지 한 줄 설명}
```

"React + FastAPI 프로젝트"보다 "공장 레이아웃을 시각화하고 편집하는 웹 애플리케이션"이 AI에게 더 유용하다. 기술 스택은 package.json에서 이미 읽을 수 있다.

### 2. 빌드/실행

AI가 프로젝트를 실행하고 테스트하는 데 필요한 명령어다. 복사-붙여넣기 가능하게 만든다.

```markdown
## 빌드 및 실행

{패키지 설치 명령어}
{개발 서버 명령어}
{빌드 명령어}
{테스트 명령어}
{린트 명령어}
```

환경변수는 빌드/실행 안에 하위 섹션으로 넣는다. 필수/선택을 구분하고, 시크릿 값은 절대 쓰지 않는다. 10개를 넘으면 별도 섹션으로 분리한다.

포인터 원칙을 적용한다. `vite.config.ts`의 전체 내용을 복사하지 않는다. "Vite 설정은 `frontend/vite.config.ts` 참조"로 충분하다.

### 3. 절대 규칙

AI가 어기면 프로젝트가 깨지는 규칙만 넣는다. 3-5개로 제한한다. "이러면 좋겠다"는 rules/로 보낸다.

세 종류가 있다:

수정 금지: AI가 절대 건드려서는 안 되는 파일이나 디렉토리. 자동 생성 파일, 벤더 코드, 설정 파일 중 손대면 안 되는 것.

프로젝트 함정: "이 파일을 수정하면 저 파일도 같이 바꿔야 한다" 같은 암묵적 의존성.

보안 경고: 하드코딩된 시크릿, 열린 CORS, 미해결 보안 이슈.

```markdown
## 절대 규칙

- {파일}: 수정 금지 — {이유}
- {파일} 수정 시 {파일}도 함께 변경
- {보안 경고}
```

에센스가 없으면 이 섹션은 비워두고 추후 발견되는 대로 축적한다. CLAUDE.md에서 가장 ROI가 높은 섹션이다.

### 4. 문서 동기화

코드 변경 시 AI가 관련 문서를 업데이트하게 하는 트리거다.

```markdown
## 문서 동기화

| 변경     | 업데이트할 문서 |
| -------- | --------------- |
| {트리거} | {문서 경로}     |
```

일반적인 패턴:

- 기능 구현 완료 → 진행현황 상태 변경
- API 변경 → API 문서 업데이트
- 트러블슈팅 해결 → 트러블슈팅 문서 추가

오래된 문서가 AI를 적극적으로 방해한다. 동기화 트리거가 없으면 문서가 코드와 괴리되고, AI가 잘못된 맥락으로 작업한다.

### 5. 맥락 관리

세션 간 연속성을 유지하는 루틴이다.

```markdown
## 맥락 관리

세션 시작: 최근 context/ 파일에서 "할 것" 확인
세션 종료: context/MMDD.md 작성 (한 것/근거/할 것)
```

"근거"가 가장 중요하다. 작업 기록은 시간이 지나면 가치가 줄지만, 결정 근거는 프로젝트 전체에서 참조된다.

### 6. 분산 전략

200줄 상한을 지키는 방법이다. CLAUDE.md에 전부 넣지 않고 분산한다.

rules/ 분리: 코딩 스타일, 테스트 전략, 보안 가이드라인, Git 워크플로우 같은 범용 규칙은 `.claude/rules/`에 둔다. 항상 로드되지만 CLAUDE.md를 비대하게 만들지 않는다.

Skills 분리: 제목만 로드되고(~100토큰), 필요할 때만 전체를 꺼내 쓰는 서랍장이다. 상세 가이드를 여기에 넣으면 평소에는 토큰을 소비하지 않는다.

Hooks 기반: SessionStart 훅으로 프로젝트별 맥락을 주입할 수 있다. CLAUDE.md 없이도 동작하는 패턴이다.

```
CLAUDE.md              ← 200줄 이하 (식별, 빌드, 절대 규칙, 동기화, 맥락)
.claude/
├── rules/             ← 항상 로드 (세부 규칙 분산)
├── skills/            ← 필요할 때만 로드 (상세 가이드)
├── commands/          ← 슬래시 명령어
└── settings.json      ← hooks, permissions
```

CLAUDE.md를 레시피 없이 AI에게 통째로 자동 생성시키지 않는다. 논문에서 LLM 자동 생성 컨텍스트 파일은 성공률이 오히려 떨어졌다. 레시피를 읽고 만들게 하거나, 사람이 직접 작성한다.

## 체크리스트

### 필수

- [ ] 프로젝트 설명이 "뭘 하는지"를 5초 안에 전달하는가
- [ ] 빌드/실행 명령어가 복사-붙여넣기 가능한가
- [ ] 절대 규칙이 3-5개 이내인가
- [ ] 문서 동기화 트리거가 정의됐는가
- [ ] 맥락 관리 루틴이 명시됐는가

### 금지

- [ ] 디렉토리 구조가 포함되지 않았는가
- [ ] 기술 스택 나열이 없는가 (package.json에서 읽을 수 있음)
- [ ] 린터가 강제하는 스타일 규칙이 중복되지 않았는가
- [ ] "있으면 좋겠다" 수준의 가이드가 포함되지 않았는가

### 분량

- [ ] 200줄 이하인가
- [ ] 200줄을 넘으면 rules/나 skills/로 분리했는가
- [ ] 코드 복사 대신 파일 포인터를 사용했는가
