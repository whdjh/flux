## 만드는 법

### 맥락

현재 상황을 AI에게 전달한다. 파일 위치, 프로젝트 구조, 이전 작업 히스토리가 맥락이다.

```
@파일경로 를 보고 {작업}해줘
```

여러 파일:
```
@파일1 @파일2 를 비교해서 {작업}해줘
```

맥락이 부족하면 AI가 추측하고, 그 추측은 종종 빗나간다. 맥락이 많다고 좋은 것도 아니다. 핵심은 "구체적이고 명확한" 맥락이다.


### 역할

AI에게 전문가 관점을 부여한다. 같은 코드도 보안 전문가와 성능 전문가가 보는 관점이 다르다.

```
보안 전문가로서 이 인증 로직을 검토해줘
```

```
시니어 프론트엔드 엔지니어로서 이 컴포넌트 구조를 리뷰해줘
```

역할을 명시하면 답변의 깊이와 초점이 달라진다.


### 의도

뭘 하려는지 명확하게 말한다. 모호한 지시는 모호한 결과를 낳는다.

```
❌ "이거 고쳐줘"
✅ "@파일.ts:42 에서 TypeError 발생, null 체크 추가해줘"

❌ "좋게 만들어줘"
✅ "이 함수의 시간복잡도를 O(n)으로 개선해줘"
```

트리거 키워드로 사고 깊이를 조절할 수 있다:
- `please ultra think` — 깊은 사고 모드
- `think hard` — 복잡한 문제 해결


### 제약

하지 말아야 할 것, 지켜야 할 조건을 명시한다. 제약이 없으면 AI가 과잉 엔지니어링한다.

```
기존 API 인터페이스를 변경하지 마.
테스트 파일은 건드리지 마.
외부 라이브러리 추가하지 마.
```


### 출력 형식

원하는 결과의 형태를 지정한다. 의도가 "뭘 할지"라면, 출력 형식은 "어떤 모양으로 줄지"다.

```
JSON으로 응답해줘
표로 정리해줘
코드만 줘, 설명 없이
마크다운으로 정리해줘
```


### 예시

원하는 결과의 구체적 사례를 보여준다. 설명 10줄보다 예시 1개가 효과적이다.

```
이런 형식으로 변환해줘:
입력: getUserName → 출력: get_user_name
```


### 분할/체이닝

복잡한 작업은 쪼개서 순차적으로 요청한다. 한 번에 모든 것을 시키면 품질이 떨어진다.

```
1단계: 먼저 현재 코드를 분석하고 문제점을 정리해줘
2단계: 문제점별로 해결 방안을 제시해줘
3단계: 가장 영향도가 큰 것부터 수정해줘
```

에이전트를 활용한 체이닝:
```
/plan {기능 설명}     → 계획 수립
구현                   → 코드 작성
/review               → 코드 리뷰
```


### 반복 개선

프롬프트는 한 번에 완성되지 않는다. 결과를 보고 다듬는다.

```
1. 초안 프롬프트로 결과 확인
2. 부족한 부분 파악 (맥락? 제약? 예시?)
3. 프롬프트 보강 후 재시도
```

효과적이었던 프롬프트는 기록해둔다. 패턴이 반복되면 에이전트나 스킬로 승격한다.


### 도구 활용

AI 코딩 도구의 고유 기능을 활용한다. `@파일경로`로 맥락을 직접 넘기고, 에이전트(`/plan`, `/review`, `/tdd`)와 스킬(`/commit`, `/save-session`)로 체이닝한다.

체이닝 예시:
```
/plan {기능 설명} → 구현 → /review → /commit
```


## 출력 형식

### 프롬프트 통합 템플릿

기본형:

```
{역할}로서 {맥락}을 보고 {의도}해줘.

{제약 1}
{제약 2}

{출력 형식}으로 응답해줘.

예시:
입력: {입력 예시} → 출력: {출력 예시}
```

분할형 (복잡한 작업):

```
1단계: {맥락}을 분석하고 {중간 산출물}을 정리해줘
2단계: {중간 산출물}을 기반으로 {의도}해줘
3단계: {검증 기준}에 맞는지 확인해줘

— 각 단계 결과를 확인하고 부족하면 {맥락/제약/예시}를 보강해서 재시도
```

도구 활용형:

```
@{파일경로} 를 보고 {역할}로서 {의도}해줘.
{제약}
```

### 프롬프트 가이드 템플릿

프로젝트별 프롬프트 모음을 만들 때 이 구조를 쓴다.

```markdown
# 프롬프트 가이드


## 구조

맥락 → 역할 → 의도 → 제약 → 출력 형식 → 예시


## 자주 쓰는 패턴

### {작업 유형}

{프롬프트 템플릿}

예시:
{실제 예시}


## 분할 전략

{복잡한 작업을 어떻게 쪼개는지}


## 효과적이었던 프롬프트

### {날짜}: {상황}

{프롬프트}

결과: {왜 효과적이었는지}
```


## 체크리스트

### 프롬프트 작성 전
- [ ] 맥락 제공 (파일, 상황)
- [ ] 역할 지정 (필요시)
- [ ] 의도 명확히 (뭘 원하는지)
- [ ] 제약 조건 (하지 말 것)
- [ ] 출력 형식 지정 (필요시)

### 복잡한 작업
- [ ] 단계별로 분할
- [ ] 에이전트/스킬 활용 검토
- [ ] 중간 결과 확인 후 다음 단계

### 작성 후 확인
- [ ] 모호한 표현 없음
- [ ] 구체적인 기준 있음
- [ ] 필요한 파일 태그됨
- [ ] 효과적인 프롬프트 기록
