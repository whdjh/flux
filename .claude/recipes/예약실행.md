## 만드는 법

### 1. 실행 방식

Claude Code를 사람 없이 돌리는 방법은 세 가지다.

CLI 직접 호출은 가장 단순하다. `-p` 플래그로 프롬프트를 넘기면 대화형 세션 없이 실행하고 종료한다. cron이나 systemd timer에 넣으면 스케줄 실행이 된다.

```bash
claude -p "프롬프트 내용"
claude -p "$(cat prompt.md)"
```

SDK 호출은 프로그래밍 방식이다. Node.js 스크립트에서 Claude Code를 호출하고 결과를 후처리할 수 있다. CI/CD 파이프라인이나 웹훅 트리거에 적합하다.

GitHub Actions 연동은 PR, 이슈, 스케줄 이벤트에 반응한다. `@anthropics/claude-code-action`을 쓰면 된다.

에센스에서 실행 환경을 확인하고 적합한 방식을 선택한다. 단순 반복이면 cron + CLI, 조건부 실행이면 SDK, PR 자동화면 GitHub Actions.

스케줄 등록은 실행 방식에 따라 다르다. cron이면 crontab에 등록하고, macOS 노트북이면 launchd를 쓴다. launchd는 잠자기 중에 놓친 작업을 깨어난 후 실행하므로 더 안정적이다.

```bash
# crontab (분은 0이 아닌 값으로 — API 부하 분산)
7 9 * * 1-5 /path/to/scripts/claude-cron.sh
```

작업 목록은 테이블로 정리한다. 작업명, 스케줄, 프롬프트 파일 경로, 타임아웃을 한눈에 볼 수 있어야 한다.


### 2. 헤드리스 실행

사람이 없는 환경에서 실행하려면 두 가지를 해결해야 한다. 권한 승인을 자동화하는 것과, 입력을 비대화형으로 만드는 것이다.

`--allowedTools`로 사용할 도구를 명시적으로 허용한다. 허용하지 않은 도구를 쓰려 하면 실행이 멈추므로, 자동 작업에 필요한 도구를 전부 열거해야 한다.

```bash
claude -p "프롬프트" \
  --allowedTools "Bash(git diff:*)" \
  --allowedTools "Read" \
  --allowedTools "Write" \
  --allowedTools "Edit"
```

`--dangerously-skip-permissions`는 모든 권한을 건너뛴다. CI처럼 격리된 환경에서만 쓴다. 로컬에서는 절대 쓰지 않는다.

출력 형식은 `--output-format`으로 제어한다. 자동화 파이프라인이면 `json`이나 `stream-json`을 쓴다. 사람이 볼 로그면 `text`를 쓴다.

```bash
claude -p "프롬프트" --output-format json
claude -p "프롬프트" --output-format stream-json
```


### 3. 권한/보안

자동 작업에서 보안은 "최소 권한"이 원칙이다. 작업에 필요한 것만 열어주고 나머지는 전부 막는다.

파일 접근 범위를 제한한다. `--allowedTools "Bash(git diff:*)"` 처럼 명령어 패턴으로 실행 가능한 bash 명령을 제한한다. `Write`와 `Edit`을 허용하면 모든 파일을 수정할 수 있으므로, 프로젝트 디렉토리 외부 접근이 불가능한 환경(컨테이너, CI)에서 실행한다.

API 키와 시크릿은 환경변수로 주입한다. 프롬프트에 하드코딩하지 않는다. CI에서는 시크릿 매니저를 쓴다.

네트워크 권한은 에센스에서 결정한다. 외부 API 호출이 필요한 작업이면 MCP 서버 접근을 허용하고, 코드 분석만 하는 작업이면 네트워크를 차단한다.


### 4. 프롬프트 설계

자동 실행 프롬프트는 대화형과 다르다. 추가 질문을 할 수 없으므로 모든 맥락을 한 번에 넣어야 한다.

프롬프트는 네 블록으로 구성한다.

```markdown
## 맥락
{프로젝트 설명, 현재 상태}

## 작업
{구체적으로 뭘 하라는 지시}

## 제약
{하지 말아야 할 것, 범위 제한}

## 출력
{결과물 형식, 저장 위치}
```

맥락은 CLAUDE.md에서 읽히므로 중복하지 않는다. 작업 지시만 명확하게 쓴다. "코드를 개선해라" 같은 모호한 지시는 자동 환경에서 예측 불가능한 결과를 낳는다.

프롬프트 파일로 분리하면 버전 관리가 된다.

```bash
claude -p "$(cat prompts/daily-review.md)"
```

### 5. 에러 핸들링

자동 실행에서 에러가 나면 사람이 즉시 볼 수 없다. 세 가지를 준비한다.

종료 코드로 성공/실패를 판단한다. `claude -p`는 실행 결과에 따라 종료 코드를 반환한다. cron 스크립트에서 이걸 잡아서 후처리한다.

```bash
claude -p "$(cat prompt.md)" --output-format json > result.json 2> error.log

if [ $? -ne 0 ]; then
  # 실패 알림 전송
  {알림 명령어}
fi
```

타임아웃을 설정한다. `--max-turns`로 대화 턴 수를 제한하면 무한 루프를 방지한다. `timeout` 명령어와 조합하면 시간 제한도 건다.

```bash
timeout 300 claude -p "프롬프트" --max-turns 10
```

재시도 가능 여부는 에러 유형에 따라 다르다. 네트워크 에러나 타임아웃은 재시도가 적절하지만, 권한 에러나 프롬프트 로직 에러는 재시도해도 같은 결과가 나온다.

```bash
MAX_RETRIES=3
for i in $(seq 1 $MAX_RETRIES); do
  timeout 300 claude -p "$(cat prompt.md)" --max-turns 10 && break
  echo "attempt $i failed, retrying in 30s..."
  sleep 30
done
```

재시도 횟수와 간격은 에센스에서 결정한다.


### 6. 로깅/모니터링

자동 작업의 실행 기록이 없으면 문제 발생 시 원인을 추적할 수 없다.

실행 로그를 파일로 남긴다. `--output-format stream-json`을 쓰면 실행 과정이 JSON 스트림으로 나온다. 이걸 날짜별 파일에 저장한다.

```bash
claude -p "$(cat prompt.md)" \
  --output-format stream-json \
  > "logs/$(date +%Y%m%d-%H%M%S).jsonl" 2>&1
```

모니터링은 두 가지를 추적한다. 실행 성공/실패 비율과 실행 시간이다. 실패가 연속으로 발생하면 알림을 보낸다. 실행 시간이 비정상적으로 길어지면 프롬프트나 작업 범위를 점검한다.

실행 시간을 추적하면 프롬프트 효율을 판단할 수 있다. stream-json 로그에서 타임스탬프를 추출하면 된다.

```bash
START=$(date +%s)
claude -p "$(cat prompt.md)" --output-format stream-json \
  > "logs/$(date +%Y%m%d-%H%M%S).jsonl" 2>&1
DURATION=$(( $(date +%s) - START ))
echo "duration: ${DURATION}s" >> logs/metrics.log
```

알림 채널은 에센스에서 결정한다. 슬랙 웹훅, 이메일, 시스템 알림 중 프로젝트에 맞는 방식을 선택한다.


### 7. 활용 패턴

자동 작업으로 효과적인 패턴이 있다.

코드 리뷰 자동화: PR이 올라오면 Claude Code가 자동으로 리뷰 코멘트를 남긴다. GitHub Actions + `claude-code-action`으로 구현한다.

일일 코드 건강 체크: 매일 정해진 시간에 테스트 실행, 린트, 타입 체크, 보안 스캔을 돌리고 결과를 리포트한다.

문서 자동 갱신: 코드 변경이 감지되면 관련 문서를 업데이트한다. CLAUDE.md의 문서 동기화 트리거와 연동한다.

이슈 트리아지: 새 이슈가 올라오면 자동으로 분류하고 라벨을 붙인다.
