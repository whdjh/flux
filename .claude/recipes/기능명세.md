## 만드는 법

### 1. 분석 → 화면 단위 분리

요구사항 분석 결과를 화면 단위로 쪼갠다. 기능 중심으로 정리하면 같은 기능이 여러 화면에 걸쳐서 설명이 흩어진다. 디자이너도 개발자도 화면 단위로 작업하기 때문에 기능명세도 화면 단위로 쓰면 모두가 같은 단위로 소통한다.

번호 체계(01_, 02_)는 메뉴구조의 순서를 따른다. 사이트맵과 기능명세가 같은 순서이면 왔다갔다하기 쉽다.

```
기능명세/
├── 00_공통.md          # 전체 공통 기능
├── 01_로그인.md
├── 02_메인페이지.md
└── ...
```

### 2. 화면별 기능명세 작성

각 화면에 대해 의도, 구성, 동작을 정리한다. 의도가 불명확하면 화면 자체가 불필요할 수 있다. 화면 구성은 정밀한 디자인이 아니라 구조를 보여주는 수준이면 된다.

기능명세 구조:
```markdown
# {기능명}

{한 줄 의도}

## 화면 구성
[ASCII 다이어그램]

## 기능
{기능별 동작 설명}

## 동작 흐름
1. 사용자가 {액션}
2. 시스템이 {반응}

## 용도
{왜 필요한지}
```

### 3. 기능명세 → 진행현황

기능명세를 기반으로 진행현황 항목을 생성한다. 진행현황은 상태만 추적한다. 상세 내용은 기능명세에 있으니 중복으로 쓰지 않는다.

```markdown
## {카테고리}

| 상태 | 작업 | 우선순위 |
|:---:|---|:---:|
| 🕐 | 기능명세에서 추출한 작업 | 필수/중요/선택 |
```
