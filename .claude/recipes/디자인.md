# 레시피

브랜드/디자인 원칙 · 색상 시스템 · 타이포그래피 · 레이아웃/스페이싱 · 디자인 토큰 · 컴포넌트 · 아이콘 · 접근성 · 다크모드

## 필요한 에센스

- [ ] 브랜드 가이드라인 (로고, 컬러 팔레트, 톤앤매너) - 파일 또는 링크
- [ ] 브랜드 색상 HEX 값 (Primary, Secondary, Accent 최소 3개)
- [ ] 폰트 (한글/영문 각각, 웹폰트 또는 파일)
- [ ] 레퍼런스 UI (모던/클래식/미니멀, 스크린샷 또는 링크)
- [ ] 대상 디바이스 및 해상도 (데스크톱/모바일/태블릿/산업장비)
- [ ] 다크모드 지원 여부 및 조건 (필수/선택/미지원 + 근거)
- [ ] 프로젝트 화면 목록 (폼, 테이블, 대시보드 등 주요 UI 패턴)
- [ ] 아이콘 스타일 선호도 (라인/솔리드/듀오톤) - 선택
- [ ] 접근성 요구사항 (WCAG 등급, 대상 사용자 특성) - 선택
- [ ] 기존 디자인 시스템 자료 (Figma, Sketch 등) - 선택


## 만드는 법

### 1. 브랜드 → 디자인 원칙

입력: 에센스의 "브랜드 가이드라인"과 "레퍼런스 UI".

에센스에서 받은 브랜드 가이드라인을 3-5개의 디자인 원칙으로 정제한다. 원칙은 구체적인 설계 판단 기준이 되어야 한다. "깔끔하게"처럼 모호한 원칙은 판단 기준이 되지 못한다.

원칙 작성 패턴:
```
{원칙명}: {한 문장 정의}
→ 적용: {구체적 설계 판단 기준}
```

예시:
```
명료함: 사용자가 3초 안에 다음 행동을 알 수 있어야 한다
→ 적용: 화면당 주요 행동 1개, 보조 행동 2개 이내
```

브랜드 톤앤매너가 없으면 레퍼런스 UI에서 추출한다. 색상 온도, 여백 밀도, 시각적 무게감에서 방향성을 잡는다.


### 2. 브랜드 색상 → 색상 시스템

입력: 에센스의 "브랜드 색상 HEX 값"과 "다크모드 지원 여부".

에센스에서 받은 HEX 값을 oklch로 변환한다. oklch는 지각적 균일성이 보장되어 같은 Chroma/Hue에서 Lightness만 조절하면 다크모드 팔레트를 자동으로 파생할 수 있다. HSL은 색상에 따라 밝기 인식이 달라지는 문제가 있다.

변환 도구: https://oklch.com

```
HEX #{값} → oklch({L} {C} {H})
```

CSS 변수 구조:
```css
/* 브랜드 색상 */
--primary: oklch({값});
--primary-foreground: oklch({값});
--secondary: oklch({값});
--secondary-foreground: oklch({값});
--accent: oklch({값});
--accent-foreground: oklch({값});

/* 시맨틱 색상 */
--destructive: oklch({값});
--warning: oklch({값});
--success: oklch({값});
--muted: oklch({값});
--muted-foreground: oklch({값});

/* 표면 색상 */
--background: oklch({값});
--foreground: oklch({값});
--card: oklch({값});
--border: oklch({값});
```

다크모드를 지원하면 Lightness(L) 값을 반전시키는 방식으로 파생한다. 채도(C)와 색상(H)은 유지하되, L 값만 조정한다. `.dark` 클래스 또는 `prefers-color-scheme: dark` 미디어 쿼리로 전환한다.

다크모드를 지원하지 않는 경우도 명시적으로 기록한다. "지원 안 함"이 아니라, 왜 지원하지 않는지 근거를 남긴다. 환경(공장 조명), 디바이스(구형 모니터), 사용자 특성 등이 근거가 된다.


### 3. 폰트 → 타이포그래피 시스템

입력: 에센스의 "폰트"와 "대상 디바이스".

에센스에서 폰트가 이미 정해져 있으면 그대로 사용한다. 정해지지 않았으면 아래 권장 목록에서 선택한다.

한글 지원 웹폰트 권장 목록:

| 폰트 | 특징 | 소스 |
|-------|------|------|
| Pretendard | 시스템 UI 느낌, 가변폰트 지원 | CDN/npm |
| Noto Sans KR | 넓은 웨이트 범위 | Google Fonts |
| Spoqa Han Sans | 깔끔한 고딕 | CDN |

CSS 변수:
```css
--font-sans: "{한글폰트}", "{영문폰트}", system-ui, sans-serif;
--font-mono: "{모노폰트}", ui-monospace, monospace;
```

크기 체계는 대상 디바이스에 맞춰 결정한다. 모바일이면 본문 16px, 데스크톱이면 14px이 기준이다. 산업 환경(거리 시인성)이면 더 키운다.

| 용도 | 크기 | Tailwind | 행간 |
|------|------|----------|------|
| 대제목 | {n}px | text-{size} | {n} |
| 소제목 | {n}px | text-{size} | {n} |
| 본문 | {n}px | text-{size} | {n} |
| 라벨 | {n}px | text-{size} | {n} |
| 캡션 | {n}px | text-{size} | {n} |

폰트 웨이트는 3단계로 제한한다: Regular(400), Medium(500), Bold(700). 과도한 웨이트 분화는 시각적 일관성을 해친다.


### 4. 디바이스 → 레이아웃/스페이싱

입력: 에센스의 "대상 디바이스 및 해상도".

스페이싱 스케일은 4px 기반 배수 체계를 사용한다. 4px 배수를 쓰는 이유는 대부분의 디스플레이가 짝수 픽셀에서 서브픽셀 렌더링 문제가 없기 때문이다.

```css
--spacing-1: 0.25rem;   /* 4px */
--spacing-2: 0.5rem;    /* 8px */
--spacing-3: 0.75rem;   /* 12px */
--spacing-4: 1rem;      /* 16px */
--spacing-6: 1.5rem;    /* 24px */
--spacing-8: 2rem;      /* 32px */
--spacing-12: 3rem;     /* 48px */
--spacing-16: 4rem;     /* 64px */
```

반응형 브레이크포인트:

| 이름 | 크기 | 대상 |
|------|------|------|
| sm | {n}px | {디바이스} |
| md | {n}px | {디바이스} |
| lg | {n}px | {디바이스} |
| xl | {n}px | {디바이스} |

Tailwind 기본값(640/768/1024/1280)을 사용하되, 특수 환경(산업용 터치패널 등)이 있으면 에센스에서 결정한다.

컨테이너 최대 너비와 여백 규칙:
```css
--container-max: {값}px;
--container-padding: var(--spacing-4);  /* 모바일 */
--container-padding-md: var(--spacing-8);  /* 데스크톱 */
```


### 5. 색상+타이포+스페이싱 → 디자인 토큰

입력: 규칙 2-4의 결과물.

위 규칙들의 결과물을 하나의 토큰 파일로 통합한다. 토큰은 3계층 구조를 따른다.

3계층으로 분리하는 이유는 변경 전파를 제어하기 위해서다. 브랜드 색상이 바뀌면 Primitive만 수정하면 Semantic과 Component가 자동으로 따라간다. 반대로 특정 컴포넌트만 예외 처리하고 싶으면 Component 레벨만 오버라이드하면 된다.

```
Primitive (원시값) → Semantic (의미값) → Component (컴포넌트값)
```

예시:
```
blue-600 → primary → button-bg
gray-100 → muted → card-bg
```

토큰 파일 위치: `{CSS 변수 파일 경로}` (보통 `index.css` 또는 `globals.css`)

CSS 변수 네이밍 규칙:
- 색상: `--{semantic}-{variant}` (예: `--primary-foreground`)
- 스페이싱: `--spacing-{scale}` (예: `--spacing-4`)
- 반경: `--radius-{size}` (예: `--radius-md`)
- 그림자: `--shadow-{size}` (예: `--shadow-sm`)

```css
--radius-sm: {값}rem;
--radius-md: {값}rem;
--radius-lg: {값}rem;
--radius-full: 9999px;

--shadow-sm: 0 1px 2px oklch(0 0 0 / 0.05);
--shadow-md: 0 4px 6px oklch(0 0 0 / 0.1);
```


### 6. 요구사항 → 컴포넌트 시스템

입력: 에센스의 "프로젝트 화면 목록", "레퍼런스 UI", "대상 디바이스", "기존 디자인 시스템 자료".

shadcn/ui 기반 컴포넌트 시스템을 구축한다. 세 단계로 진행한다.

1단계: shadcn/ui 초기화 설정

`npx shadcn@latest init` 실행 시 선택하는 항목들이다. 이 설정이 전체 컴포넌트의 기본 외형을 결정한다.

| 항목 | 설명 | 결정 기준 |
|------|------|-----------|
| Component Library | Base UI 또는 Radix | Base UI가 접근성 우수 |
| Style | Default/New York/Mira 등 | 레퍼런스 UI 톤에 맞춤 |
| Base Color | Zinc/Slate/Gray/Neutral 등 | 브랜드 색상과 조화 |
| Theme | 브랜드 Primary에 가까운 색 | 브랜드 색상에서 파생 |
| Icon Library | Lucide/Phosphor 등 | 규칙 7에서 결정 |
| Radius | Small/Medium/Large | 디자인 원칙(부드러운/각진) |

설정 결과는 `components.json`에 저장된다.

2단계: 컴포넌트 선정

프로젝트 화면 목록에서 필요한 UI 패턴을 추출하고, 대응하는 shadcn/ui 컴포넌트를 선정한다.

```
기본 입력: button, input, select, checkbox, radio, switch, textarea
레이아웃: card, separator, tabs, accordion
오버레이: dialog, popover, tooltip, dropdown-menu, sheet
피드백: toast, alert, skeleton, spinner
데이터: table, badge, avatar, pagination
네비게이션: breadcrumb, navigation-menu, sidebar
```

모든 컴포넌트를 한번에 설치하지 않는다. 화면별로 필요한 것만 설치한다. shadcn/ui는 복사 방식이라 나중에 추가해도 충돌이 없다.

3단계: 커스텀 명세

프로젝트 환경에 맞게 수정이 필요한 컴포넌트를 식별한다. 커스텀 대상이 되는 일반적인 경우:

- 크기 변형 추가 (공장 환경의 큰 터치 영역, 모바일의 작은 버튼)
- 색상/스타일 고정 (다크모드 미지원 시 라이트 고정)
- 아이콘 라이브러리 교체 (Lucide → Phosphor 등)
- 접근성 강화 (키보드 네비게이션, 스크린리더 지원)

커스텀 기록 형식:
```
{컴포넌트명}: {변형명} 추가/변경
→ 이유: {환경/사용자 특성}
→ 변경: {구체적 수치/동작}
```

예시:
```
Switch: lg 사이즈 추가
→ 이유: 공장 환경 터치 편의
→ 변경: 24×44px (기본 16×28px)
```

컴포넌트 변형(Variant) 규칙은 디자인 원칙에서 파생한다. 버튼을 예로 들면:
```tsx
// 변형은 시맨틱하게 정의한다
variant: "default" | "secondary" | "destructive" | "outline" | "ghost" | "link"
size: "sm" | "default" | "lg" | "icon"
```


### 7. 스타일 선호도 → 아이콘 시스템

입력: 에센스의 "아이콘 스타일 선호도"와 "레퍼런스 UI".

아이콘 라이브러리 비교:

| 라이브러리 | 스타일 | 아이콘 수 | 특징 |
|-----------|--------|----------|------|
| Lucide | 라인 | 1500+ | shadcn 기본, 가벼움 |
| Phosphor | 라인/솔리드/듀오톤 | 1200+ | 다양한 변형 |
| Heroicons | 라인/솔리드 | 300+ | Tailwind 공식 |
| Tabler | 라인 | 5000+ | 수량 최다 |

선택 기준은 스타일 → 수량 → 프레임워크 호환성 순이다. 스타일 선호도가 없으면 shadcn 기본인 Lucide를 선택한다. 여러 변형(라인+솔리드)이 필요하면 Phosphor가 유리하다.

사용 규칙:
```tsx
import { {아이콘명} } from "{라이브러리}"

// 크기는 3단계로 제한한다
<{아이콘명} size={16} />  // sm: 인라인, 라벨 옆
<{아이콘명} size={20} />  // md: 버튼, 메뉴 아이템
<{아이콘명} size={24} />  // lg: 빈 상태, 강조
```

3단계로 제한하는 이유는 시각적 일관성이다. 아이콘 크기가 4-5가지로 늘어나면 화면이 산만해진다.

아이콘에는 반드시 접근성 속성을 포함한다:
```tsx
// 장식용: aria-hidden
<{아이콘명} aria-hidden="true" />

// 의미 전달용: aria-label 또는 sr-only 텍스트
<button aria-label="{동작 설명}">
  <{아이콘명} />
</button>
```


### 8. 사용자 특성 → 접근성 기준

입력: 에센스의 "접근성 요구사항"과 "대상 디바이스".

WCAG 2.2 AA를 기본 목표로 한다. 특수 환경(고령자, 산업 현장)이면 AAA까지 고려한다. WCAG 2.2는 2023년 10월 발표된 현행 표준이다. 2.1 대비 9개 새 성공 기준이 추가되었고, 터치 접근성과 포커스 표시가 강화되었다.

색상 대비율:

| 요소 | AA 기준 | AAA 기준 |
|------|---------|----------|
| 일반 텍스트 | 4.5:1 | 7:1 |
| 큰 텍스트 (18px+) | 3:1 | 4.5:1 |
| UI 컴포넌트 | 3:1 | - |

검증 도구: https://webaim.org/resources/contrastchecker/

키보드 접근성:
- 모든 인터랙티브 요소는 Tab으로 접근 가능해야 한다
- 포커스 링은 항상 보여야 한다 (`outline: 2px solid var(--ring)`)
- 모달은 포커스 트랩을 적용한다 (shadcn/ui Dialog가 기본 지원)
- 포커스 표시 최소 크기: 2px (WCAG 2.2 신규 기준 2.4.13)

터치 접근성:
- 최소 터치 영역: 24×24px (WCAG 2.2 기준 2.5.8), 권장 44×44px
- 터치 타겟 간 간격: 8px 이상
- 드래그 동작에는 반드시 단일 포인터 대안 제공 (WCAG 2.2 신규 기준 2.5.7)

스크린 리더 지원:
- 시맨틱 HTML 우선 (`nav`, `main`, `aside`, `section`)
- aria 속성은 시맨틱 HTML로 불충분할 때만 사용
- 이미지에는 반드시 `alt` 속성 포함


## 출력 형식

### 디자인 가이드 템플릿

````markdown
# 디자인 가이드

{프로젝트명}의 디자인 결정사항이다.


## 디자인 원칙

{원칙1}: {정의}
{원칙2}: {정의}
{원칙3}: {정의}


## 브랜드 색상

| 이름 | HEX | oklch | 용도 |
|------|-----|-------|------|
| {이름} | #{HEX} | oklch({값}) | Primary |
| {이름} | #{HEX} | oklch({값}) | Secondary |
| {이름} | #{HEX} | oklch({값}) | Accent |

브랜드 자료: `{경로}`


## 시스템 색상

```css
--primary: oklch({값});
--primary-foreground: oklch({값});
--secondary: oklch({값});
--accent: oklch({값});
--destructive: oklch({값});
--muted: oklch({값});
--background: oklch({값});
--foreground: oklch({값});
--border: oklch({값});
--radius: {값}rem;
```


## 타이포그래피

## 레이아웃/스페이싱

4px 기반 배수 체계.

```css
--spacing-1: 0.25rem;   /* 4px  - 인라인 간격 */
--spacing-2: 0.5rem;    /* 8px  - 요소 내부 */
--spacing-4: 1rem;      /* 16px - 섹션 내부 */
--spacing-8: 2rem;      /* 32px - 섹션 간격 */
```

반응형 브레이크포인트:

| 이름 | 크기 | 대상 |
|------|------|------|
| sm | {n}px | {디바이스} |
| md | {n}px | {디바이스} |
| lg | {n}px | {디바이스} |
| xl | {n}px | {디바이스} |

```css
--container-max: {값}px;
--container-padding: var(--spacing-4);
```
````
