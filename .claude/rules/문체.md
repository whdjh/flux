# 문체

문서의 대상과 목적에 따라 문체를 선택한다.

문체는 두 축으로 나뉜다. 기본 문체는 본문에 쓰는 완결된 문장이고, 항목 형식은 리스트나 표에 쓰는 비완결 문장이다. 기본 문체는 하나만 선택하되, 리스트 항목에는 간결체를 자유롭게 쓸 수 있다.


## 기본 문체

본문, 설명, 논증에 쓴다. 문서 하나에 기본 문체 하나만 쓴다.

### 서술체

내부 문서의 기본 문체다. 설계 노트, 가이드, 기준 문서에 쓴다.

객관적이고 단정적인 느낌을 준다. 문장이 완결되어 있어서 공식 문서에 어울린다. 문서작성원칙.md가 이 문체로 쓰여 있다.

```
쓰기와 읽기가 로컬에서 즉시 일어난다. 서버에는 백그라운드로 동기화한다.
네트워크가 끊겨도 작업을 계속할 수 있다. 대신 충돌 해소 전략이 필요하다.
```

종결어미: ~한다, ~이다, ~않는다

### 대화체

1:1 설명이나 비개발자 대상 문서, 튜토리얼에 써. 말하듯 쓰니까 진입 장벽이 가장 낮아. 반말이라 격식이 필요한 상황에는 안 맞아. 격식이 필요하면 해요체를 써.

```
쓰기랑 읽기가 전부 로컬에서 바로 일어나. 서버에는 백그라운드로 동기화하는 구조야.
네트워크 끊겨도 작업할 수 있어. 대신 충돌 해소를 어떻게 할지 정해야 해.
```

종결어미: ~해, ~야, ~거든, ~돼

### 해요체

사용자 대면 문서에 써요. UX 라이팅 가이드, 사용자 안내, 온보딩 텍스트처럼 친근하면서도 격식이 필요한 곳에 맞아요.

대화체와 친근함은 같지만 존댓말이라 낯선 사용자에게도 편안해요. 토스의 UX 라이팅이 이 문체를 쓰고 있어요.

```
사용자는 쏟아지는 정보를 모두 읽지 않아요. 원하는 정보를 빠르게 스캔할 수 있도록
꼭 필요한 내용만 필요한만큼 전달하는 것을 중요하게 생각해요.
```

종결어미: ~해요, ~이에요, ~예요, ~돼요, ~있어요

### 합니다체

격식이 가장 높은 문체입니다. 보도자료, 기업 공지, 발표 자료, 약관처럼 공식적인 권위가 필요한 곳에 사용합니다.

해요체와 같은 존댓말이지만 거리감이 다릅니다. 해요체가 "옆에서 설명하는" 느낌이라면, 합니다체는 "단상에서 발표하는" 느낌입니다. 친근함보다 신뢰와 권위가 우선일 때 선택합니다.

```
본 서비스는 개인정보를 암호화하여 저장합니다. 사용자의 동의 없이
제3자에게 제공하지 않습니다. 자세한 내용은 개인정보처리방침을 참조하십시오.
```

종결어미: ~합니다, ~입니다, ~습니다, ~됩니다, ~않습니다, ~하십시오, ~주십시오


## 항목 형식

### 간결체

리스트, 표, 레이블에 씀. 어떤 기본 문체와든 자연스럽게 공존함.

문장을 끝맺지 않고 명사형으로 끊음. 정보 밀도 높고 읽는 속도 빠름. 슬랙이나 회의록처럼 빠른 공유에도 단독으로 쓸 수 있음. 단, 인과나 논증이 필요한 본문에는 맞지 않음.

```
모든 쓰기/읽기 로컬 처리. 서버에는 백그라운드 동기화.
오프라인 작업 가능. 충돌 해소 전략 필요.
```

종결어미: ~함, ~됨, ~없음, ~가능


## 혼용 예시

서술체 본문 + 간결체 리스트. 본문에서 흐름을 잡고, 리스트에서 밀도를 높인다.

```
네이티브(Swift)는 Rust FFI로 직접 바인딩해서 브릿지 오버헤드가 없다. 반면 RN은
키 입력마다 JS → Native → Rust → Native → JS를 왕복한다. 일반 앱에서는 괜찮지만,
실시간 리치텍스트 편집에서는 체감된다.

iOS 전용 기능:
- Share Extension: 다른 앱에서 "공유"로 즉시 수집. RN으로 못 만듦.
- Widgets: 홈 화면 위젯. WidgetKit은 SwiftUI 전용.
- Siri Shortcuts: 음성으로 수집. 네이티브 전용.
```
